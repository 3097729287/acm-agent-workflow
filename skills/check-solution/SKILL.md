# 题解质检（17 项格式闸）

拿本仓库的 `tools/check_solution.py` 当闸门，对题解 md 做交付前检查。**这个 skill 只跑检查、报告问题，
不改写文件**——改不改、怎么改由用户拍板；用户说要修再动手，动手前先备份。

## 前置（缺哪个都还能跑，只是对应项打「不适用」并说明原因）

| 组件 | 必需性 | 影响 |
|---|---|---|
| Python 3.8+ | **必需** | 全部脚本；只用标准库，不用 pip 装东西 |
| g++（C++17） | 可选 | 第 5 项「代码块真编译」 |
| Node + katex | 可选 | 第 17 项「KaTeX 全量渲染」；装法 `cd tools && npm install katex` |

## 怎么跑

一条命令（`<本skill目录>` = 本 skill 的目录，加载时会给出它的绝对路径；没看到路径就自己找一下：
`ls ~/.claude/skills/check-solution/gate.py`，或它在仓库里的位置是 `<仓库根>/skills/check-solution/`）：

```bash
python "<本skill目录>/gate.py" <题解.md> [更多.md ...]
```

`gate.py` 只干一件事：找到仓库根，再把参数**原样**交给 `tools/check_solution.py`，退出码也原样传出来。
仓库根的查找顺序 = `--repo <路径>` → 环境变量 `ACM_AGENT_WORKFLOW_ROOT` → 当前目录逐级向上 →
待查 md 所在目录逐级向上 → 本 skill 目录逐级向上；一个都找不到就打印三种解法并以退出码 2 退出。

常用开关（原样转给 check_solution.py）：

- `--no-compile`：跳过第 5 项。先快速看格式时用（一趟从数秒降到约 0.1 秒），**交付前必须补一次全量**。
- `--no-record`：跳过第 6 / 9 / 10 / 11 项（整场题解专有口径）——单题、专题、非整场文档才用，见下。
- `--quiet`：只打印有问题的项。`--list`：只打印 17 项清单。

## 看结果

- 末行「结论：全部通过」+ **退出码 0** = 过闸。
- 末行「★有问题，改完再交付★」+ **退出码 1** = 没过；每条问题都带**行号 + 原句**，照着改。
- `[不适用]` **不等于通过**：要么是工具没装（g++ / Node+katex），要么是开关跳过了（`--no-record` /
  `--no-compile`）。报结论时要把这几项单独说清楚，别混进「全过」。

## 报红了怎么修

**第一步永远是先分辨这份东西是不是「整场题解」**（判据：有目录表、多道题、文末实测记录节）。

- 是 → 全量 17 项都算数，按下面逐条改。
- 不是（单题题解 / 专题长文 / 规划调研文档）→ 第 **9 / 10 / 11** 项报红是口径不匹配，**不是文档的错**：
  改用 `--no-record` 重跑，把这几项当不适用。**不要为了让闸门变绿去硬加目录表或改节名。**

按项对应的修法（规范以仓库 `knowledge/` 为准，这里只给落点）：

| 报红项 | 怎么修 |
|---|---|
| 1 / 1b / 2 / 3 / 16 / 17（LaTeX 类） | 先跑 `python tools/unify_latex.py <md> apply` 自动转；公式被灰底包着的先跑 `python tools/unpair_ticks.py <md> apply`。规范：`knowledge/05-数学LaTeX.md` |
| 5（代码块编译） | 以编译器报的那一行报错为准改代码（改的是 **md 里贴着的那份**）。验证口径：`knowledge/04-验证协议.md` |
| 6 / 6b（实测记录） | ≤6 行纯文字、不用表格和 `- ` 列表、不许「约 / 大概 / 左右」这类模糊数；没跑的档要如实写「未验证」 |
| 7 / 7b / 8（编码 / 行尾 / 表格竖线） | 按报的行号直接改：UTF-8 无 BOM、行尾统一 LF、同一张表内 `|` 数一致 |
| 9 / 10 / 11（节白名单 / 目录表 / 小节顺序） | `knowledge/03-题解写法.md` 是这三项的唯一定义处（题内只许 题意 / 从零讲 / 手算 / 思路 / 参考代码 / 复杂度 / 易错点，四项必写） |
| 4 / 4b（`<sub>` 二次转义 / 繁体字） | 直接改：`&lt;sub&gt;` 还原成 `<sub>`；繁体字换简体 |

## 别做的事

- **别为了让闸门变绿而删内容或绕过检查** —— 闸门红了先判断是真问题还是口径不匹配，改不动的项如实报给用户。
- 别拿它查**算法归档 md / 索引 / 状态表**：它只为「交付题解 md」设计，那些文件会有两类固定误报
  （文末实测记录、历史老习惯），见 `knowledge/10-工具链.md` 的 `check_solution.py` 一节。
- 它只管**格式**；代码对不对归 `tools/verify.py`（四档验证）和 `tools/md_full.py`（抽 md 里的代码复跑）。

## 整包质检（可选，用户给的是题解包时）

包 = 含 `manifest.json` 的目录或 zip（结构见 `knowledge/10-工具链.md`）。改用导入器的 dry 模式，
它会顺带对包内每份题解 md 跑同一套 17 项闸门，另外查字段、文件名、知识点词典、覆盖冲突：

```bash
python tools/import_solution.py <包>          # dry：只校验 + 出报告，不动盘
```

## 报告给用户时的格式

结论一行（过 / 没过 + 退出码）→ 没过就按「项号 + 行号 + 一句话修法」列问题 → 下一步要用户做什么
（改哪几处、要不要我改、要不要补装 g++ / katex 把「不适用」变成真跑）。
