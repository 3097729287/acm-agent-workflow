# 题解算法归档（每场题解 → 算法目录）

> 类型：工作要求 + 方法 ｜ 归档规则全文 + 精简索引（全库台账）；全量索引在 `<数据根>\索引\题解算法索引.md`。

## 一、归档做什么

每写完一场题解（触发见《工作流》），**额外做三件事**：

1. 逐题判定用了什么数据结构 / 算法，**跳过签到题**；
2. 每道非签到题，在**主算法文件夹**里写一份题目记录 md（模板见第三节）；
3. 同步两处索引：**跑 `tools/index_sync.py` 自动生成**（全量索引场次小节 + 本文件第五节的表都由记录 md 头部机械生成）——手工只写记录 md 与反查表。

**时机**：题解定稿、没人再要求改之后**直接归档，不用先问**。
题解还在改就归档，回头索引会和正文对不上。

**「知识点」列的标准名从哪来**：一律取算法库**文件夹名**（顶层文件夹名 + `DP\` 的四个子文件夹名），
只有四个非文件夹标准名可用（二分答案 / DFS 序 / Hall 定理 / 连通块计数）。
题解里爱怎么写怎么写，**只有状态表这一列要归一**（`tools/fill_knowledge.py` 是这一列的唯一写入口）。
**归到哪个算法文件夹自己定**：判完直接放 / 建，说一声就行，不用反问。

**同一趟顺手更新《概念台账》**：这场新从零讲过的算法 / 数据结构补进台账，
「高频但还没从零讲过」那节里如果本场补讲了，就从那里删掉。两件事一起做——归档时算法名本来就在手边。

**收工自检（机制，别靠人记）**：`python tools/archive_check.py RoundNNN` ——
机器对账四处：算法库记录 md 在不在、全量索引有没有本场、
本文件精简索引与「算法 → 文件夹」对照表有没有本场、《概念台账》有没有本场；外加行尾 / 编码检查。
再逐行对账**索引「归档位置」列 ↔ 记录实际所在文件夹 ↔ 记录头部 `**归档文件夹**` 字段**、
**反查表覆盖本场每题**、**题解指针**（格式 + 死指针 + 反查表「（指针）」标记回验）。
**退出码 0 = 归档完成**（记录文件名与题名只差空格 / 括号全半角只算「提醒」）。
**两处表不用手工写**：`python tools/index_sync.py dry` 看 diff → `apply`（自动备份、幂等）——
记录 md 是表的单一事实来源；反查表仍手工（`archive_check` 兜底对账）。

## 二、口径

| 项目 | 约定 |
|---|---|
| 归档根目录 | **`<数据根>\算法\`**；下面所有相对路径都以这个根为准 |
| 新算法文件夹 | **顶层直接建算法名**（`树状数组\`、`字典树\`…）。**扁平优先，平级算法之间不许互相嵌套**（反例：BFS 和二分查找是兄弟、不是父子，`BFS\二分查找\Bound\` 这种是错的）。**只有真从属关系才嵌套**：`DP\区间DP\`、`DP\树形DP\`、`DP\状压DP\` 等（都是 DP 的子类）、`素数\欧拉筛\`（筛法是求素数的一种方法） |
| 具体知识点 | **不建子文件夹**，写进 md 的「具体知识点」一节（如「树状数组：区间加 + 单点查」） |
| 记录文件名 | `<比赛名>-<题号>-<题名>.md`，如 `牛客周赛Round159-F-小月的路径码.md`；**题名段 = 记录 md 标题行的题名**（全角括号、题名里的空格照抄） |
| 一题多算法 | **主算法文件夹详写**；其余用到的算法文件夹里放**一行指针**。指针文件统一叫 `题解指针.md`，**一题一行**：`- <题号> <题名>：` + 反引号里的主算法文件夹名（例 `- F 小月的路径码：`树状数组\``）。**不写标题、不写说明段、不写完整文件名**——作用 = 「按次要算法反查到原题」，**不是再写一遍题解**，所以只留一行；一个文件夹里所有次要算法的指针**合并进同一个文件**，不许一题一个文件 |
| 代码 | **不放 cpp**，只放 md；代码留在题解库里每题自己的子目录（`题解\RoundNNN\<区间>\<字母>\`） |
| 详细度 | **精简**：题意 3~5 行 + 数据范围 + 用到的算法点 + 原题链接，不照抄整份题面 |
| 要不要再加工 | **不额外操作**：算法库里这份就是「**具体题解**」，不压缩、不合并、不改结构。一场比赛的交付 = 题解区**一份完整题解** + 算法库里的**逐题记录（题目指针）**，两者都别二次加工 |
| 索引位置 | 全量 = `<数据根>\索引\题解算法索引.md`——放在 `<数据根>\` 下**与 `算法\`、`题解\` 平级**（索引不属于算法库，跟着算法库的清理规则走会被误删）；模板同目录 `题目记录模板.md`。精简版 = 本文件第五节 |
| 记录头部「归档文件夹」 | 推荐写**相对 `算法\` 的文件夹名**（如 `` `字典树\` ``，可移植）；`tools/archive_check.py` 也认 `<数据根>\算法\字典树\` 占位写法与当前数据根的绝对路径（旧绝对路径换过数据根只提醒、不报错） |
| 编码 / 行尾 | UTF-8 **无 BOM** + **纯 LF**（该目录 md 是 LF；cpp 是 CRLF，别跟着 cpp 走） |
| md 格式 | 数学写 LaTeX（`$...$`，见《数学 LaTeX》），反引号只给真代码 |
| 索引表里的链接 | 全量索引的「原题」列**一律写 Markdown 链接**：`[原题](https://ac.nowcoder.com/acm/contest/<场次ID>/<题号>)`。**别把裸 URL 摊在单元格里**——URL 是不可断的长串，整表被它撑超宽后，最后一列只剩两三个字的宽，渲染出来是「一个字一行」的竖条 |

## 三、文件与模板

| 文件 | 作用 |
|---|---|
| `<数据根>\索引\题解算法索引.md` | 全量索引：**一场一节** + 每场一张 5 列小表 `题号 / 题名 / 难度 / 算法 / 归档位置`；后面是反查表（算法 → 题目）+ 说明 + 不带题目的资料 |
| `<数据根>\索引\题目记录模板.md` | 每题 md 的模板（复制正文改内容），含「一行指针」写法 |
| 本文件第五节 | 精简索引，跟全量索引条数必须一致 |

记录固定五节：**题意（精简）→ 关键点（为什么用这个算法）→ 复杂度 → 踩过的坑 → 相关**。
（「数据范围」是「题意」节里的一行**加粗小字**，不单独成节。）
「踩过的坑」别省——那是这份记录里最值钱的一栏（对齐《算法坑集》的写法）。

## 四、归档检查清单（做完逐条对）

1. **签到题没有**被归档；
2. 每个非签到题在**本场那一节**的小表里有一行，5 列齐全：题号 / 题名（写成 Markdown 链接，**不摊裸 URL**）/ 难度（CF 数字）/ 算法与数据结构 / 归档文件夹（相对 `<数据根>\算法\`，末尾带 `\`）；
3. md **真的在**那个文件夹里（**列目录或 grep 确认过**，不是「我以为写了」）；
4. 多算法题在次要算法文件夹的 `题解指针.md` 里留了**一行**（格式见第二节口径表）；
5. 新建文件夹用的是**通用算法名**，不是题目名；**没有把两个平级算法互相嵌套**；
6. 反查表同步更新（**本场每个用到的算法名都要在反查表里出现**，不是只改总数）；
7. 全量索引与精简索引**条数一致**，且**两处都写了本场小节**（只写记录 md、不更新索引 = 没归档完）；
8. **本场新从零讲过的概念已补进《概念台账》**（写明「概念 / 首次出现 / 讲在哪一节」三样）；
9. **跑过 `archive_check.py RoundNNN` 且退出码 0**（见第一节「收工自检」）。
