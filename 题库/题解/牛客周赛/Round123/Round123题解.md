## A. 小红玩牌

### 题意

两张牌，每张有「点数 $n$」和「花色 $c$」：

- 点数大的牌大；
- 点数相同，按花色 **A > B > C > D** 从大到小排。

问第一张牌是不是比第二张大：是输出 Yes，否则输出 No。

### 手算

| 输入 | 比较过程 | 输出 |
|---|---|---|
| 1 A / 1 B | 点数相同（都是 1）→ 比花色，A 比 B 大 | Yes |
| 1 A / 2 D | 点数 1 < 2，花色再大也没用 | No |

### 思路

判断分两级，先看点数和花色谁更优先：

1. **点数不同** → 点数大的牌大，花色完全不参与比较；
2. **点数相同** → 比花色，题面规定 A > B > C > D。

第二级有个反转：字符 'A'、'B'、'C'、'D' 本身是按 A 到 D 从小到大排的，
**字典序小的花色反而更大**，所以点数相同时要写 c1 < c2，写反了就全错。
其余部分照题意直译即可。

### 参考代码

```cpp
// 牛客周赛 Round 123 A. 小红玩牌
// 题意：比两张牌的大小。先比点数，点数大的牌大；点数相同比花色，A > B > C > D。
// 输出 Yes 表示第一张比第二张大，否则 No。
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n1, n2;          // 两张牌的点数
    char c1, c2;         // 两张牌的花色
    cin >> n1 >> c1;     // 第一张牌
    cin >> n2 >> c2;     // 第二张牌

    bool firstBigger;
    if (n1 != n2) {
        firstBigger = (n1 > n2);   // 点数不同：直接比点数
    } else {
        // 点数相同：花色 A>B>C>D。字符的 ASCII 恰好是 'A'<'B'<'C'<'D'，
        // 而我们需要的是"A 最大"，所以**字符更小的反而更大**，用 < 比较。
        firstBigger = (c1 < c2);
    }

    cout << (firstBigger ? "Yes" : "No") << "\n";
    return 0;
}
```

### 易错点

1. **花色比反了**（本题唯一的坑）。字符 'A'、'B'、'C'、'D' 的 ASCII 是 65、66、67、68，也就是 **'A' 最小**；
   可题目要的是 **A 最大**。所以点数相同时，要写 c1 < c2 才算"第一张大"。心里默念一遍：字符小的花色反而大。
2. `cin >> n1 >> c1;` 读 1 A 这种一行两个数据没有问题：整数读完后，空格会被自动跳过，接着读字符。
3. 输出是 Yes / No，注意大小写，别写成 `YES` / `NO`。

## B. 小红作弊

### 题意

一副 52 张牌，牌面是 1 ~ 13。要求：**两人合起来，每个数字的牌恰好 4 张**。

- 输入两行各 13 个整数：小红、小紫手上各数字的张数；
- 小紫的牌一定合法（同一个数字不超过 4 张）；
- 小红每次可以把**自己的**一张牌改成任意数字，问最少改几次。

### 手算

样例 2：小红是 2 0 0 … 0，小紫是 3 4 4 … 4 3。

| 数字 | 小紫有 | 小红最终必须有 | 小红现在有 | 多出来 |
|---|---|---|---|---|
| 1 | 3 | $4 - 3 = 1$ | 2 | 1 张 |
| 13 | 3 | $4 - 3 = 1$ | 0 | 0 张 |

多出来 1 张 → 改成缺的那个数字就完了 → 答案 1。

### 思路

小紫的牌**不会变**，所以小红最后的手牌是**唯一确定的**：第 $i$ 种数字必须持有

$need[i] = 4 - y[i]$        （$y[i]$ = 小紫手上数字 $i$ 的张数）

小红现在有 $x[i]$ 张：

- $x[i] > need[i]$：多出来的 `x[i] - need[i]` 张必须改掉，**一张算一次**；
- $x[i] < need[i]$：不用管，缺的牌正好由别处多出来的补上（两人总张数固定是 52，
  多出来的总数 = 缺的总数）。

所以答案就是 **$\sum \max(0, x[i] - need[i])$**，一行循环搞定。

### 参考代码

```cpp
// 牛客周赛 Round 123 B. 小红作弊
// 题意：两人共 52 张牌，牌面 1~13。要求「每个数字的牌恰好 4 张」（两人合计）。
//       小紫的牌合法（同一个数字不超过 4 张），小红可以改自己手上任意一张牌的数字，
//       问最少改几次。
//
// 关键：小紫不动，所以小红最终手牌是**唯一确定的**：
//       第 i 种数字最终必须持有 need[i] = 4 - y[i] 张。
//       小红现在有 x[i] 张，多了的（x[i] > need[i]）必须改掉；
//       少了的自然由别处多出来的补上（总数一定对得上：两边总和都是 52）。
//       所以答案 = Σ max(0, x[i] - need[i])。
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int x[14], y[14];                       // 下标 1~13 对应牌面 1~13
    for (int i = 1; i <= 13; i++) cin >> x[i];   // 小红手上的张数
    for (int i = 1; i <= 13; i++) cin >> y[i];   // 小紫手上的张数

    long long ans = 0;
    for (int i = 1; i <= 13; i++) {
        int need = 4 - y[i];                // 小红最终必须持有几张 i
        if (x[i] > need) ans += x[i] - need; // 多出来的每一张都得改一次
    }

    cout << ans << "\n";
    return 0;
}
```

### 易错点

1. **别把"缺的"也加一遍**。缺多少就有人多多少，两边数字一样，加两次等于答案翻倍。
2. `need[i]` 可能比 `x[i]` 大，一定要 `if (x[i] > need[i])` 或套 $\max(0, \ldots)$，否则会减出负数。
3. 两行各 13 个整数，一共 26 个，别只读一行。
4. 小紫合法只是保证 $need[i] = 4 - y[i] \ge 0$，不需要额外判断。

## C. 小红出对

### 题意

- $n$ 张牌，每张有**牌面数字** $a_i$ 和**花色** $c_i$（A/B/C/D）；
- 一个「对」= 两张**数字相同**的牌，每次打出一个对；
- 限制：**所有打出的牌里，不能有两张"花色 + 数字"都相同的牌**；
- 求最多能打出多少张，并输出一种方案（每行两个下标，表示这一对打的是第几张牌）。

注意第三条限制的真正含义：**对于同一个数字，打出的牌花色必须两两不同**。
同一个数字、同一个花色的两张牌，最多只能出一张。

### 从零讲：构造题的「上界 + 达到上界」

#### 构造题和别的题哪里不一样

普通题只要求你输出一个**数**（最多多少次、多少种）。构造题还要你把**方案**写出来，
评测机拿你的方案去**逐条检查**：每对牌数字是否相同、有没有重复使用同一张牌、
有没有出现两张"花色 + 数字"一样的牌。所以构造题永远分两步走：

1. **先算上界**：这个数最大可能是多少（用一段谁都能看懂的推理）；
2. **再把上界做出来**：给一个能达到这个数的具体方案。

只要这两步都成立，答案就是对的——上界保证了"不可能更多"，方案保证了"确实能做到"。

#### 上界怎么来

设某个数字 $v$ 一共有 **$d$ 种不同的花色**（注意：是种类，不是张数）。这个数字能出几张？

- 打出的张数必须是**偶数**（两张一对，不能剩半对）；
- 打出的牌花色必须**两两不同**，所以最多只能出 $d$ 张。

两条合起来：最多出 **$2 \times \lfloor d/2 \rfloor$** 张（$d$ 是偶数就是 $d$ 张，$d$ 是奇数就浪费一种花色，出 $d-1$ 张）。

各数字之间**互不干扰**（限制说的是"花色 + 数字"这个组合，不同数字之间撞不上），
所以总上界就是把每个数字的上界加起来：

上界 = $\sum_v 2 \times \lfloor d_v / 2 \rfloor$

#### 怎么把这个上界做出来

对每个数字 $v$ 单独处理：

1. 按**输入顺序**扫一遍该数字的所有牌，每种花色只取**第一次出现**的那一张，
   记下它的下标 —— 这样得到一串花色互不相同的牌，长度正好是 $d$；
2. 丢掉最后多出来的那张（如果 $d$ 是奇数），剩下 $m = 2 \lfloor d/2 \rfloor$ 张；
3. 顺次两两配对：第 1 张配第 2 张、第 3 张配第 4 张……

为什么这样配出来的每一对都合法？

- 一对里的两张牌**数字相同**（同一个数字的牌）→ 满足「对」的定义；
- 一对里的两张牌**花色不同**（第 1 步保证了花色两两不同）→ 不会出现两张"花色 + 数字"都一样的牌；
- 不同数字的牌之间不可能"花色 + 数字"相同（数字就不一样）。

于是每个数字都恰好打出了 $2 \lfloor d/2 \rfloor$ 张，加起来正好等于上界 —— 上界可以达到，
所以它就是最大值。

#### 为什么不用"随便配对"这种做法

有人会想：把所有牌按数字分好组，每组随便两两配对不就行了？问题出在**花色**上：
样例 2 里数字 1 有两张**都是 A 花色**，随便配就是一对 1A + 1A，
打出的牌里出现了两张"花色 + 数字"完全一样的牌 —— 违反限制。
所以配对之前必须先去重花色，"每组里每种花色只留一张"这一步不能省。

#### 两个常见疑问

**Q1：为什么统计的是"花色种数 $d$"而不是"牌的张数"？**
因为限制卡的是"花色 + 数字"这个组合。同一个数字、同一个花色有 10 张，也只能出 1 张。
看样例 3：三张 1，花色是 A、B、A，牌有 3 张但只有 3 种花色，最多出 2 张。

**Q2：每个数字各自取到自己的上界，加起来就一定能同时取到吗？**
能。因为一个数字出的牌只和这个数字自己的牌有关，方案之间不抢牌（每个数字用的是不同下标的牌），
所以把它们并起来就是一个全局合法方案。

### 手算

样例 1：1A 1B 3A 2A 3B（下标 1 ~ 5）。把牌摆成"花色 $\times$ 数字"的表：

| 花色 | 数字 1 | 数字 2 | 数字 3 |
|---|---|---|---|
| A | 1 | 4 | 3 |
| B | 2 | — | 5 |
| C | — | — | — |
| D | — | — | — |

- 数字 1：有 A、B 两种花色 → 能出一对（第 1、2 张）；
- 数字 2：只有 A 一种花色 → 两张同花色不能出，**一张都出不了**；
- 数字 3：有 A、B 两种花色 → 能出一对（第 3、5 张）。

合计 4 张。

样例 2：1A 1A 2B 2B：数字 1 只有 A 花色、数字 2 只有 B 花色 → 0 张。

样例 3：1A 1B 1A 1C：数字 1 有 A、B、C **三种**花色 → 最多出 2 张（花色不能重复，
三张里只能挑两张）→ 答案 2，方案 1 2。

### 思路

把牌按**数字**分组。题面第三条限制翻译过来就是：同一个数字打出去的牌，花色必须两两不同。

于是每组各算各的：

- 数字 $v$ 一共有 $d_v$ 种不同花色 → 它最多打 $2 \times \lfloor d_v/2 \rfloor$ 张
  （出的是「对」，张数必须为偶数；花色不能重复，所以取不超过 $d_v$ 的最大偶数）；
- 不同数字之间互不影响 → 答案 = $\sum_v 2 \times \lfloor d_v/2 \rfloor$。

方案同理：每组按「该花色第一次出现的下标」取牌，取够偶数张后顺次两两配对，配对自然合法。

### 参考代码

```cpp
// 牛客周赛 Round 123 C. 小红出对
// 题意：n 张牌，每张有「牌面数字 a_i」和「花色 c_i」。每次打出一个「对」＝两张数字相同的牌。
//       限制：所有打出的牌里，不能有两张「花色 + 数字」都相同的牌。
//       求最多能打出多少张，并给出一种方案。
//
// 关键：把牌按**数字**分组，一组的牌里，打出去的那些必须**花色两两不同**
//       （否则就出现两张花色数字都相同的牌）。
//       设某个数字一共有 d 种不同的花色，那这个数字最多打 2*floor(d/2) 张
//       （打出的张数必须是偶数，而且每种花色最多一次）。
//       各组互不影响，所以答案 = Σ 2*floor(d_v/2)。
//
//       构造：每组按「输入顺序里第一次出现某花色」取牌，凑成偶数张后
//       顺次两两配对——同一组的牌花色互不相同，配对自然合法。
#include <bits/stdc++.h>
using namespace std;

const int MAXA = 200005;                 // a_i ≤ 2*10^5

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    // ids[v]：牌面数字为 v 的牌的下标，按输入顺序存
    vector<vector<int>> ids(MAXA);
    vector<int> suit(n + 1);             // suit[i]：第 i 张牌的花色（0~3 表示 A~D）
    for (int i = 1; i <= n; i++) {
        int a;
        char c;
        cin >> a >> c;
        suit[i] = c - 'A';
        ids[a].push_back(i);
    }

    vector<pair<int, int>> pairs;        // 打出的每一对
    vector<char> used(4, 0);             // 本次分组里，哪些花色已经拿过牌
    vector<int> pick;                    // 本次分组里挑出来的牌（花色互不相同）

    for (int v = 1; v < MAXA; v++) {
        if (ids[v].empty()) continue;

        pick.clear();
        fill(used.begin(), used.end(), 0);   // 每个数字单独统计花色
        for (int id : ids[v]) {
            if (!used[suit[id]]) {           // 这种花色还没拿过 → 可以拿
                used[suit[id]] = 1;
                pick.push_back(id);
            }
        }
        int m = (int)pick.size() / 2 * 2;    // 只能取偶数张
        for (int k = 0; k + 1 < m; k += 2)
            pairs.push_back({pick[k], pick[k + 1]});
    }

    cout << pairs.size() * 2 << "\n";
    for (auto &p : pairs) cout << p.first << " " << p.second << "\n";
    return 0;
}
```

### 复杂度

第 1 步按数字分组是 $O(n)$（值域 $2 \times 10^5$，用 vector 数组存下标），
第 2 步每个数字最多看过 4 种花色，输出方案 $O(n)$。总时间 O(n + 值域)，空间 O(n + 值域)。

### 易错点

1. **输出的下标是"输入顺序"（第几张牌，从 1 开始），不是牌面数字**。样例 1 输出 3 5
   指的是第 3 张（3A）和第 5 张（3B），不是数字 3 和 5。
2. 第一行输出的是**张数 $k$**，不是对数；$k$ 一定是偶数，后面跟 $k/2$ 行。
3. 本题是 **Special Judge**（题面明说"如果存在多个解决方案，您可以输出任意一个"），
   所以牛客的"自测运行"可能给你报错，那不代表你的方案错了，要自己核对。
4. 每换一个数字，统计花色的那个标记数组要**重新清空**，别把上一个数字的花色带过来。
5. 别把"花色"当成主键去分组：一个对要求的是**数字**相同。

## D. 小红打牌

### 题意

一个「飞机」= 10 张牌，重排后能写成

$$\{a, a, a, a+1, a+1, a+1, b, b, c, c\}$$

的形状：两个**连续**的三张，外加两个**对子**。对子的点数 $b$、$c$ 随便取：

- 可以相等（$b = c$）；
- 可以和三张的点数重合（$b$ 或 $c$ 等于 $a$、$a+1$ 都行）。

题面自己的例子：{1,1,1,2,2,2,3,3,4,4} 是飞机；{1,1,1,3,3,3,2,2,4,4} 不是（两个三张 1 和 3 不连续）。

两个飞机相同，**当且仅当十张牌的"可重集合"完全一样**——也就是"每个点数各几张"完全相同，
和这十张牌原本是第几张无关、和顺序无关。求能选出多少种不同的飞机，答案对 998244353 取模。

### 从零讲：可重集合怎么数才不重不漏（代表元）

#### 什么是「可重集合」

普通集合里每个元素只能出现一次，{1,2,3}。**可重集合**（multiset）允许元素重复，
重要的是"每个元素出现几次"，而不是顺序：

{1,1,1,2} 和 {2,1,1,1} 是同一个可重集合

题面说"两个飞机数组组成的可重集合不完全相同才算不同"，意思就是：
只看"每种点数各几张"，顺序和来源都不算。

#### 为什么要给飞机办一张"身份证"

如果直接去数"十张牌的所有选法"，同一架飞机会被数很多遍：比如手上七个 1、三个 2，
随便挑三个 1、三个 2、再挑四个 1 当对子——挑法有很多种，可它们说的是**同一架飞机**。
所以必须给每架飞机找一个**唯一的写法**（代表元），然后"数写法"就等于"数飞机"。

这题的代表元很自然：**用三元组 $(a, b, c)$ 表示这架飞机**，其中 $a$ 是三张的起点、
$b \le c$ 是两个对子的点数（规定 $b \le c$，是为了让"$b$ 和 $c$ 交换"不算新的飞机）。

于是就变成两件事：

1. 三元组 → 飞机：一个三元组最多对应一架飞机（可能凑不出牌，那就不是飞机）；
2. 飞机 → 三元组：**每架飞机只能对应一个三元组**（不唯一的话就会重复计数）。

第 2 条是关键，下面单独说。

#### 为什么每架飞机只有一个三元组

反证：假设同一个可重集合既能写成 $(a, b, c)$，又能写成 $(a', b', c')$，且 $a' \ne a$。

| 情况 | 集合里至少要有 | 一共要几张 | 结论 |
|---|---|---|---|
| $a' \ge a+2$（两组三张隔开） | $a$、$a+1$、$a'$、$a'+1$ 各 3 张 | $\ge 3 \times 4 = 12$ 张 | 超过 10 张，不可能 |
| $a' = a+1$（两组三张挨着） | $a+1$ 要出 6 张，再加 $a$、$a+2$ 各 3 张 | $\ge 6+3+3 = 12$ 张 | 超过 10 张，不可能 |

两条路都堵死了，所以 **$a$ 是唯一的**。$a$ 定了以后，从可重集合里扣掉 $a$ 的三张和 $a+1$ 的三张，
剩下的四张就是两个对子，$b$、$c$ 也随之唯一。

结论：三元组和飞机**一一对应**，数三元组就是数飞机，既不会漏也不会重。

#### 定下代表元后，怎么数得快

对固定的 $a$，先扣掉两个三张，剩下的"容量"记作 cap：

- $cap[x] = cnt[x] - 3$（$x$ 是 $a$ 或 $a+1$，它们各被三张用掉 3 张）
- $cap[x] = cnt[x]$（其它点数）

两个对子要么是两个不同点数（$b < c$），要么是同一个点数两次（$b = c$）：

| 情况 | 条件 | 有几对可选 |
|---|---|---|
| $b < c$ | $cap[b] \ge 2$ 且 $cap[c] \ge 2$ | 从集合 $T = \{x : cap[x] \ge 2\}$ 里任挑两个 → C(个数, 2) |
| $b = c$ | $cap[b] \ge 4$（同一个点数要凑两对） | 集合 $T4 = \{x : cap[x] \ge 4\}$ 的大小 |

所以对每个合法的 $a$（要 $cnt[a] \ge 3$ 且 $cnt[a+1] \ge 3$），贡献就是

$$C(|T|, 2) + |T4|$$

答案 = 所有合法 $a$ 的贡献之和。|T| 和 |T4| 不必每个 $a$ 重扫一遍：
先全场统计 g2 = "够 2 张的点数种数"、g4 = "够 4 张的点数种数"，
再把 $a$、$a+1$ 这两个特殊位置做加减即可（代码里就三行）。

拿样例 2 走一遍：g2 = 5（1、2、3、4、5 都够 2 张），g4 = 0。
唯一的合法 $a = 1$，扣掉 1、2 各三张后 $cap[3] = cap[4] = cap[5] = 2$，其它是 0，
所以 T = {3,4,5}、T4 是空的 $\to C(3, 2) + 0 = 3$，和手算一致。

#### 两个常见疑问

**Q1：答案为什么要取模？数会大到溢出吗？**
单个 C(|T|,2) 最多到 $2 \times 10^{10}$ 量级（|T| 最多 $2 \times 10^5$），乘上合法 $a$ 的个数后整体能到 $10^{14}$ 量级，
`long long` 装得下，但题面要求取模，所以按模加就行。

**Q2：为什么不用枚举 $b$、$c$ 两个点数（$O$(值域²)）？**
值域是 $2 \times 10^5$，两两枚举要 $4 \times 10^{10}$ 次，超时。用 C(|T|,2) 把"挑两个点数"一次性算出来，
每个 $a$ 只要 $O(1)$，整体就是 $O$(值域)。

### 手算

样例 1：1 1 1 2 2 2 1 1 1 1（七个 1、三个 2）。凑一个飞机试试：

- 三张的部分只能是 1 和 2（点数 1 有 7 张、点数 2 有 3 张，都够 3 张）；
- 扣掉 1,1,1 和 2,2,2 之后，还剩四个 1 → 正好当两个对子（$b = c = 1$）。

所以只有这一种，答案 1。**注意 $b = c$ 是允许的**，这是最容易漏的情况。

样例 2：1 1 1 / 2 2 2 / 3 3 / 4 4 / 5 5。三张的部分只能是 1 和 2（点数 3 只有 2 张），
剩下两个对子从 {3,4,5} 里挑两个不同的点数 → 3 种：

| 飞机 | 对子 $b$ | 对子 $c$ |
|---|---|---|
| 1 | 3 | 4 |
| 2 | 3 | 5 |
| 3 | 4 | 5 |

### 思路

分三步把「数飞机」变成「数三元组」：

1. **三元组唯一**：一个飞机由 $(a, b, c)$ 完全确定，而且写不出第二种——若还能写成 $a' \ne a$，
   要么多出 4 个点数各 $\ge 3$ 张（> 10 张），要么某个点数要 $\ge 6$ 张，都不可能在 10 张内。
   所以枚举合法三元组计数，不重不漏。
2. **算容量**：两个三张吃掉 $a$ 和 $a+1$ 各 3 张，剩下的
   $cap[x] = cnt[x] - 3 \times [x = a] - 3 \times [x = a+1]$ 才能拿去做对子。
3. **数对子**：$b < c$ 要求 $cap[b]$、$cap[c] \ge 2$（这类点数个数记作 |T|），
   $b = c$ 要求 $cap[b] \ge 4$（个数记作 |T4|），这一档贡献 C(|T|, 2) + |T4|。

|T| 和 |T4| 不必每个 $a$ 重扫一遍，用全场的统计量加减修正就能 $O(1)$ 得到，整体只枚举 $a$ 和 $b \le c$。

### 参考代码

```cpp
// 牛客周赛 Round 123 D. 小红打牌
// 题意：手上有 n 张牌（牌面数字 a_i）。一个「飞机」是 10 张牌，重排后能写成
//       {a,a,a,a+1,a+1,a+1,b,b,c,c} 的形状（两个连续的三张 + 两个对子，
//       对子的点数 b、c 随便，可以相等，也可以和三张的点数重合）。
//       问能选出多少种**不同的**飞机（两个飞机相同 ⟺ 十张牌的可重集合完全一样）。
//
// 关键 1：飞机由 (a, b, c) 决定，且**这三个数是唯一的**——
//         假设同一个可重集合还能写成 (a', b', c') 且 a' ≠ a：
//         a' ≥ a+2 时集合里至少有 4 种不同的点数各 ≥3 张，共 ≥12 张 > 10 张，不可能；
//         a' = a+1 时点数 a+1 需要 ≥6 张，加上 a、a+2 各 3 张也是 ≥12 张，不可能。
//         所以数飞机 = 数合法三元组 (a, b ≤ c)。
// 关键 2：对固定的 a，三张的部分吃掉 cnt[a] 和 cnt[a+1] 各 3 张，
//         剩下的容量 cap[x] = cnt[x] - 3*[x==a] - 3*[x==a+1]。
//         两个对子要求：b < c 时 cap[b], cap[c] ≥ 2；b == c 时 cap[b] ≥ 4。
//         于是令 T = {x : cap[x] ≥ 2}、T4 = {x : cap[x] ≥ 4}，
//         这一档的贡献就是 C(|T|, 2) + |T4|。
// 关键 3：|T| 和 |T4| 可以用全场统计量 O(1) 算出来（见代码），不必每个 a 重扫。
#include <bits/stdc++.h>
using namespace std;

const int MAXA = 200005;                 // a_i ≤ 2*10^5
const long long MOD = 998244353;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<int> cnt(MAXA + 2, 0);
    for (int i = 0; i < n; i++) {
        int v;
        cin >> v;
        cnt[v]++;
    }

    // 全场统计：有多少种点数够 2 张、够 4 张
    long long g2 = 0, g4 = 0;
    for (int v = 1; v <= MAXA; v++) {
        if (cnt[v] >= 2) g2++;
        if (cnt[v] >= 4) g4++;
    }

    long long ans = 0;
    for (int a = 1; a + 1 <= MAXA; a++) {
        if (cnt[a] < 3 || cnt[a + 1] < 3) continue;   // 两个三张凑不出来

        // |T| = g2 - 2 + [cnt[a]≥5] + [cnt[a+1]≥5]
        // （a 与 a+1 本来都算进了 g2，扣掉；如果它们还剩 ≥2 张，再加回来）
        long long T = g2 - 2 + (cnt[a] >= 5) + (cnt[a + 1] >= 5);
        // |T4| = g4 - [cnt[a]≥4] - [cnt[a+1]≥4] + [cnt[a]≥7] + [cnt[a+1]≥7]
        long long T4 = g4 - (cnt[a] >= 4) - (cnt[a + 1] >= 4)
                          + (cnt[a] >= 7) + (cnt[a + 1] >= 7);

        long long pairs2 = T >= 2 ? T * (T - 1) / 2 : 0;   // 两个不同的点数做对子
        ans = (ans + pairs2 % MOD + T4 % MOD) % MOD;       // 同一个点数做两个对子
    }

    cout << ans % MOD << "\n";
    return 0;
}
```

### 复杂度

读入 $O(n)$，统计 g2 / g4 一次 $O$(值域)，再枚举 $a$ 一次 $O$(值域)。总时间 O(n + 值域)，
空间 $O$(值域)。值域取 $2 \times 10^5 + 2$（因为要访问 $cnt[a+1]$）。

### 易错点

1. **漏掉 $b = c$ 的情况**。样例 1（七个 1、三个 2）就是靠两个对子都取 1 才成立的，
   只数"两个不同点数"会得到 0。
2. **$b$、$c$ 可以等于 $a$ 或 $a+1$**，此时它们能用的张数要减掉 3（三张已经用掉了），
   所以判断"够不够 2 张"用的是 $cnt[a] \ge 5$ 而不是 $cnt[a] \ge 2$。
3. **忘了取模**，或者用 `int` 存中间结果（C(|T|,2) 能到 $2 \times 10^{10}$，必须 `long long`）。
4. 数组要开到 $2 \times 10^5 + 2$：$a$ 最大是 $2 \times 10^5$，代码会访问 $cnt[a+1]$。
5. $n < 10$ 时一架飞机都凑不出来，公式会自动给出 0（因为没有任何 $a$ 满足 $cnt[a] \ge 3$ 且 $cnt[a+1] \ge 3$）。

## E. 小红出牌（easy）

### 题意

- 「顺子」= 若干张牌，从小到大排序后每相邻两张都差 1（也就是数字连续的一段）；
  **单独一张牌也是顺子**；
- 本题保证 $n$ 张牌的数字**互不相同**（这是它和 F 题唯一的区别）；
- 对**每一个前缀** $a_1$ ~ $a_x$（$x$ 从 1 到 $n$），求把这些牌全部出成顺子所需的**最少次数**；
- 输出 $n$ 个整数，第 $i$ 个是前 $i$ 张牌的答案。

### 从零讲：顺子 = 数轴上连续的一段

#### 顺子到底是什么

每张牌上的数字可以看成数轴上的一个刻度。一批牌能拼成一个顺子，当且仅当它们占的刻度
**挨在一起、中间没有空**：

```
  题面说：k 张牌是一个顺子 ⟺ 从小到大排序后每相邻两张都差 1。
  换句话说，顺子就是**数轴上挨在一起的一段**，中间不许有空。
  拿题面自己的例子 a = {4,3,6,7,5} 看，排好序是 3,4,5,6,7：
                  3   4   5   6   7

      ·   ·   ·   ━━━━━━━━━━━━━━━━━   ·
  这一整段连着，所以 5 张牌**一次**就能出完。
  再看 {3,5}：中间缺了 4，粗线连不起来，只能算两张单牌（两张单牌各自也是顺子）。
                  3       5

      ·   ·   ·   ·   ·   ·   ·
```

上面第一张图里 3、4、5、6、7 连成一片，一次就能出完；第二张图里 3 和 5 中间缺了 4，
连不起来，只能算两张单牌（单独一张也算顺子）。

#### 最少出牌次数为什么等于"连续段数"

把前缀里的数字画在数轴上，它会裂成若干**连续段**（段内相邻、段与段之间至少空一个数字）。

- **至少**要出"段数"次：两张数字相差超过 1 的牌，永远不可能待在同一个顺子里
  （顺子要求中间的数字一个不缺，而手上根本没有中间那些牌），所以每个段只能在自己内部拼，
  一个段至少要出一次；
- **段数就够**：一个段里的数字是连续的，把它们全放进一个顺子即可。

所以「最少次数 = 连续段的个数」。

#### 前缀一个个来：新牌怎么和邻居合并

本题要求对每个前缀都回答，如果每个前缀都重新排序重扫一遍就是 $O(n^2)$，太慢。
关键是**在线维护段数**：每读入一张新牌 $v$：

1. 先算 **+1**：$v$ 还不认识任何邻居时，它自己是一段；
2. 如果 $v-1$ 已经在手上，那 $v$ 就能接在"包含 $v-1$ 的那一段"右边 → 段数 **$-1$**；
3. 如果 $v+1$ 已经在手上，$v$ 也能接在它左边 → 段数再 **$-1$**。

为什么这两步就够了？因为本题数字**互不相同**，$v$ 至多只有一个左邻居 $v-1$ 和一个右邻居 $v+1$。
两个邻居都在时，说明 $v$ 正好把左右两段"焊"成一段：段数从 2 段变 1 段，净变化 $+1-1-1 = -1$，
正好对得上。

#### 为什么这题能用"段"，F 题就不行

因为这道题**数字互不相同**：一个数字最多一张牌，所以"数字连续的一段"直接等于"一个顺子"。

F 题允许重复：同一个数字有 3 张牌时，一个顺子里放不下 3 张相同的牌
（顺子里每个数字只能出现一次）。这时"段"的说法就不够了，
F 题要换成另外一个公式，见下一题。

#### 两个常见疑问

**Q1：单独一张牌真的算顺子吗？**
算。题面明说"特殊的，单独的一张牌也是顺子"，所以 $n = 1$ 时答案是 1。

**Q2：为什么要"在线"维护，不能每个前缀单独算吗？**
$n$ 最多 $10^5$，每个前缀重扫一遍是 $O(n^2) = 10^{10}$，会超时。在线维护每张牌只花 $O(1)$，
总共 $O(n)$。

### 手算

样例：$n = 5$，牌面依次是 5 3 1 2 4（注意是**按抽到的顺序**，不是排好序的）。

| 前 $x$ 张 | 手上的数字 | 能怎么出 | 最少次数 |
|---|---|---|---|
| 1 | {5} | {5} | 1 |
| 2 | {5,3} | {5} + {3} | 2 |
| 3 | {5,3,1} | {5} + {3} + {1} | 3 |
| 4 | {5,3,1,2} | {5} + {3,1,2} | 2 |
| 5 | {5,3,1,2,4} | {5,3,1,2,4} = {1,2,3,4,5} | 1 |

答案是 1 2 3 2 1，和题面一致。注意第 4 步：新来的 2 把原来的 {1} 和 {3} **接成了一段**，
次数反而从 3 掉到 2。

### 思路

一个牌集最少要拆成几个顺子？答案就是它的**连续段数**：同一段连续的牌合成一个顺子最省，
分成两段就一定得两次。

于是问题变成「在线维护当前集合有几段」：

- 每来一张新牌 $v$，先 +1（它自己算一段）；
- 若 $v - 1$ 已在集合里，它就能和左边那段接上 → 段数 $-1$；
- 若 $v + 1$ 也在集合里，右边那段也能接上 → 段数再 $-1$。

（左右都在时，$v$ 把原本分开的两段焊成一段，正好 $-2$。）按输入顺序逐张处理、每张输出一次段数即可。

### 参考代码

```cpp
// 牛客周赛 Round 123 E. 小红出牌（easy）
// 题意：n 张牌，数字**互不相同**。「顺子」＝ 若干张数字连续（可重排成 x, x+1, ..., x+k-1）的牌。
//       对每个前缀 a[1..x]，求把这些牌全部出成顺子所需的**最少次数**（每个顺子算一次）。
//
// 关键：一个牌集能拆成的最少顺子数 = 这个集合里「连续段」的个数。
//       （同一段连续的牌合成一个顺子最省；分开成两段就一定得两次。）
//       于是只要在线地维护「当前集合有几段」：
//       每来一张新牌，先 +1（它自己算一段），
//       如果 v-1 已经在集合里，就能和左边那段接上 → 段数 -1；
//       如果 v+1 已经在集合里，就能和右边那段接上 → 段数 -1。
//       （左右都在时两张邻牌本来分属两段，接上后合为一段，正好 -2。）
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<char> has(n + 2, 0);        // has[v]：数字 v 是否已经出现过（a_i ≤ n，多开两格防越界）

    long long segs = 0;                // 当前集合的连续段数
    for (int i = 1; i <= n; i++) {
        int v;
        cin >> v;

        has[v] = 1;
        segs++;                        // 新牌先单独算一段
        if (has[v - 1]) segs--;        // 左邻居在 → 并进左边那段
        if (has[v + 1]) segs--;        // 右邻居在 → 并进右边那段

        cout << segs << (i == n ? '\n' : ' ');
    }
    return 0;
}
```

### 复杂度

每个前缀只做常数次判断：总时间 $O(n)$，空间 $O(n)$（一个标记数组 has）。

### 易错点

1. **标记数组要开到 $n + 2$**（代码里访问 $has[v-1]$ 和 $has[v+1]$，$v$ 可以等于 $n$，
   所以 has 至少要能放下标 $n+1$）。
2. **先 +1 再判断邻居**的顺序不影响结果（判断的是 $v-1$ 和 $v+1$，与 $v$ 自己无关），
   但一定要两个邻居都判断，只判左边会漏掉"接右边"的情况。
3. 输出是**读一张输出一个数**、共 $n$ 个数、空格分隔，别输出成"一行一个"。
4. 题面保证 $a_i \le n$ 且互不相同，所以不用担心重复和越界；
   但如果你把数组开到 $10^5$ 而 $n$ 也用 $10^5$，注意下标从 1 开始。

## F. 小红出牌（hard）

### 题意

和 E 题**只有一句话不同**：本题**不保证**牌面数字互不相同。其余完全一样：
对每个前缀，求把这些牌全部出成顺子的最少次数。

### 手算

样例：$n = 6$，牌面依次是 1 3 1 2 3 2。

| 前 $x$ 张 | 每种数字几张 | 最少次数 | 怎么出 |
|---|---|---|---|
| 1 | $1 \times 1$ | 1 | {1} |
| 2 | $1 \times 1, 3 \times 1$ | 2 | {1} + {3} |
| 3 | $1 \times 2, 3 \times 1$ | 3 | {1} + {3} + {1} |
| 4 | $1 \times 2, 2 \times 1, 3 \times 1$ | 2 | {1,2,3} + {1} |
| 5 | $1 \times 2, 2 \times 1, 3 \times 2$ | 3 | {1,2,3} + {1} + {3} |
| 6 | $1 \times 2, 2 \times 2, 3 \times 2$ | 2 | {1,2,3} + {1,2,3} |

答案 1 2 3 2 3 2，和题面一致。

### 思路

> 「顺子 = 数轴上连续的一段、前缀在线维护段数」这条思路在本文 **E 题的「从零讲：顺子 = 数轴上连续的一段」一节**已经完整讲过，
> 这里只补 E 题没有的那一半：**同一个数字有多张牌时**怎么办。

#### 为什么"数段数"不够用了

E 题里一个数字最多一张牌，所以"连续的数字"天然就是一个顺子。
现在数字会重复：手上三张 2，不可能把三张 2 塞进同一个顺子
（顺子排序后每个数字只出现一次）。所以要换一个角度：**数每张牌属于哪个顺子**。

#### 公式：最少顺子数 = $\sum \max(0, cnt[v] - cnt[v-1])$

设 $cnt[v]$ = 前缀里数字 $v$ 的张数，并规定 $cnt[0] = 0$。答案就是

$$\sum_v \max(0, cnt[v] - cnt[v-1])$$

**为什么这是下界**：看数字 $v$ 的这些牌。每个顺子内部数字是连续的，
所以在数字 $v$ 这里，"从前面延伸过来"的顺子最多只有 $cnt[v-1]$ 个
（一个顺子最多经过 $v-1$ 一次，也就最多带一张 $v-1$）。剩下的 $cnt[v] - cnt[v-1]$
个顺子必须在 $v$ 这里**开一个头**（以 $v$ 为最小数字）。每个顺子恰好只有一个"开头"，
把所有正的开头数加起来，就是顺子总数的下界。

**为什么能达到**：按"能接上左边就接上"的贪心去配（数字 $v$ 的牌优先接在还没结束的
顺子后面），就能做到每个数字 $v$ 恰好有 $\max(0, cnt[v] - cnt[v-1])$ 个新开头。
下界可达，所以它就是最小值。

#### 验证一下直觉

`cnt = 2 1 2 1`（数字 1 有 2 张、数字 2 有 1 张、数字 3 有 2 张、数字 4 有 1 张）。
下面这段是配图脚本的真实输出，柱状图后面那张表就是"把它代进公式"的结果：

```
  F 题不保证互不相同，一段里同一个数字只能放一张牌，
  所以「有几段」这个说法不够用了。换成数**每张牌属于哪个顺子**：
  设 cnt[v] = 数字 v 有几张。数字 v 的这些牌里，最多有 cnt[v-1] 张能接在
  某个「已经走到 v-1 的顺子」后面（一个顺子最多经过 v-1 一次），
  所以至少要有 cnt[v] - cnt[v-1] 个顺子**从 v 开始**。把所有「开头」加起来：

      最少顺子数 = Σ_v max(0, cnt[v] - cnt[v-1])      （规定 cnt[0] = 0）

  每个顺子恰好有一个开头，所以这个和正好是顺子个数。
  例：cnt[1]=2, cnt[2]=1, cnt[3]=2, cnt[4]=1，柱子画出来是这样：


          ┃       ┃

          ┃   ┃   ┃   ┃

      0   1   2   3   4
  把它代进公式：
  数字 v  cnt[v]  cnt[v-1]  max(0, 差)
  ──────  ──────  ────────  ──────────
       1       2         0           2
       2       1         2           0
       3       2         1           1
       4       1         2           0
  四项相加 = 2 + 0 + 1 + 0 = 3，所以最少出 3 次：
    {1,2,3,4} + {1,3} + {3}   —— 三个顺子，正好把 6 张牌出完。
```

也就是 2 + 0 + 1 + 0 = 3 次，对应 {1,2,3,4} + {1,3} + {3}。

#### 每读一张牌，只有两项会变

要求输出 $n$ 个答案，不能每步把整个数组重算一遍（$O(n^2)$ 会超时）。
注意 $cnt[v]$ 一变，和式里只有两项会动：

- $term(v) = \max(0, cnt[v] - cnt[v-1])$；
- $term(v+1) = \max(0, cnt[v+1] - cnt[v])$。

所以每步做法是：先记住这两项的旧值 → `cnt[v]++` → 再算这两项的新值 →
总和加上差值。整体 $O(n)$。下面这段是同一份配图脚本（`A-G\E\runs_visual.py` 第 5 部分）的实跑输出：

```
  官方样例 a = 1 3 1 2 3 2。cnt[v] 一变，只有 term(v) 和 term(v+1) 这两项会动，所以每步 O(1) 就能更新总和。
  新牌 v  改前 term(v)+term(v+1)  改后  增量  总和
  ──────  ──────────────────────  ────  ────  ────
       1                       0     1     1     1
       3                       0     1     1     2
       1                       1     2     1     3
       2                       1     0    -1     2
       3                       0     1     1     3
       2                       1     0    -1     2
  答案：1 2 3 2 3 2
  官方样例输出：1 2 3 2 3 2  →  一致
  注意第 4 步（读到第 4 张牌 2）总和反而变小了：因为 2 一来，
  数字 3 的牌就能接上，原来的两个顺子并成了一个——这正是「段数合并」。
```

注意第 4 步总和从 3 掉到 2：数字 2 一来，数字 3 的牌就能接上，
原来的两个顺子并成了一个——这正是 E 题里"两段合并"的同一件事。

### 参考代码

```cpp
// 牛客周赛 Round 123 F. 小红出牌（hard）
// 题意：跟 E 题一样，只是**不再保证牌面数字互不相同**。
//       对每个前缀 a[1..x]，求把这些牌全部出成顺子所需的最少次数。
//
// 关键：设 cnt[v] = 前缀里数字 v 的张数（cnt[0] = 0）。则
//       最少顺子数 = Σ_v max(0, cnt[v] - cnt[v-1])。
//       为什么：数字 v 的 cnt[v] 张牌，每张都待在某个顺子里；一个顺子最多
//       只经过 v-1 一次，所以最多有 cnt[v-1] 个顺子能「从 v-1 延伸过来」，
//       剩下 cnt[v] - cnt[v-1] 个顺子必须在 v 这里**开头**。把这些开头数加起来
//       就是顺子总数（每个顺子恰有一个最小数字）。反过来按「尽量接上左边」
//       贪心配对就能达到这个下界，所以它正好是最小值。
//
//       实现：每读入一张 v，只有 v 和 v+1 两项的值会变，O(1) 局部更新即可。
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<long long> cnt(n + 2, 0);   // a_i ≤ n，多开两格给 v+1 用

    auto term = [&](int v) {           // 第 v 项：max(0, cnt[v] - cnt[v-1])
        return max(0LL, cnt[v] - cnt[v - 1]);
    };

    long long total = 0;               // Σ term(v)
    for (int i = 1; i <= n; i++) {
        int v;
        cin >> v;

        long long before = term(v) + term(v + 1);   // 会受影响的两项：v 和 v+1
        cnt[v]++;                                    // 新牌进桶
        long long after = term(v) + term(v + 1);
        total += after - before;

        cout << total << (i == n ? '\n' : ' ');
    }
    return 0;
}
```

### 复杂度

每张牌 $O(1)$ 更新：总时间 $O(n)$，空间 $O(n)$（一个计数数组 cnt）。

### 易错点

1. **cnt 数组要开到 $n + 2$**：代码里会访问 $cnt[v+1]$，$v$ 最大是 $n$，所以下标要到 $n+1$。
2. **$cnt[0]$ 必须是 0**：数组多开一格、下标 0 从不加牌，就自动满足（公式要求 $cnt[0] = 0$）。
3. **别每步重新求和**：那是 $O(n^2)$。只更新 $term(v)$ 和 $term(v+1)$ 两项。
4. 总和用 `long long` 存（$n = 10^5$ 时总和最大也就是 $10^5$，但养成习惯没坏处）。
5. 输出是 $n$ 个数、空格分隔；每步都要输出，别只在最后输出一个。

## G. 小红出千

### 题意

- $n$ 张牌，牌面 $a_i$ 可以很大（$\le 10^9$），可以重复；
- 每次「出千」：把**任意一张**牌的数字改成**任意正整数**；
- 目标：让这 $n$ 张牌整体成为一个**顺子**——也就是重排后是 $x, x+1, \ldots, x+n-1$，
  即 **$n$ 个互不相同的连续整数**；
- 求最少出千次数，并输出方案（每行"第 $i$ 张牌 改成 $x$"，$1 \le x \le 2 \times 10^9$）。

### 从零讲：同向双指针（滑动窗口）

#### 第一步：先想清楚"哪些牌可以留下来"

最后的结果是**互不相同的连续 $n$ 个整数**，所以：

- 留下来的牌，数字必须**两两不同**——同一个数字有 3 张，最多留 1 张，另外 2 张必须改；
- 留下来的牌，必须能塞进某个长度为 $n$ 的区间 $[L, L+n-1]$（连续 $n$ 个整数就是这么一个区间）。

于是问题变成：**找一个长度 $n$ 的区间，让它覆盖尽量多种"不同的数字"**，
答案就是 $n -$ 最多覆盖的种类数。为什么是"种类数"而不是"张数"？
因为同一个数字只能留一张。

#### 双指针是什么

把出现过的数字排序去重，得到 $D[0], D[1], \ldots, D[m-1]$（升序）。我们要找一个**下标区间**
$[i, j]$，使得 $D[j] - D[i] \le n-1$（能塞进长度 $n$ 的窗口）且 $j - i + 1$ 尽量大。

最朴素的办法是枚举 $i$、再枚举 $j$，$O(m^2)$ 太慢。**同向双指针**的做法是：

- $j$ 从 0 往右一格一格走；
- 每走一格，如果 $D[j] - D[i] > n-1$（窗口装不下了），就把 $i$ 也往右推，直到重新装得下；
- 用一个变量记下**历史上出现过的最宽窗口**。

两个下标都只往右走、从不回头，所以总共只看 $O(m)$ 步。

为什么 $i$ 回头没有意义？因为 D 是升序的：$j$ 变大时 $D[j]$ 只会更大，
"装不下"这件事只会变得更严重，所以左端只能往右挪。**这就是双指针成立的全部理由。**

#### 在这题里怎么用（走一遍样例 1）

D = [1, 2, 3, 4, 6]，$n = 5$（窗口跨度最多 4）。$j$ 一步步往右：

| $j$ | $D[j]$ | 左端 $i$ | 窗口里的数字 | 种类数 | 历史最好 |
|---|---|---|---|---|---|
| 0 | 1 | 0 | 1 | 1 | 1 |
| 1 | 2 | 0 | 1,2 | 2 | 2 |
| 2 | 3 | 0 | 1,2,3 | 3 | 3 |
| 3 | 4 | 0 | 1,2,3,4 | 4 | 4 |
| 4 | 6 | 1 | 2,3,4,6 | 4 | 4 |

历史上最好成绩是 4（窗口 [1,5] 覆盖了 1、2、3、4 四种数字），所以
最少出千次数 = $5 - 4 = 1$ 次。

```
  把出现过的数字排序去重成 D[0..m-1]。窗口左端 i 只会往右走，不会回头：
  右端 j 往右挪一格时，如果 D[j] - D[i] 超过了 n-1（装不进窗口），就把 i 往右推，
  直到重新装得下。i 一共只会走 m 步，所以整体 O(m)。
  j  D[j]  左端 i  窗口里的数字  个数   本步动作   最好成绩
  ─  ────  ──────  ────────────  ────  ──────────  ────────
  0     1       0  1                1  —                  1
  1     2       0  1,2              2  —                  2
  2     3       0  1,2,3            3  —                  3
  3     4       0  1,2,3,4          4  —                  4
  4     6       1  2,3,4,6          4  左端吐出 1         4
  最后一行 j=4（数字 6）时，窗口被迫左移到只剩 6 自己，
  但「最好成绩」早就记下了 4 —— 这就是**取历史最大**，不是看最后一个窗口。
```

#### 方案怎么生成

1. 用最好的那个窗口确定目标顺子：取 $L = \max(1, D[j] - n + 1)$
   （窗口右端顶住 $D[j]$，往回退 $n-1$ 就是起点；但 L 不能小于 1，所以套一个 $\max$）。
   为什么要往回退到右端？因为这样窗口一定还在 $[L, L+n-1]$ 里，不会漏掉窗口里的数字。
2. **保留**：窗口里每个数字，取它在输入里**第一次出现**的那张牌；
3. **要改的牌** = 剩下的所有牌；**要填的空缺** = $[L, L+n-1]$ 里没被保留数字占用的那些；
4. 两边数量一定相等（保留了几张，就空出几个位置），按顺序一一对应填进去。

```
  输入：n = 5，牌面 1 2 3 4 6（第 i 张牌的下标就是 i）
  去重后的数字 D = [1, 2, 3, 4, 6]
  最好的窗口：包含 4 种数字，起点 L = 1，也就是目标顺子 [1, 2, 3, 4, 5]


          1   2   3   4       6

      ·   ·   ·   ·   ·   ·   ·   ·
```

#### 两个常见疑问

**Q1：为什么数的是"不同数字的种数"，不是"牌的张数"？**
因为最后必须是 $n$ 个**互不相同**的连续整数。同一个数字有两张牌，只有一张能留在原位。
比如 $n = 3$、牌面 5 5 5：能保留 1 张，另外 2 张必须改（改成 6、7 之类）。

**Q2：L 为什么要写 $\max(1, \ldots)$？**
牌面都是正整数，目标顺子也必须全是正整数。如果 $D[j] - n + 1$ 算出来是 0 或负数，
说明窗口可以整体往右挪到从 1 开始（因为手上的数字都 $\ge 1$，这样不会漏掉任何数字）。
比如 $n = 3$、牌面 1 1 1：D = [1]，$L = \max(1, 1-3+1) = 1$，目标是 {1,2,3}。

### 手算

样例 1：$n = 5$，牌面 1 2 3 4 6。

- 若目标顺子取 [1,5]：1、2、3、4 都能原样留着，只有 6 得改 → 改 1 次；
- 能不改吗？不改的话五张牌是 1、2、3、4、6，中间缺 5、多一个 6，不连续 → 不行。

所以答案是 1 次，方案：把第 5 张改成 5。

样例 2：1 2 3 本身连续 → 0 次。

### 思路

1. **什么牌能原样保留**：最终是 $n$ 个互不相同的连续整数，所以留下来的牌必须数字互不相同、
   且都落在某个长度 $n$ 的区间 $[L, L+n-1]$ 内。于是「最多保留几张」= 数轴上某个长 $n$ 的窗口里
   最多能覆盖几点不同的数字（同一个数字哪怕有 10 张也只能保 1 张）。
2. **求这个最大值**：把出现过的数字排序去重成 D，用同向双指针找 $D[j] - D[i] \le n - 1$ 的最宽窗口，
   窗口长度就是最多保留数，答案 = $n -$ 保留数。
3. **给方案**：取 $L = \max(1, D[j] - n + 1)$，窗口里每个数字保留**第一次出现**的那张牌，
   剩下的空闲牌依次填进 $[L, L+n-1]$ 里没被占用的数字（空闲牌数正好等于空缺数）。

### 参考代码

```cpp
// 牛客周赛 Round 123 G. 小红出千
// 题意：n 张牌（数字 a_i ≤ 10^9，可能有重复）。每次「出千」可以把任意一张牌改成
//       任意正整数。要使这 n 张牌最终成为一个「顺子」（重排后 x, x+1, ..., x+n-1，
//       即 n 个互不相同的连续整数），求最少出千次数，并给出一种方案。
//
// 关键 1：最后是 n 个**互不相同**的连续整数，所以**原样保留**下来的牌必须
//         数字互不相同，而且都落在一个长度 n 的区间 [L, L+n-1] 里。
//         所以「保留几张」= 某个长度 n 的区间里，最多覆盖多少种**不同的**数字。
//         （同一个数字有 10 张也只能保 1 张，其余的全得改。）
// 关键 2：把出现过的数字排序去重成 D[0..m-1]，用**同向双指针**求
//         D[j] - D[i] ≤ n-1 的最宽窗口，窗口里的数字个数就是能保留的最大张数。
//         答案 k = n - 最多保留数。
// 关键 3：构造方案——区间取 L = max(1, D[j] - n + 1)，保留窗口里每个数字
//         **第一次出现**的那张牌，剩下的每张空闲牌依次填进 [L, L+n-1] 里
//         没被占用的数字（空闲牌数 = 空缺数，正好一一对应）。
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<long long> a(n + 1);
    for (int i = 1; i <= n; i++) cin >> a[i];

    // 按（数字，下标）排序，得到去重后的数字表 D 和每个数字第一次出现的下标
    vector<int> ord(n);
    iota(ord.begin(), ord.end(), 1);
    sort(ord.begin(), ord.end(), [&](int i, int j) {
        return a[i] != a[j] ? a[i] < a[j] : i < j;
    });

    vector<long long> D;                 // 出现过的数字（升序、去重）
    vector<int> firstIdx;                // 每个数字在输入里第一次出现的下标
    for (int k = 0; k < n; k++) {
        if (k == 0 || a[ord[k]] != a[ord[k - 1]]) {
            D.push_back(a[ord[k]]);
            firstIdx.push_back(ord[k]);
        }
    }
    int m = (int)D.size();

    // 同向双指针：窗口内数字的跨度不超过 n-1（这样它们才能塞进长度 n 的区间）
    int best = 0, bi = 0, bj = 0, i = 0;
    for (int j = 0; j < m; j++) {
        while (D[j] - D[i] > n - 1) i++;
        if (j - i + 1 > best) { best = j - i + 1; bi = i; bj = j; }
    }

    long long L = max(1LL, D[bj] - (long long)n + 1);   // 目标顺子的起点

    // 保留：窗口里每个数字取第一次出现的那张
    vector<char> keep(n + 1, 0);
    for (int k = bi; k <= bj; k++) keep[firstIdx[k]] = 1;

    // 要改的牌（按输入顺序）与要填的空缺（按数字升序）
    vector<int> freeCard;
    for (int x = 1; x <= n; x++) if (!keep[x]) freeCard.push_back(x);

    vector<long long> freeTarget;
    int p = bi;                                  // 窗口里被保留数字的下标
    for (long long t = L; t <= L + n - 1; t++) {
        if (p <= bj && D[p] == t) { p++; continue; }   // 这个数字已被保留的牌占用
        freeTarget.push_back(t);
    }

    cout << freeCard.size() << "\n";
    for (size_t k = 0; k < freeCard.size(); k++)
        cout << freeCard[k] << " " << freeTarget[k] << "\n";
    return 0;
}
```

### 复杂度

排序 + 去重 $O(n \log n)$，双指针扫描 $O(m)$（$m$ 是不同数字的种数，$m \le n$），
生成方案 $O(n)$。总时间 $O(n \log n)$，空间 $O(n)$。

### 易错点

1. **别把"保留的张数"当成"窗口里的牌数"**：同一个数字有多张牌时只能留 1 张，
   所以统计的是**不同数字**的种数（代码里先排序去重就是这个原因）。
2. **L 要 $\ge 1$**：窗口右端往回退时可能退到 0 或负数，必须 $\max(1, \ldots)$。
3. **新数字最大到 $2 \times 10^9$**，用 `long long` 存，别用 `int` 算 $L + n - 1$。
4. 本题是 **Special Judge**（方案不唯一），牛客"自测运行"可能报错；
   但一定要保证改完以后**真的是** $n$ 个连续整数，一个重复都不能有。
5. 排序时**值相同的牌按下标升序**排（代码里的比较函数写了 $i < j$），
   这样"每个数字第一次出现的那张"就是输入里最靠前的那张，方案才稳定可复现。
6. 保留的牌不用输出，只输出被改的牌；第一行是**要改的张数**，不是总张数。
