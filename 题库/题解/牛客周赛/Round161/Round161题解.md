## A. 小月的亮灯

### 题意

一条刻度线上有 3 盏灯，输入三个 0 或 1 的数 $a_0$、$a_1$、$a_2$。

第 $i$ 盏灯（$i$ 取 1、2、3）的状态就是 $a_{i-1}$：它亮着，小月得 $i - 1$ 分。求总分。

翻译成一句人话：

- 第 1 盏灯（$a_0$）亮 → 得 0 分
- 第 2 盏灯（$a_1$）亮 → 得 1 分
- 第 3 盏灯（$a_2$）亮 → 得 2 分

总分 = $a_1 \times 1 + a_2 \times 2$。$a_0$ 亮不亮都加 0，写不进式子都一样。

### 手算

样例 1：1 0 1

| 灯 | 状态 | 亮着得分 | 实得 |
|---|---|---|---|
| 第 1 盏 | 1 | 0 | 0 |
| 第 2 盏 | 0 | 1 | 0 |
| 第 3 盏 | 1 | 2 | 2 |

合计 0 + 0 + 2 = 2，跟样例输出对上。

样例 2：0 1 1 → 0 + 1 + 2 = 3。样例 3：0 0 0 → 0。

### 思路

总分就是「每盏亮着的灯各贡献自己那一分」再加起来：

总分 = $a_0 \times 0 + a_1 \times 1 + a_2 \times 2$

第 1 盏灯的系数是 0，亮不亮都不影响答案——可以简写成 $a_1 + 2 \times a_2$，
但保留三个系数一一对应更不容易记错。数据只有 3 个数，不用循环、也不用判断范围。

### 参考代码

```cpp
#include <bits/stdc++.h>
using namespace std;

// 第 i 盏灯（i = 1,2,3）的状态是 a[i-1]，亮着就得 i-1 分
int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int a0, a1, a2;
    cin >> a0 >> a1 >> a2;

    int ans = a0 * 0 + a1 * 1 + a2 * 2;   // 三盏灯的得分分别是 0、1、2
    cout << ans << '\n';
    return 0;
}
```

### 易错点

1. **第 1 盏灯得 0 分，不是 1 分**：题目说「第 $i$ 盏灯得 $i - 1$ 分」，$i$ 从 1 数，所以第一盏是 0 分。写成 a0 * 1 就把样例 1 算成 3 了。
2. **别把灯号和数组下标混在一起**：数组下标从 0 开始，灯的编号从 1 开始，两者差 1。
3. 输入只有 3 个数，不需要循环，也不需要判断范围。

## B. 小月的纪录点

### 题意

$n$ 个数 $a_1 \ldots a_n$。$a_i$ 是「记录点」当且仅当它**严格大于**它左边的所有数；$a_1$ 无条件算记录点。

输出两件事：

1. 记录点一共有几个；
2. 相邻两个记录点下标之差的最大值（记录点少于 2 个时算 0）。

### 手算

样例 1：6 个数 2 1 4 3 5 5

| 下标 $i$ | $a_i$ | 左边见过最大值 | 是不是记录点 |
|---|---|---|---|
| 1 | 2 | — | 是（第一个无条件算） |
| 2 | 1 | 2 | 不是（1 < 2） |
| 3 | 4 | 2 | 是（4 > 2） |
| 4 | 3 | 4 | 不是 |
| 5 | 5 | 4 | 是（5 > 4） |
| 6 | 5 | 5 | **不是**（相等不算，必须严格大于） |

记录点下标 = 1、3、5，共 3 个；相邻差分别是 $3 - 1 = 2$、$5 - 3 = 2$，最大是 2。输出 3 2。

样例 2：7 6 5 4 3 一路下降，只有第一个是记录点 → 1 0。

### 思路

判断 $a_i$ 是不是记录点，只需要知道一件事：左边最大的数是多少。

- 如果 $a_i >$ 左边最大值 → 它是记录点，同时左边最大值被它刷新；
- 否则它不是记录点，最大值不变。

所以从左到右走一遍，用一个变量 `mx` 记「目前为止的最大值」就够了，不用回头看前面所有数。

记下上一个记录点的下标 last，每遇到新记录点就更新答案 `best = max(best, i − last)`。

### 参考代码

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<long long> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    // a[0] 一定是记录点，先把它记上
    long long mx = a[0];          // 目前见过的最大值
    int cnt = 1;                  // 记录点个数
    int last = 0;                 // 上一个记录点的下标
    int best = 0;                 // 相邻记录点下标之差的最大值

    for (int i = 1; i < n; i++) {
        if (a[i] > mx) {          // 严格大于左侧所有元素
            cnt++;
            best = max(best, i - last);
            last = i;
            mx = a[i];
        }
    }

    cout << cnt << ' ' << best << '\n';
    return 0;
}
```

### 易错点

1. **相等不算记录点**：条件必须是 >，写成 >= 的话样例 1 会多出第 6 个位置的记录点，输出变成 4 1。
2. **$a_1$ 无条件算**：代码里把 `cnt` 初始化成 1、`mx` 初始化成 $a_0$，循环从 $i = 1$ 开始，就是为了这件事。
3. **差值不是减 1**：相邻记录点的下标差是 $i - last$（两个下标的差）。在第 2 个记录点之前 `best` 一直是 0，正好对应「记录点少于 2 个时输出 0」，不用特判。
4. **$a_i$ 可以到 $\pm 10^9$**：用 `int` 也能装下（$\pm 2.1 \times 10^9$），但差值最大只有 $2 \times 10^5 - 1$，`int` 足够。这里用 `long long` 存数组是留余量。
5. $n$ 可以到 $2 \times 10^5$，别写 $O(n^2)$ 的「回头看左边所有数」，会超时（不过它正是本题对拍用的暴力，见文末实测记录）。

## C. 小月的排序

### 题意

- $n$ 个非负整数，$n \le 2 \times 10^5$，每个数 $< 2^{31}$；
- 输出**按这套规则排好序之后**的第 $k$ 个元素。

排序规则有三条，依次比较，前一条分不出胜负才看下一条：

1. 二进制里 1 的个数（popcount）少的更小；
2. 最低位 1 所在位更低的更小（0 特殊，记为第 31 位）；
3. 前两条都一样时，数值小的更小。

注意「第 $k$ 个」是按排序后的新次序数的第 $k$ 个，不是原数组第 $k$ 个 —— 排序是不稳定的吗？没关系，规则 3 比数值，数值相同的数谁前谁后无所谓，输出值一样。

### 从零讲：popcount 和「最低位 1 在第几位」

#### 是什么

一个非负整数写成二进制后：

- **popcount**：里面有多少个 1。比如 7 = 0111 有 3 个，8 = 1000 有 1 个。
- **最低位 1 的位置（lowbit position）**：从右往左数第一个 1 在第几位，个位算第 0 位。比如 12 = 1100，末尾有两个 0，第一个 1 在第 2 位 → 位置是 2；奇数的最低位 1 都在第 0 位。

这两个量都能一眼从二进制里读出来，看这张表（脚本 `bits_visual.py` 跑出来的）：

```
  数值  二进制（低 8 位）  1 的个数  最低位 1 在第几位
  ────  ─────────────────  ────────  ─────────────────
  8     00001000           1         3
  3     00000011           2         0
  4     00000100           1         2
  7     00000111           3         0
  0     00000000           0         31
```

#### 有什么用：把「比较规则」变成「排序键」

排序的本质是给每个元素算一个键，然后按键从小到大排。本题的键是一个三元组：

```
键(a) = (popcount(a), 最低位1的位置(a), a)
```

三元组怎么比？从左到右逐项比，第一项分出胜负就停，否则看第二项 —— 这跟题目的三条规则一字不差。

C++ 里 `sort` 的比较函数就是在回答「$p$ 该排在 $q$ 前面吗」，所以把三元组逐项比写进去即可。

#### 在这题里怎么用

```cpp
sort(a.begin(), a.end(), [](unsigned int p, unsigned int q) {
    int cp = __builtin_popcount(p);   // 规则一
    int cq = __builtin_popcount(q);
    if (cp != cq) return cp < cq;
    int lp = lowbit_pos(p);           // 规则二
    int lq = lowbit_pos(q);
    if (lp != lq) return lp < lq;
    return p < q;                     // 规则三
});
```

其中最低位 1 的位置这样算：

```cpp
int lowbit_pos(unsigned int v) {
    if (v == 0) return 31;        // 0 没有 1，按题意记为 31
    return __builtin_ctz(v);      // 数末尾有几个 0，就是最低位 1 的位置
}
```

`__builtin_ctz(v)` = count trailing zeros（数末尾 0 的个数）；末尾 0 的个数恰好等于最低位 1 的位置。

#### 为什么不用更眼熟的写法

- **手写循环数 1 的个数**（`while (v) { c += v & 1; v >>= 1; }`）当然也行，但它是 31 次循环 $\times n$ 个数 $\times$ 比较次数，实测在这题的数据范围下慢一截；`__builtin_popcount` 是一条 CPU 指令。对拍用的暴力版本就故意写成手写循环，跟内建指令版互相验证。
- **先按数值排序再按规则重排**是不行的：规则 3 只在前两条打平时才用，数值顺序不能提前介入。
- **0 的坑**：`__builtin_ctz(0)` 是未定义行为（0 没有末尾的 1），必须先特判返回 31，否则本地跑出来可能是 32 也可能是别的，样例还碰巧能过，交上去就是随机的。

#### 0 为什么记成第 31 位

0 一个 1 都没有，「最低位 1 在哪」这个问题对它没有答案。题目约定它是第 31 位 —— 比任何真实的最低位（最大第 30 位，因为 $a_i < 2^{31}$）都大，意思是「只要还有别的数跟它 1 的个数相同（只有 1 的个数都是 0 时才可能），0 排后面」。实际上 0 的 popcount 是 0，全场最小，第一条规则就让它排最前了，这条约定主要防止程序崩。

### 手算

输入 5 3，五个数 8 3 4 7 0，问排序后第 3 个。

逐个拆二进制（只写低 4 位就够看）：

| 数值 | 二进制 | 1 的个数 | 最低位 1 在第几位 |
|---|---|---|---|
| 8 | 1000 | 1 | 3 |
| 3 | 0011 | 2 | 0 |
| 4 | 0100 | 1 | 2 |
| 7 | 0111 | 3 | 0 |
| 0 | 0000 | 0 | 31（题目规定） |

排序过程：

- 第一条（1 的个数）：0 是 0 个 → 排最前；8 和 4 都是 1 个；3 是 2 个；7 是 3 个 → 排最后。
- 8 和 4 打个平手，看第二条：4 的最低位 1 在第 2 位，8 在第 3 位 → 4 在前。
- 3 和 7 个数不同，不用再看。

最终顺序：0, 4, 8, 3, 7，第 3 个是 8 ✓（样例输出 8）。

样例 2：4 2，6 5 10 0：

| 数值 | 二进制 | 1 的个数 | 最低位 1 位置 |
|---|---|---|---|
| 0 | 0000 | 0 | 31 |
| 5 | 0101 | 2 | 0 |
| 6 | 0110 | 2 | 1 |
| 10 | 1010 | 2 | 1 |

6 和 10 前两条都一样（2 个 1、最低位都在第 1 位），比数值：6 < 10 → 6 在前。顺序 0, 5, 6, 10，第 2 个是 5 ✓。

### 思路

排序谁都会，本题的考点是**两数怎么比**：不是比数值，而是按「题意」里那三条规则依次比，前一条分不出胜负才看下一条。

把这三条写成一个比较函数丢给 `sort`，再取第 $k$ 个就是答案。

朴素做法：手写冒泡 / 选择排序，每次比较都现算 popcount 和最低位 $\to O(n^2)$ 次比较，$n = 2 \times 10^5$ 时是 $4 \times 10^{10}$ 次，直接超时。

正解：把比较函数交给 `std::sort`，$O(n \log n)$ 次比较，$2 \times 10^5 \times 18 \approx 3.6 \times 10^6$ 次，实测 0.15 秒左右。

只问第 $k$ 个，要不要用 `nth_element`？可以（$O(n)$ 平均），但 `sort` 已经够快了，不必为它多写一次比较逻辑。

### 参考代码

```cpp
#include <bits/stdc++.h>
using namespace std;

// 最低位 1 所在的位序（从 0 开始数）。题目规定 0 的最低位 1 在第 31 位
int lowbit_pos(unsigned int v) {
    if (v == 0) return 31;        // 0 没有 1，按题意记为 31
    return __builtin_ctz(v);      // 数末尾有几个 0，就是最低位 1 的位序
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    cin >> n >> k;
    vector<unsigned int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    sort(a.begin(), a.end(), [](unsigned int p, unsigned int q) {
        int cp = __builtin_popcount(p);   // 规则一：1 的数量少的更小
        int cq = __builtin_popcount(q);
        if (cp != cq) return cp < cq;

        int lp = lowbit_pos(p);           // 规则二：最低位 1 更低的更小
        int lq = lowbit_pos(q);
        if (lp != lq) return lp < lq;

        return p < q;                     // 规则三：数值小的更小
    });

    cout << a[k - 1] << '\n';             // 第 k 个：下标是 k-1
    return 0;
}
```

### 复杂度

- 时间：$O(n \log n)$，$2 \times 10^5$ 时约 $3.6 \times 10^6$ 次比较，每次比较是两条内建指令。
- 空间：$O(n)$，存数组。

### 易错点

1. **`__builtin_ctz(0)` 未定义**：必须特判 0。这是本题最大的坑，详见「从零讲」里 0 为什么记成第 31 位那一小节。
2. **比较函数必须严丝合缝地按三条规则**：漏掉规则 3（数值兜底）的话，`sort` 遇到两个完全相同的数会返回 false，虽不至于崩，但「排完序第 $k$ 个」在数值相同的段里就不再确定；加上规则 3 才和题意一致。
3. **读 $0 \le a_i < 2^{31}$**：用无符号整型装最稳（正好覆盖到 $2^{32}-1$），用 `int` 装也能过，但比较时符号位容易掺进来出事。
4. **$k$ 是 1-based**：第 $k$ 个 → 下标 $k - 1$。
5. 输出的是**排序后的值**，不是下标。

## D. 小月的岛屿

### 题意

一张 $n$ 行 $m$ 列的 01 网格：

- **四连通**意义下：两个格子相邻 $\iff$ 曼哈顿距离 = 1（只认上下左右）；
- **八连通**意义下：两个格子相邻 $\iff$ 切比雪夫距离 = 1（周围 8 格全算，含对角）。

设四连通下 1 的连通块数是 $c_4$、最大块面积是 $s_4$；八连通下是 $c_8$、$s_8$。求 $c_4 - c_8$、$s_4$、$s_8$。没有 1 时两个面积都是 0。

数据范围 $n, m \le 200$ —— 这是在明说：$O(nm)$ 甚至 $O(nm \times 8)$ 都随便跑。

### 从零讲：连通块与洪水填充

#### 是什么

把每个格子看成点，相邻关系看成边，就得到一张图。图里**互相能走到的一批点**叫一个连通块（连通分量）。

「洪水填充」（flood fill）是数连通块的标准动作：

1. 找一个还没被标记的 1；
2. 从它出发，把能走到的所有 1 全部标记成「已经数过」；
3. 连通块计数 +1，刚才标记了多少格子，这块面积就是多少；
4. 回到第 1 步，直到没有没标记的 1。

走法用队列就是 BFS，用栈就是 DFS。

#### 有什么用

凡是「一片一片的东西有多少片、最大一片多大」的问题，都是它：岛屿数量、细胞计数、被墙围住的区域、这张图的连通块。

看一个最小例子（脚本 `grid_visual.py` 的第 3 部分）：

```
这张 2x2 里，两个 1 是对角关系：
      █  ·
      ·  █

四连通：两块，各 1 个格子
      1  ·
      ·  2

八连通：一块，2 个格子
      1  ·
      ·  1
```

同样两个 1，只因为「斜着算不算邻居」不同，就从两块变成一块 —— 这正是本题 $c_4 - c_8$ 的来源。

#### 四连通和八连通差在哪（邻居示意图）

中心格 ▣ 周围哪几格算邻居？◆ 是算的：

```
四连通（只认上下左右，要拐直角走两步才算）：
      ·  ◆  ·
      ◆  ▣  ◆
      ·  ◆  ·

八连通（周围 8 格全算，斜着一步就到）：
      ◆  ◆  ◆
      ◆  ▣  ◆
      ◆  ◆  ◆
```

判断式：

| 连通方式 | 相邻条件 | 格子数 |
|---|---|---|
| 四连通 | $abs(x1 - x2) + abs(y1 - y2) = 1$ | 4 |
| 八连通 | $\max(abs(x1 - x2), abs(y1 - y2)) = 1$ | 8 |

代码里用一个 bool eight 切换，遍历 $3 \times 3$ 的偏移，四连通时把不是曼哈顿距离 1 的跳掉：

```cpp
if (!eight && abs(dx) + abs(dy) != 1) continue;   // 四连通只要上下左右
```

#### 在这题里怎么用

同一个函数跑两遍，只改 eight 这个开关：

```cpp
int c4 = count_blocks(false, s4);   // 四连通
int c8 = count_blocks(true,  s8);   // 八连通
```

样例 1 跑出来的分块（脚本实跑输出）：

```
四连通分块（同一个数字 = 同一块）：
      1  ·  ·
      ·  2  ·
      ·  ·  3

八连通分块：
      1  ·  ·
      ·  1  ·
      ·  ·  1
```

#### 为什么用队列 BFS 而不是递归 DFS

递归 DFS 写起来更短，但 $200 \times 200 = 40000$ 个格子连成一片时，递归深度能到 40000 层 —— 实测会栈溢出崩掉（0xC00000FD）。这不是理论风险，是实际会炸。

用队列写的迭代版 BFS 就没有这个问题，堆内存随便用。对拍用的暴力版本故意写成递归 flood()（只在小网格上跑），跟它互相验证。

### 手算

```
100
010
001
```

三个 1 摆在主对角线上。四连通下，任意两个都不上下左右相邻（都差一步斜的）→ 3 块，每块 1 格 $\to c_4 = 3$，$s_4 = 1$。

八连通下，斜着也算相邻，三个连成一串 → 1 块，3 格 $\to c_8 = 1$，$s_8 = 3$。

答案 $3 - 1 = 2$，1，3 ✓（样例输出 2 1 3）。

样例 2：

```
1100
0110
0011
```

这条斜带在四连通下就已经连成一块（$(1, 2)$ 与 $(2, 1)$ 是上下关系、$(2, 2)$ 与 $(2, 3) \ldots$ 逐格都挨着）→ 6 格 1 块；八连通当然也是 1 块 6 格 → 0 6 6。

### 思路

网格只有 $200 \times 200 = 40000$ 个格子，两个尺度各扫一遍，把「连通块个数」和「最大面积」记下来，输出 $c_4 - c_8$、$s_4$、$s_8$ 就行。

### 参考代码

```cpp
#include <bits/stdc++.h>
using namespace std;

int n, m;
vector<string> g;

// eight = false 走四连通，true 走八连通。
// 返回连通块个数，最大面积写进 smax
int count_blocks(bool eight, int &smax) {
    vector<vector<char>> vis(n, vector<char>(m, 0));
    int cnt = 0;
    smax = 0;

    for (int i = 0; i < n; i++) {
        for (int j = 0; j < m; j++) {
            if (g[i][j] != '1' || vis[i][j]) continue;

            cnt++;                       // 发现一个新连通块
            int area = 0;
            queue<pair<int, int>> q;
            vis[i][j] = 1;
            q.push({i, j});

            while (!q.empty()) {
                auto [x, y] = q.front();
                q.pop();
                area++;

                for (int dx = -1; dx <= 1; dx++) {
                    for (int dy = -1; dy <= 1; dy++) {
                        if (dx == 0 && dy == 0) continue;              // 自己不算邻居
                        if (!eight && abs(dx) + abs(dy) != 1) continue; // 四连通只要上下左右
                        int nx = x + dx, ny = y + dy;
                        if (nx < 0 || nx >= n || ny < 0 || ny >= m) continue;
                        if (g[nx][ny] != '1' || vis[nx][ny]) continue;
                        vis[nx][ny] = 1;
                        q.push({nx, ny});
                    }
                }
            }
            smax = max(smax, area);
        }
    }
    return cnt;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n >> m;
    g.resize(n);
    for (int i = 0; i < n; i++) cin >> g[i];

    int s4, s8;
    int c4 = count_blocks(false, s4);   // 四连通
    int c8 = count_blocks(true,  s8);   // 八连通

    cout << c4 - c8 << ' ' << s4 << ' ' << s8 << '\n';
    return 0;
}
```

### 复杂度

- 时间：两遍 $O(nm \times 9)$，上限 $2 \times 40000 \times 9 \approx 72$ 万次判断，实测 0.15 秒。
- 空间：两张 visited 表，各 40000 个 `char`。

### 易错点

1. **递归 DFS 会爆栈**：40000 层递归在实测直接崩，用队列 BFS。
2. **八连通的块数一定 $\le$ 四连通**：八连通把四连通的邻居全包含了，只会合并不会拆开，所以 $c_4 - c_8 \ge 0$。如果你算出来是负数，那一定是八连通那遍漏了对角。
3. **没有 1 时要输出 0 0 0**：代码里 smax 初始化为 0，一个块都没有时自然就是 0，不用特判。
4. **面积是格子数**，不是行数列数；四连通的最大面积 $\le$ 八连通的最大面积。
5. 数组别开成 `vis[205][205]` 之外还去访问越界下标：循环里的 nx、ny 必须先判范围再访问。

## E. 小月的路线

### 题意

$n$ 个点 $m$ 条有向边（允许重边），每条边 $(u, v, d, r)$。路径从 1 到 $n$：

- 总距离 = 经过边的 $d$ 之和，总风险 = $r$ 之和；
- 小月先挑距离最小的路，再在这些路里挑风险最小的；
- 走不到输出 -1 -1；$n = 1$ 时输出 0 0。

范围：$n \le 2 \times 10^5$，$m \le 3 \times 10^5$，$d$ 和 $r \le 10^9$。

**信号**：$d$、$r$ 都能取到 $10^9$，路径最长 $2 \times 10^5$ 条边 → 总距离能到 $2 \times 10^{14}$，`int` 装不下，必须 `long long`。

### 从零讲：Dijkstra 在做什么

#### 是什么

最短路问题的经典解法。维护一个数组 dist：$dist[v]$ = 目前找到的、从起点到 $v$ 的最短距离（一开始只有 $dist[1] = 0$，其余是无穷大）。

每一轮做两件事：

1. 在所有「还没定下来」的点里，挑 dist 最小的那个 $u$，**它的距离就此定死**；
2. 用 $u$ 的所有出边去更新别人：如果 `dist[u] + w(u,v) < dist[v]`，就把 $dist[v]$ 改小。

#### 为什么这样是对的

关键在第一步：「dist 最小的那个可以定死」凭什么？

因为边权非负。假设 $u$ 是没定下来的点里 dist 最小的，而存在一条更短的到 $u$ 的路 P，那 P 一定是从某个「已定下来」的点 $x$ 出来、再走到某个没定下来的点 $y$、最后到 $u$。由于边权非负，走到 $y$ 的距离 $\le$ 走到 $u$ 的距离 $\le P$ 的长度 $< dist[u]$，也就是说 $dist[y] < dist[u]$，跟「$u$ 是最小的」矛盾。所以不存在更短的路。

一句话：**边权非负 $\implies$ 每次取最小的那个一定已经最优**。这也是为什么有负权边时 Dijkstra 会失效。

#### 双关键字怎么写

把「距离」和「风险」绑成一个二元组 (dist, risk)，比较规则：

```
(4, 6) < (5, 0)     // 先看距离
(4, 2) < (4, 6)     // 距离相同时看风险
```

松弛条件就变成：

```cpp
if (nd < dist[e.to] || (nd == dist[e.to] && nr < risk[e.to])) {
    dist[e.to] = nd;
    risk[e.to] = nr;
    pq.push({nd, e.to});
}
```

优先队列只按距离排序就够 —— 距离最小的先弹出来；距离相等、风险更小的那次更新会再入队一次，弹出来时 dist 没变、risk 已经是更小的，照常往后面传。

#### 每一步长什么样（脚本 `dijkstra_visual.py` 实跑）

```
出发前：只有 1 号结点是 (0, 0)，其余都还不知道怎么到
  结点  1  2  3
  ────  ─  ─  ─
  dist  0  ∞  ∞
  risk  0  ∞  ∞

第 1 步：定下来的是 1 号结点，目前（距离 0，风险 0）
  走 1 → 2：新方案（距离 2，风险 5）（原来到不了），比原来好，更新
  走 1 → 3：新方案（距离 5，风险 0）（原来到不了），比原来好，更新
  结点  1  2  3
  ────  ─  ─  ─
  dist  0  2  5
  risk  0  5  0

第 2 步：定下来的是 2 号结点，目前（距离 2，风险 5）
  走 2 → 3：新方案（距离 4，风险 6）（原来 5, 0），比原来好，更新
  结点  1  2  3
  ────  ─  ─  ─
  dist  0  2  4
  risk  0  5  6

第 3 步：定下来的是 3 号结点，目前（距离 4，风险 6）
  它没有出边，跳过。

终点 3 号：距离 4，风险 6
```

第 2 步就是本题的考点：新方案风险 6 比原来的 0 大，但距离 4 比 5 小，照换不误。

#### 为什么不能用别的做法

- **Floyd / Bellman-Ford**：$O(n^3)$ 或 $O(nm)$，在这题规模下必超时。Bellman-Ford 只在对拍里当暴力用（不同实现范式，见文末实测记录）。
- **先跑一遍最短距离、再在最短距离子图上跑最短风险**也行，但要建子图、跑两遍，代码更长；字典序松弛一遍就完事。
- **SPFA**：最坏情况会退化，不用。

### 手算

边：$1 \to 2 (2, 5)$、$2 \to 3 (2, 1)$、$1 \to 3 (5, 0)$。

两条路：

| 路径 | 总距离 | 总风险 |
|---|---|---|
| 1 → 3 直达 | 5 | 0 |
| 1 → 2 → 3 绕路 | 4 | 6 |

先比距离：4 < 5 → 选绕路，输出 4 6。风险 0 那条虽然风险最低，但距离更远，小月根本不看它 —— **顺序很重要**。

### 思路

边上有两个非负权：距离 $d$ 和风险 $r$。要的是「距离最小；距离最小时风险最小」的那条路 —— 也就是按二元组 (距离, 风险) 的字典序取最小。

因为 $d$ 和 $r$ 都非负，Dijkstra 照样成立，只是松弛的时候多一条「距离相等时比风险」。

### 参考代码

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Edge {
    int to;
    long long d, r;      // 距离、风险，都要 long long：路径最长 2e5 条边 × 1e9
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    vector<vector<Edge>> adj(n + 1);
    for (int i = 0; i < m; i++) {
        int u, v;
        long long d, r;
        cin >> u >> v >> d >> r;
        adj[u].push_back({v, d, r});
    }

    if (n == 1) {                    // 起点就是终点
        cout << "0 0\n";
        return 0;
    }

    const long long INF = (1LL << 62);
    vector<long long> dist(n + 1, INF), risk(n + 1, INF);

    // 按距离排序的小根堆；距离相同时靠下面的松弛把风险压到最小
    priority_queue<pair<long long, int>,
                   vector<pair<long long, int>>,
                   greater<pair<long long, int>>> pq;

    dist[1] = 0;
    risk[1] = 0;
    pq.push({0, 1});

    while (!pq.empty()) {
        auto [du, u] = pq.top();
        pq.pop();
        if (du != dist[u]) continue;          // 这是过时的一份，丢掉

        for (const Edge &e : adj[u]) {
            long long nd = dist[u] + e.d;
            long long nr = risk[u] + e.r;
            // 距离更小 → 换；距离一样但风险更小 → 也换
            if (nd < dist[e.to] || (nd == dist[e.to] && nr < risk[e.to])) {
                dist[e.to] = nd;
                risk[e.to] = nr;
                pq.push({nd, e.to});
            }
        }
    }

    if (dist[n] == INF) cout << "-1 -1\n";
    else cout << dist[n] << ' ' << risk[n] << '\n';
    return 0;
}
```

### 复杂度

- 时间：$O((n + m) \log n)$，$m = 3 \times 10^5$ 时约 $3 \times 10^5 \times 18$ 次堆操作，实测 0.17 ~ 0.23 秒。
- 空间：邻接表 $O(n + m)$，两个 long long 数组 $O(n)$。

### 易错点

1. **`int` 装不下距离**：$d \le 10^9 \times 2 \times 10^5$ 条边 = $2 \times 10^{14}$，必须 `long long`。这是本题最常见的 WA 原因。
2. **$n = 1$ 特判**：题目明确要求输出 0 0，不特判的话 $dist[1]$ 已经是 0，其实也能过，但写清楚更稳。
3. **`if (du != dist[u]) continue` 不能写成 `du > dist[u]` 之外的别的判断**：这一句只用来丢掉过时的堆元素；风险变小那次更新入队时 `du == dist[u]`，不会被它误杀。
4. **重边不用特殊处理**：两条 1 → 2 的边各自松弛，风险小的那条自然留下。
5. **走不到要输出 -1 -1**，不是 0 0，也不是只输出一个 -1。

## F. 小月的筹码

### 题意

- $n \le 40$，$0 \le k \le n$，$0 \le x < 2^{30}$；
- 每个数 $0 \le a_i < 2^{30}$；
- 两个方案不同 $\iff$ 存在某个筹码一个选了另一个没选（**只看下标的集合，不看数值** —— 两个数值一样的筹码算两种不同的选法）；
- 方案数对 $10^9+7$ 取模。

**信号**：$n = 40$ 是个很特殊的数 —— 比 30 大（不能状压 DP），比 60 小（$2^{n/2}$ 还能枚举）。看到 40 就该想到折半。

### 从零讲：折半枚举（meet-in-the-middle）

#### 是什么

把要枚举的对象**砍成两半**，各自独立枚举，再把两边的结果「配」起来。

名字的意思是：与其从起点一路走到终点（$2^n$ 条路），不如从起点和终点各走一半，在中间碰头（$2^{n/2} + 2^{n/2}$ 条半程路）。

#### 有什么用：把 $2^n$ 变成 $2^{n/2}$

| $n$ | 子集数 $2^n$ | 能不能直接枚举 |
|---|---|---|
| 20 | 1048576 | 可以 |
| 26 | 67108864 | 不行，会超时 |
| 30 | 1073741824 | 不行，会超时 |
| 40 | 1099511627776 | 不行，会超时 |

$n = 40$ 直接枚举是 1.1 万亿，一台机器跑不完；拆成两半后每半只有约 105 万 —— 这就是省下来的地方：$2^{40} \to 2 \times 2^{20}$。

#### 在这题里怎么用：配对的钥匙是异或的消去律

把 40 个筹码分成左半 20 个、右半 20 个。任何一个「选法」都由「左半选哪些」+「右半选哪些」拼成。

设左半选出的异或值是 $v_1$、选了 $c_1$ 个；右半是 $v_2$、$c_2$ 个。要求：

```
c1 + c2 = k      （一共选 k 个）
v1 xor v2 = x    （异或和等于 x）
```

第二式两边同时异或 $v_1$，就得到：**右半该凑出的值是 $v_1 xor x$**。

于是对左半的每一种选法，右半该长什么样是**可以直接算出来的**，不用去试。剩下的问题变成：右半里有多少种选法「选了 $k - c_1$ 个、异或值 = $v_1 xor x$」—— 一个查表问题。

脚本 `mitm_visual.py` 跑样例 1 的配对过程（$n = 4$，左半 $a_1$、$a_2$，右半 $a_3$、$a_4$）：

```
  左半方案  已选  左异或  右还差  右要凑出  配上几个
  ────────  ────  ──────  ──────  ────────  ────────
  空集      0     0       2       3         1
  {a1}      1     1       1       2         0
  {a2}      1     2       1       1         0
  {a1,a2}   2     3       0       0         1
```

最后一行：左半全选（异或 3），右半要选 0 个且异或 0 → 空集，配上 1 种。第一行：左半不选，右半要选 2 个凑出 $3 \to \{a_3, a_4\}$，配上 1 种。合计 2 ✓。

#### 为什么不用更眼熟的做法

- **线性基**：能回答「能不能凑出 $x$」「凑出 $x$ 的方案总数（不限制个数）」，但本题**卡死了必须选 $k$ 个**，线性基的自由度是 $2^{n-r}$ 个解均匀分布，不区分选了几个 —— 它数不出「恰好 $k$ 个」。
- **DP over 位**（逐位处理）：$n$ 和 $k$ 都要进状态，$40 \times 30$ 位的状态不算大，但转移要按「这一位上有多少个数是 1」做组合计数，写起来绕且容易错，本题用折半更直接。
- **暴力枚举 $2^n$ 选法**：$n \le 20$ 时完全可行（对拍就用的它），$n = 40$ 直接超时。

#### 两个细节

1. **「选了几个」必须跟着存**：只存异或值是不够的，因为 $k$ 是硬约束。所以每张表的关键字是二元组 (个数, 异或值)。
2. **相同关键字要合并计数**：不同的选法可能有相同的 (个数, 异或值)（比如右半 {a4} 和空集异或都是 0，但个数不同；{a3} 和 {a3,a4} 异或都是 3，个数不同）。合并之后配对时是**乘法**：左半有 $p$ 种、右半有 $q$ 种，配出 $p \times q$ 种方案。

### 手算

4 2 3，四个筹码 1 2 3 0，选 2 个凑异或和 3。

枚举所有选 2 个的组合：

| 选哪两个 | 异或和 | 等于 3 吗 |
|---|---|---|
| 1, 2 | 1 xor 2 = 3 | ✓ |
| 1, 3 | 1 xor 3 = 2 | ✗ |
| 1, 0 | 1 xor 0 = 1 | ✗ |
| 2, 3 | 2 xor 3 = 1 | ✗ |
| 2, 0 | 2 xor 0 = 2 | ✗ |
| 3, 0 | 3 xor 0 = 3 | ✓ |

2 种 ✓（样例输出 2）。注意 {1, 2} 和 {3, 0} 是两个不同方案，因为选的下标不同。

### 思路

从 $n$ 个筹码里选恰好 $k$ 个，让异或和等于 $x$，问方案数（对 $10^9+7$ 取模）。

$n = 40$ 时 $2^{40} \approx 1.1 \times 10^{12}$ 种子集，枚举不完。折成两半各 20 个：每半 $2^{20} \approx 105$ 万，两边各枚举一遍，再按「选了几个 + 异或值」配对，总复杂度 $O(2^{n/2} \log 2^{n/2})$。

### 参考代码

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MOD = 1000000007;

// 枚举半边的所有子集，压成 (选了几个, 异或值) -> 方案数，按 key 排序好
vector<pair<unsigned long long, int>> build(const vector<int> &a, int st, int len) {
    vector<pair<int, int>> v;            // (选了几个, 异或值)，每个子集一项
    v.reserve(1u << len);
    v.push_back({0, 0});                 // 空集
    for (int i = 0; i < len; i++) {
        int sz = (int)v.size();
        for (int t = 0; t < sz; t++)     // 已有的每个子集都多一个"选 a[st+i]"的版本
            v.push_back({v[t].first + 1, v[t].second ^ a[st + i]});
    }

    vector<pair<unsigned long long, int>> c;
    c.reserve(v.size());
    for (auto &p : v) {
        unsigned long long key = ((unsigned long long)p.first << 32) | (unsigned int)p.second;
        c.push_back({key, 1});
    }
    sort(c.begin(), c.end());

    vector<pair<unsigned long long, int>> comp;   // 合并相同的 (个数, 异或值)
    for (auto &p : c) {
        if (!comp.empty() && comp.back().first == p.first)
            comp.back().second = (comp.back().second + p.second) % MOD;
        else
            comp.push_back(p);
    }
    return comp;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k, x;
    cin >> n >> k >> x;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    int L = n / 2, R = n - L;            // 折半：前 L 个、后 R 个
    auto left  = build(a, 0, L);
    auto right = build(a, L, R);

    long long ans = 0;
    for (auto &p : left) {
        int c1 = (int)(p.first >> 32);                 // 左半选了几个
        int v1 = (int)(p.first & 0xffffffffu);         // 左半的异或值
        int c2 = k - c1;                               // 右半要选几个
        if (c2 < 0 || c2 > R) continue;
        unsigned long long key =
            ((unsigned long long)c2 << 32) | (unsigned int)(v1 ^ x);   // 右半该长什么样
        auto it = lower_bound(right.begin(), right.end(),
                              make_pair(key, 0));
        if (it != right.end() && it->first == key)
            ans = (ans + (long long)p.second * it->second) % MOD;
    }

    cout << ans << '\n';
    return 0;
}
```

### 复杂度

- 时间：枚举两侧各 $2^{20} \approx 105$ 万项，排序 $O(2^{20} \times 20)$，再对左半的每一项二分右半（20 次比较）→ 约 $2 \times 10^7$ 次基本操作，实测 0.3 秒上下。
- 空间：两侧各约 105 万个 (key, 计数) 对，按 16 字节算约 32 MB。

### 易错点

1. **$k = 0$ 时答案是 1 还是 0**：空集异或和是 0，所以 $x = 0$ 时答案是 1（就是「什么都不选」这一种），$x \ne 0$ 时是 0。
2. **数值相同的筹码算不同方案**：$\{a_1\}$ 和 $\{a_2\}$ 在 $a_1 = a_2$ 时是两个不同选法 —— 枚举的是下标集合，天然满足，别去重。
3. **计数要取模**：乘法那一步 `p.second * it->second` 最大约 $10^{18}$ 量级（$(10^9)^2 = 10^{18}$），`long long` 能装（上限 $9.2 \times 10^{18}$），但对完再乘下一轮会爆，所以每步都取模。
4. **异或值范围**：$a_i < 2^{30}$、$x < 2^{30}$，异或结果 $< 2^{30}$，塞进 key 的低 32 位没问题；个数 $\le 40$ 放在高 32 位，两者不会串。
5. **c2 越界要跳过**：$k - c_1$ 可能为负或大于 R，不判的话会去查一个不存在的 key（查不到就是 0，不会崩，但逻辑上要写清楚）。
