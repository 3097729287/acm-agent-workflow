# 牛客周赛 Round 159 E - 小月的前缀集合

- **难度**：CF 1500
- **原题链接**：https://ac.nowcoder.com/acm/contest/139660/E
- **题解位置**：`题解\牛客周赛\Round159\Round159题解.md`（整场题解，含完整推导）
- **归档文件夹**：`算法\字典树\`
- **数据结构与算法**：前缀覆盖计数（题解正文主实现是编号数组，字典树是等价写法）
- **具体知识点**：可重集合动态增删后统计不同非空前缀个数；每个前缀记计数而不是 `bool`（同一前缀被多个串共用，删除时会误伤）

## 题意（精简）

维护一个 01 串的**可重**集合，初始为空。q 次操作：+ s 插入一个 s；- s 删除**一个** s（保证此刻集合里至少有一个 s）。
每次操作**之后**，输出集合中所有串的**不同非空前缀**一共有多少个。
"可重"与"删除一个"这两处措辞是信号：删除不是把这个串的所有副本删光。

**数据范围**：q ≤ 2×10^5；|s| ≤ 20。

## 关键点（为什么用这个算法）

1. 信号：前缀本来就是字典树上的节点，"不同非空前缀个数"就是 cnt ≥ 1 的节点个数；一次增删只影响 s 自己的 |s| ≤ 20 个前缀。
2. 朴素做法每次操作后重扫集合、把前缀塞进 set<string>：单次要处理总长 20q 的字符串、还要做 string 比较，q = 2×10^5 时是上亿次带 log 的字符串操作，太慢，而且每次从头算，白扔上一次的结果。
3. 关键洞察：一个前缀 P 在答案里，当且仅当集合中**至少有一个串以 P 为前缀**；所以不要维护"集合里有哪些串"，而是维护"每个前缀被多少个串覆盖"（`occ[P]`）。
4. 插入时这 ≤ 20 个前缀各 +1，某个前缀第一次从 0 变成 1 时答案 +1；删除时各 -1，从 1 变成 0 时答案 -1。字典树版完全同构，只是"前缀的编号"改由节点动态分配。

## 复杂度

- 时间：每次操作 O(|s|) ≤ 20，总 O(20q)；q = 2×10^5 时约 4×10^6 次操作（编号数组版实测 0.048 s，字典树版 0.054 s）
- 空间：编号数组版 O(2^21)（约 8 MB）；字典树版 O(20q)，节点上限 4×10^6

## 踩过的坑

1. **用 `bool` 记前缀而不是计数** → 同一前缀被多个串共用，删除时误伤（样例 1 第 4 步删 01 后前缀 `"0"` 依然存在，`bool` 会把它一起抹掉，答案算错）。这是本题最经典的错误。
2. 删除是删**一个**（可重集合），不是把这个串删光；题目保证删除时集合里至少有一个，所以不用判"不存在"。
3. 给前缀编码时忘了"起手 1" → `"0"` 与 `"00"` 撞码、答案偏小；数组要按最长 20 开 2^21，开成 2^20 会越界（编号最大到 2^21 - 1）。
4. 字典树版的**根节点不算前缀**（题目要求"非空"）；另外**每次操作后都要输出**，包括删除操作之后，别只在插入时输出。
