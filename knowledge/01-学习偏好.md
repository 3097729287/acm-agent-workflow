# 学习偏好（写作与交付的口径）

> 类型：读者画像与风格约定 ｜ 所有题解 / 教程 / 报告的默认口径

## 读者是谁

- 会基础语法、正在刷题提升的竞赛学习者。
- 本工作流默认服务「当下的自己 + 三个月后的自己」：题解不是即时教学材料，
  而是**存档 + 复习材料 + 检索工具**——写完当下可能不读，复习时会按台账与索引回来查。
  「从零讲」「指针」「概念台账」三样都服务于这件事：忘了的能快速找回、讲过的别重复讲。

## 讲解方式（必须遵守）

- 从零开始：先讲清题目问什么 → 概念 / 状态 / 转移的**直觉解释** → 最后才是代码。
- 抽象概念配**能手算验证的小例子**（如 n=3 三堆石子演示合并顺序影响总分）。
- 代码逐行中文注释、标识符英文；指出错误要**逐条列出**并解释「为什么错」，先肯定对的部分。
- 用户贴自己的代码时：先编译跑样例 + 对拍，再逐行读。

## C++ 口径

- **默认全用 `cin` / `cout`**，迫不得已才用 `scanf` / `printf`：
  文件开头 `ios::sync_with_stdio(false); cin.tie(nullptr);`。统一一个流体系，
  可以绕开一种本地特有的坑（stdio 与 iostream 混用，在部分 MinGW / UCRT64 工具链上会**静默读空**，
  详见《环境准备》）。注意：这类坑**只坑本地验证**，评测机不复现——本地跑不出结果时先怀疑环境，
  别去改一个正确的算法。
- 交付的 C++ **必须本地验证**：编译 → 跑样例 → 随机对拍 → **如实说明验证到了哪一步**（见《验证协议》《工作流》）。

## 交付与落盘

- 题解进 `<数据根>\题解\<比赛名>\RoundNNN\`，算法归档进 `<数据根>\算法\<算法名>\`（见《工作流》《归档》）。
- 桌面副本是**可选功能**：`config.json` 里配了 `desktop_copy_dir` 才有这一步，默认关。
- 长文要有**目录**、手算小例子（拿样例逐对枚举验证）、**易错点清单**、对拍 / 练习建议。
