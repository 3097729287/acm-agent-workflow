# 环境准备（工具链与常见坑）

> 类型：参考 ｜ 本工作流需要什么环境、怎么装、有哪些坑。
> 工具脚本都在仓库 `tools/` 下；数据区与配置见《工作流》《工具链》。

## 最低要求

| 组件 | 必需性 | 用途 | 说明 |
|---|---|---|---|
| Python 3.10+ | **必需** | 跑 `tools/` 下全部脚本 | 只用标准库，不需要 pip 装依赖 |
| Node.js | 可选 | KaTeX 公式校验（`check_solution.py` 第 17 项） | 还要在 `tools/` 下跑 `npm install katex`；缺任一样，第 17 项跳过并报 NA，不影响其余 16 项 |
| g++ | 可选（强烈建议） | 本地编译验证 C++ | 需要 C++17，编译命令按 `g++ -O2 -std=c++17`（见《验证协议》） |
| gdb | 可选 | 断点调试 | **必须与编译器同批**（见坑 4） |

Windows 上装 Python 时勾选「Add to PATH」；装 MSYS2 按官方安装器默认路径（如 `C:\msys64`），
把 `ucrt64\bin` 加进 PATH —— 除了 `g++.exe` / `gdb.exe`，跑生成的 exe 也要靠它找
`libstdc++-6.dll` 等运行库。Linux / macOS 用系统包管理器装 g++ 即可。

## 配置与寻址

工具靠 `config.json` 定位数据：

- 查找顺序：`AGENT_CP_CONFIG` 环境变量 → 仓库根 `config.json` → 内置默认值。
- 字段：`data_root`（数据根）/ `backup_root`（备份仓）/ `desktop_copy_dir`（可选，
  null = 关）。从 `config.example.json` 复制一份改。
- 相对路径一律相对 `config.json` 所在目录解析（没有 config 时相对仓库根）。

数据区之外，自己的脚本（如字符画脚本）要导入 `tools/` 里的模块时，用**工具寻址头**：
优先读 `AGENT_CP_TOOLS` 环境变量，否则向上查找含 `tools/toolutil.py` 的目录
（完整片段见《配图》）。

## 跑起来

    python tools/check_solution.py --help     # 每个脚本都能 --help
    python tools/fetch_problem.py <cid 或比赛URL>

在仓库内执行即可，产物写到 `data_root` 下。工具之间不互相启动，各自独立跑。

## 坑（均已实测；做法写祈使句）

### 1. MSYS2 别做「部分升级」

长期不升级时，只 `pacman -S` 单个包 = 部分升级：新包链接的新版 libstdc++ 符号
老 DLL 里没有，程序启动直接 `0xC0000139 STATUS_ENTRYPOINT_NOT_FOUND`
（PowerShell 里表现为**退出码 -1073741511 + 零输出**，很像"程序坏了"）。
修法只有全量 `pacman -Syu`（可能跑两遍：第一遍升 msys2-runtime / pacman 后，
pacman 会要求关闭所有 MSYS 进程而退出 1，属正常）。

从 PowerShell 调 pacman 升级时**先加 MSYS 的 PATH**：
`$env:PATH="<MSYS2 安装目录>\usr\bin;$env:PATH"`，否则 post-install 脚本找不到
mkdir / cp / grep，报 `line 14: mkdir: command not found`，证书等收尾步骤静默失败。

### 2. stdio 与 iostream 不要混用（这个坑只坑本地验证）

先用 `scanf` / `getchar` / `fgets` 读过之后，**任何** `cin >>`（int、string、char[]、
`cin.get()` 都一样）都立刻失败 —— failbit 置位、变量为空；**反过来也一样**。
两边各读各的缓冲，谁也看不见谁。某些 MinGW / UCRT64 工具链上会**静默读空**：
不报错、不崩，程序拿着空变量继续跑。

**探针**（`scanf("%d", &n)` 之后立刻打印）：

    cin.good=1  bad=0  eof=0  fail=0     ← 流状态是好的，不报任何错
    cin.rdbuf()->sgetc() = -1            ← 但缓冲区已经是 EOF
    fgetc(stdin) = 10                    ← 同一时刻 stdio 还能读到字节

注意此时 `cin.rdbuf()` 的类型确实是 `__gnu_cxx::stdio_sync_filebuf`、
`cin.sync_with_stdio()` 也返回 true，但**行为就是不同步**。
**为什么危险**：静默读到空；若代码随后按下标访问那个空 `string`（`s[j]`），
就是越界读未初始化内存 → **同一输入每次运行答案都不同**（实测连跑 5 次得
`24 24 24 23 24`），表现得像"算法算错"，实际是输入没进来。

**做法**：

1. **这类坑评测机不复现** —— 曾有一份混用代码本地官方样例输出 12（应为 0），
   同一份提交到评测机却 AC。本地跑不出结果时**先怀疑环境，别去改一个正确的算法**；
2. 要让本地验证也可信，**把这一处的 `scanf` 统一改成 `cin`** ——
   **默认全用 `cin` / `cout`，迫不得已才用 `scanf` / `printf`**；
3. 改完**重跑官方样例**再看结论，别只看编译通过。

### 3. 编码：终端默认不是 UTF-8

直接 print 中文会乱码。用 `PYTHONIOENCODING=utf-8` 运行，或把结果写进文件再读。
源码与交付文件一律 UTF-8；`.cmd` / `.bat` 一律纯 ASCII + CRLF（别在批处理里写中文）。

### 4. gdb 必须与编译器同批

旧版 gdb（如某 IDE 自带的 7.8.1，配套 gcc 4.9）读不了 GCC 15 / 16 生成的 DWARF5，
报 `Dwarf Error: wrong version in compilation unit header (is 5, should be 2, 3, or 4)`，
且断点绑不上符号表。用与编译器同批发布的 gdb。

### 5. 别用 PowerShell 管道给原生 exe 喂 stdin

`"3" | .\a.exe` 传进去的输入是坏的（`scanf("%lld")` 读出 `990612814520` 这种垃圾），
而"先读 n 再读 n 个数"的程序会**读不到输入直接挂死**，空等满超时。
改用 `cmd /c "a.exe < in.txt"`，或先写 `.in` 文件再重定向 —— 同一份输入这样喂就正常。

**附带**：写 PowerShell 脚本按 **Windows PowerShell 5.1** 语法，别用 7+ 才有的参数
（如 `Get-Content -AsByteStream`）。

### 6. 内联脚本别过转义层

把含**反斜杠**的内容塞进 `python - << 'EOF'` / here-string 内联脚本写文件时，
反斜杠每过一层就被解释一次（JSON 参数 → shell heredoc → Python 字面量），
想要的字面 `\n` 会变成真换行，把文件写坏。反引号同族：PowerShell here-string、
bash 双引号都会把反引号当转义 / 命令替换吃掉，探测串变了形、报"命中 0 处"（假阴性）。

**做法**：C 源码、正则、Windows 路径这类内容**一律用编辑工具直接写文件**；
凡含**反引号 / 反斜杠 / `$`** 的 Python（尤其探测串、正则、路径），
**一律先写成 `.py` 文件再跑**，别塞进 here-string。路径用正斜杠，
或反斜杠用 `chr(92)` 拼。`python -c` 里直接写 Windows 路径还会报
`SyntaxWarning: invalid escape sequence`，用 r-string 或正斜杠避开。

**同族坑**：内联脚本经工具调用的 JSON 解码时，脚本里写的 `\t`、`\a` 会先变成
真控制字符（TAB / BEL），写进文件后肉眼看不见 —— 路径用正斜杠最省事。

### 7. 别用 `grep -c $'\r'` 探测行尾

Git Bash / MSYS2 下它把**每一行**都算成"含 CR"，所有文件都报"全是 CRLF"，
会把纯 LF 误判成 CRLF。**做法**：① `file <路径>` 看有没有
`with CRLF line terminators`；② 精确计数用 Python：

    CRLF = (chr(13) + chr(10)).encode()
    d.count(CRLF)                                # CRLF 行数
    d.count(chr(10).encode()) - d.count(CRLF)    # 裸 LF 行数

**两个都非零 = 混了行尾**。真正要防的是"混"，比"是哪种行尾"更容易出错。

### 8. PowerShell 的 `>` 写出的是 UTF-16LE

`>` / `Tee-Object` 落盘带 BOM 的 UTF-16LE，拿 Python 按 `encoding="utf-8"` 读回来
直接 `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 0`。
**做法**：要抓一个脚本的 stdout 落盘，用 Python 自己抓 ——
`subprocess.run([sys.executable, 脚本], capture_output=True)`，把 `r.stdout`
`open(路径, "wb").write(...)`；或读完显式 `encoding="utf-16"`。
**别用 `python x.py > out.txt`**：多一层编码转换，下游全得跟着猜。

### 9. 多个 Python 并存时，解释器要写死

不同来源的 Python（官网安装版 / MSYS2 自带）包集与路径语义都不一样：
MSYS2 的 python 常常没有第三方包，`import numpy` 直接 `ModuleNotFoundError`。
**做法**：要用第三方包的脚本，用能跑通的那个解释器（命令里写全路径）；
装包时国内网络可走镜像：`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple <包>`。

**附带**：MSYS2 版 python 是 POSIX 路径语义，`os.path.abspath` 返回正斜杠路径 ——
做"路径 → 扁平镜像名"这类字符串变换时，要把 `/` 和 `\` 一起替换，
只换 `\` 会拼出带 `/` 的嵌套目录。
