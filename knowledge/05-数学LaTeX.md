# 数学 LaTeX（交付 md 的数学书写口径）

> 类型：格式规范 ｜ 触发：任何要落盘给别人看的 `.md`（题解、差异说明、教程、报告）

**前置条件**：查看器要开启内联公式（Typora：设置里勾「内联公式」），`$...$` 才能正常渲染。
查看器设置一改，本口径就跟着改——出问题先确认查看器现在开了什么（见文末「更根本的一条」）。

## 结论（照做）

**数学写行内公式 `$...$`**：

| 写 | 例 |
|---|---|
| 变量、数值 | `$x$`、`$n = 2 \times 10^5$` |
| 比较 | `$1 \le x \le 10^{18}$` |
| 幂 / 下标 | `$10^{18}$`、`$a_i$`、`$w_{l-1}$` |
| 复杂度 | `$O(n \log n)$`、`$O(\sqrt{n})$` |
| 数学函数 | `$\log_2 x$`、`$\gcd(a, b)$`、`$\max(a, b)$` |
| 希腊字母 / 符号 | `$\theta$`、`$\sum_{d \mid v} d^d$`、`$\pmod{10^9+7}$` |

- **块公式 `$$...$$` 也可以用**（渲染成居中公式；`\begin{cases}...\end{cases}` 这类多行结构就写在块里）。
- **下标写 `$a_i$`**，不写 HTML `a<sub>i</sub>`。**例外**：**含中文的下标**（如 `Σ<sub>儿子 v</sub>`）保留 HTML 原样——转换器故意跳过它们（中文会截断数学片段，硬转会断成半截标签）。
- **公式不套反引号灰底、只有真代码才加**：变量 / 公式 / 复杂度 / 坐标 / 区间 / 集合裸写，C++ 关键字与类型、函数名、数组访问、文件路径与命令、字符串字面量才用反引号——这才是要的「Word 排版」。判定细则见下面「去灰底」一节。
- 中文行文里的**叙述箭头**（「点数相同 → 比花色」）保持 Unicode 原样，不算数学、不必转。

## 转换器：`tools/unify_latex.py`

`python tools/unify_latex.py <文件或目录> [dry|apply]`
（dry 打 diff + 统计；apply 落盘，**自动备份**进备份仓（`config.json` 的 `backup_root`，按来源目录镜像子目录），`newline="\n"` 保证纯 LF）。

- **幂等**：对已转好的文件再跑 = 0 改动（保护段含已有的 `$...$`），可反复跑。
- **前置步骤：先跑 `unpair_ticks.py` 去灰底**——unify 保护行内代码，`` `O(n)` `` 里的公式它不碰，灰底不去掉就转不到。
- **块公式保护**：跨行 `$$...$$` 用状态机整块跳过；同行 `$$...$$` 用 PROT 段保护（内容已是公式，不再转）。
- 中文截断 / 括号不平衡的片段**主动放弃**（保留 Unicode）——保守行为，不算 bug；交付时肉眼过一遍即可。
- 新题解直接用 LaTeX 写，根本不需要转换器。

## 转换器踩过的坑（都靠 dry diff + KaTeX 全量渲染抓出来，无一是肉眼看出的）

| 症状 | 根因 / 防范 |
|---|---|
| `\max` 被切成 `\ma x`（628 个公式损坏） | 想用正则「字母命令后补空格」会**回溯分词**；正解 = 映射端保证每个命令自带尾随空格 |
| `\ldotsn` 粘连（KaTeX 报未定义命令） | 同上：`…` / `...` 映射成 `" \\ldots "` 带尾空格 |
| 映射后 `\ldots ,` 多出空格 | 渲染后统一清 `[ \t]+([,;])` |
| md 列表编号被吸进公式（`5. n < 10` → `$5. n < 10$`，列表塌掉） | 片段左端只剩块标记（`5.` / `>` / `#`）时反复切出去 |
| 代码运算符被数学化（`g++`、`i--`） | 片段含 `++`/`--` → 放弃；**检查放在两端修剪之前**（否则尾部 `++` 先被当连接符剪掉、查不到） |
| `__builtin_clzll` 被转成下标 | 片段含 `__` → 放弃 |
| 实测记录行被公式化（`$A 0.005 s$`、`$Yes + n-1$`） | 加两条放弃规则：结尾像「数字 + 单位」（`[0-9] [a-zA-Z]{1,2}$`）、大写词打头接运算符 |
| 整个文件 diff 全红（假差异） | Python 写文件默认 CRLF → 必须 `newline="\n"`（核行尾按二进制数 `\r\n`） |

退出码 0 = 全过。**裸的 Unicode 数学符号（≤ ≥ ≈ ×）不在检查范围**——要么是叙述连接符、要么是转换器有意放弃的片段，保留 Unicode 在查看器里本来就能显示；「该转没转」交给第 2 项（跑转换器本尊），比列符号表准。

**KaTeX 全量渲染**（语法验证的最强手段）——**已固化成 checker 第 17 项，交付时自动跑**；
手工跑仍是 `python tools/extract_math.py <md>...` 抽全部公式（含跨行 `$$` 块）到 `math.json` →
`node katex_check.js math.json`（依赖：`tools/` 下已 `npm install katex`；
`katex.renderToString(tex, {throwOnError: true, strict: false})`）。
公式**内部**的命令拼错 / 花括号不配只有它能抓。实测抓出 3 个人工读 diff 漏掉的语法错误。

## 校验清单（做 Unicode→LaTeX 批量转换时照抄）

1. 代码块**数量不变且逐字未变**（做批量转换那次：8 份 134 块逐一对照）
2. `$` 全部配对（checker 第 1 项）
3. **KaTeX 全量渲染 0 失败**
4. **中文串 0 丢失**（转前转后逐串比对）
5. 行数不变、行尾纯 LF、无 BOM
6. **幂等**：转后再 dry 跑一遍 = 0 改动
7. diff 抽查若干行（尤其表格行、列表行、实测记录行）

## 表格单元格里别摊长 URL（会挤成一条竖线）

修索引总表时：最后一列是裸 URL，查看器里那一列只剩两三个汉字宽，
`https://ac.nowcoder.com/acm/contest/134529/C` 渲染成**一个字一行**的竖条。

- **改法**：写成 Markdown 链接 `[原题](完整网址)` —— 渲染后只占两个汉字宽，链接照样能点、能右键复制网址。
- **成因（推断，未实测）**：URL 是不可断的长串，列的自然宽度按它算 → 整表超宽 → 挤给最后一列的剩余宽度近乎为零。
- **通用判据**：单元格里出现「无空格的超长串」就先想这条。长文件名能靠 `-` / `_` 断行、URL 的 `//` `.` 也勉强能断，但都断在难读的位置，不如收进链接。
- **`check_solution.py` 查不到这条**：第 7b 只查裸 URL 的存在，宽度问题只能靠「表格够不够窄」的判断，外加开一次查看器亲眼确认。

## 行首缩进的公式 = 缩进代码块：`$` 原样露出（checker 第 16 项）

**症状**（一次实测：全文件 9 处）：查看器里整行显示成
原样的 `$\sum_v 2 \times \lfloor d_v / 2 \rfloor$`、`$need[i] = 4 - y[i]$`——
`$` 和命令都不渲染，看着像代码；同一份里其余 300 多处公式正常。

**根因**：这些行**行首有 $\ge 4$ 空格缩进、且前面是空行**（独立成段）→ Markdown 判成
**缩进代码块**（性质等同围栏代码块），代码块里的 `$...$` 不做行内解析、原样显示。
历史成因：早期想让公式「独立成行」就加了缩进，Unicode 时代在等宽块里还像样，
LaTeX 化后 `$` 全裸奔。

**判据**（别看漏也别误伤）：
- 算代码块：**前行是空行**（或文首 / 刚出围栏）+ 行首 $\ge 4$ 空格。
- 不算：缩进行**紧跟着普通文字**（段落续行，缩进被忽略）；**列表项内部**的续行也对齐缩进，
  照常渲染（有一处正是这种，别去动）。

**修法**（实修口径）：
- 纯公式行 → 写 `$$...$$` 独立块公式（居中渲染）
- 带中文的公式行 → 去掉行首缩进、并回普通段落（行内 `$...$`）
- 句子中间 / 列表项里的公式 → 并回句子本身

**闸门**：`check_solution.py` **第 16 项**。自证口径：对修复前的备份
跑一遍应把问题块全报出来（那次报了 7 块），修复后跑应通过——**新加的检查项
必须先拿旧文件自证能报，再信它在别处的「通过」**。

## 去灰底：什么算「真代码」

**工具**：`tools/unpair_ticks.py`（`python unpair_ticks.py <文件.md> [dry]`，幂等，自带 9 项校验，
备份走备份仓（`config.json` 的 `backup_root`））。**在 LaTeX 化流程里是前置步骤**：先去掉数学的灰底，再让 `unify_latex.py` 转。
已经手写了 LaTeX 的混合稿用 `tools/unpair_ticks_relaxed.py`（复用同一套判定，只跳过「正文没有 `$`」那条校验）。

| 保留灰底（真代码） | 去掉灰底（数学，之后写 `$...$`） |
|---|---|
| C++/Python 关键字与类型：`int`、`long long`、`string`、`bool`、`ll` | 题面给的量：`n`、`m`、`k`、`t`、`a`、`b`、`x`、`i`、`j` |
| 标准库与代码里的函数名：`scanf`、`sort`、`next_permutation`、`upper_bound`、`gcd`、`cross`、`part1()` | 复杂度：`O(n)`、`O(nlog n)`、`O(4^n·n²)` |
| 代码里的标识符与数组访问：`ch[v][x]`、`cnt[id[v]]`、`best`、`mn`、`mx`、`d1`、`ptr`、`vis`、`allZero` | 数值与算式：`2^k`、`10^12`、`5×10^5`、`n(n+1)/2` |
| 代码语句与表达式：`ch[v][x] = ++tot;`、`if (best) --cnt[best];`、`(d1 > 0 && d2 < 0) \|\| (...)` | 坐标与集合：`(2,0)`、`A = (4,0)`、`{2,4}`、`a={3,8,5,2,4}` |
| 路径/文件名/命令/链接：`run.cmd`、`RoundNNN\B-G\E\cross_visual.py`、`cd C:\...`、`https://...` | 区间：`[l,r]`、`[mn, mx]`、`[0, P]`（**注意：`w[0..n]`、`ch[v][x]` 这种带数组名的要保留**） |
| 字符串/字符字面量：`"abc"`、`x = "1A0"`、`'0'`、`'\n'` | 箭头与图例：`O→A`、`(0,0) → (4,0)`、`+`、`-`、`/`、`━` |

**规则在脚本里的顺序**（自上而下，先命中先算）：
1. 落在 ``` 代码块里的一个字都不动；
2. 含纯数学符号 `· ∈ ≡ × ≈ √ ⌈ ⌊ ∑ ⟺ θ ∞ ≠ ⊆ ∪ ∩ ∀ ∃ ≤ ≥` → 去掉（哪怕里面夹着代码名字）；
3. 整段就是一个或几个 `[..]`（纯区间记号）→ 去掉；
3b. **老式下标**（`x_i` / `cnt_i` / `a_j`：基名 $\le 3$ 字符 + 一个下划线 + 1~2 字母的尾巴）→ 去掉；
4. **形状像标识符**（`IDENT` snake_case/camelCase、`DOTNAME` 模块.函数、`SLASHNAME` 带 `-` 或 `/` 的名字、`SLASHCMD` 斜杠命令 `/status` 这类）
   或逐字命中白名单，或含代码特征子串（`[` `]` `::` `;` `==` `!=` `&&` `||` `++` `->` `.cpp` `\` `https://` 引号，以及 `ch`/`cnt`/`best`/`mn`/`mx`/`cross`/`gcd`/`ptr`/`d1`~`d4`）→ 保留；
5. 其余 → 去掉。

**为什么要有第 2、3 条**：只按「含不含代码特征」判会出错——`A·B = |A||B|cosθ` 含 `||`、`= |{ t ∈ [0, S) : t ≡ j (mod m) }|` 含 `[]`、`[l,r]` 含 `[]`，都会被误判成代码。

**为什么第 4 条是「形状」而不只是白名单**（实测）：
白名单是题解场景攒的，一份**非题解**的交付 md（配置文件 / 脚本名很多的那种）里 `flow_reps`、`water_glow`、`bloom_str`、
`grabCut`、`findContours(RETR_EXTERNAL)`、`DepthFlow`、`_work/`、`dylankamski/waterscape` 这类
配置项名 / 函数名 / 仓库名**全不在名单里** → 26 处判定里 **24 处误报**。
照「补名单不改规则」硬补要补 20 多个词，而且下个项目又来一批 → 改成**判形状**：
snake_case、camelCase、`模块.函数`、带 `-` 或 `/` 的名字一律算真代码。
**裸单词（`n` / `x` / `s`）故意不放过** —— 放过裸词就等于放过数学变量，那才是真该去灰底的。

四个门槛都是被回归测试逼出来的，**改这个函数必须跑回归**（`tools/selfcheck_unpair.py`，56 保留 + 37 去掉共 93 条样本，退出码 0 = 全过）：

| 一开始的写法 | 崩在哪 | 现在的写法 |
|---|---|---|
| snake_case 首段不限长 | `x_i`、`n_max` 这种老式下标被当成标识符留下灰底 | 首段 $\ge 3$ 字符 + 另加 `SUBSCRIPT` 规则 |
| `SUBSCRIPT` 只看「尾巴 1~2 字母」 | `caustic_hi`、`caustic_lo` 被误杀（`hi`/`lo` 在真代码里是常见后缀） | 再加「基名 $\le 3$ 字符」 |
| 没管点号 | `cv2.remap`、`np.clip` 被判成数学 | `DOTNAME`（首段与每段点后都以字母开头，挡 `3.14`） |
| 斜杠命令被当数学 | `/status`、`/model` 被判成数学记号 | 新增 `SLASHCMD` 形状（`/` + 小写字母 $\ge 2$ 位，**单字母 `/x` 不放过**）；`SLASHNAME` 放开前导 `/`（`/api/plan`），顺带修正 4 处 `.../Software/...` 路径的旧漏判 |

**踩过的坑**：
- 单引号当代码特征会把数学符号 `V'`（压缩值）也保住 → 单引号要配合「不含数学符号」才生效。
- 一开始把 `ab`/`abc`/`ax`/`a~f`/`A~F` 当成代码标识符放进白名单，结果样例串 `abc`、`ab` 灰底保住了，而旁边的 `a` 去掉了 → **同一句话里一半灰一半不灰**，比不改还难看。**白名单要按「这个文档里它到底是什么」定，不能按「名字像以前见过的标识符」定。**
- 去掉反引号后，表格里原本被反引号包住的 `|`（如 `|S|`）会撑破单元格 → 转换器要单独查这一项（实测：这些 `|` 都在正文行，不在表格行，未触发）。
- **工具别只留在临时目录里**（那里随任务删除一起清掉）。脚本都在 `tools/`，且**接受文件路径参数**而不是写死某一题的路径。

**坑（历史，已封存）**：转换函数如果对**已经生成过 `<sub>` 的行**再跑一遍转义，会把 `<sub>` 二次转义成 `&lt;sub&gt;`。
根因是把「转义原文尖括号」和「生成下标标签」写在同一步里。**分工：先对原文转义，再生成标签。**（现在下标写 `$a_i$`，不再生成 `<sub>`，但 checker 第 4 项仍防老文件回流。）

## 附：把脚本输出嵌进 md 的流水线

长题解里嵌十几段字符画时，别手抄——用「源 md 写占位符 + 脚本替换」：
源里写 `<<<VIS runs 3>>>`、`<<<CPP f>>>`，替换脚本从**实跑输出**和**验过的 cpp** 里取内容填进去，
交付 md 里嵌的就永远是"跑过的那一份、验过的那一份"。

**踩的坑**：占位符**不要自己带围栏**。源里写成

    ```text
    <<<VIS runs 3>>>
    ```

而替换脚本又吐出 ```` ```text ... ``` ````，结果就是两行紧挨着的 ```` ```text ````——
渲染出来是一个**空代码块**，正文全掉到代码块外面去了。
**规矩：围栏写在源 md 里，占位符只代表"正文"**（对 cpp 反过来：占位符整行替换，围栏由脚本吐）。

## 更根本的一条

**验证的维度里必须包含「使用者看到的形态」——而形态 = 查看器的当前设置。**

旧版教训：当时的验证全在语义层（对拍、比输出、查证明），从没验证过屏幕上长什么样，把自己的渲染结果当成了使用者看到的文本。而查看器设置一改（开启内联公式）之后，当年必须避开的 `$` 反而成了标准写法——**规则跟着查看器设置走：交付格式出问题（或要定新格式）时，先问「查看器现在开了什么」**。
