# 工作流（六步 + 落盘结构 + 分档）

> 类型：流程主干 ｜ **「落盘结构」与「分档规则」的唯一定义处**，其它文档只写指针；本文件同时是整个知识库的入口。
> 前提：环境已装好（见《环境准备》），数据根已配好（`config.json` 的 `data_root`，见 README）。

## 触发语

**只发一个牛客周赛的比赛 URL**（例：`https://ac.nowcoder.com/acm/contest/126120`）——
看到这种消息就照下面六步开工，**默认写该场全部题目**：有几题写几题，不自行截断、不挑题，也不再反问参数。

**题解根目录 = `<数据根>\题解\`**，根下**先按比赛分一层**：牛客周赛 = `<数据根>\题解\牛客周赛\`，
以后 Codeforces / AtCoder 各开一个平级目录，互不挤在一个 `RoundNNN` 命名空间里。
比赛目录里每一场一个 `RoundNNN\` 文件夹，交付 md 放场次根，其余全在里面——见下面「落盘结构」。

场次号（Round N）**不用手工定名**：`fetch_problem.py` 会去比赛主页读「牛客周赛 Round N」来自动定位输出目录
（题单接口本身只给 contestId、不给比赛名，主页有）。读不到就退到暂存区
`题解根\牛客周赛\_work\nk<cid>\` 并打印提示——**不瞎猜场次号**，猜错会把两场题解混进同一个文件夹。

## 六步：每一步都是一条命令

| # | 步骤 | 怎么做 | 产出 |
|---|---|---|---|
| 0 | **抓题面** | `python tools/fetch_problem.py <cid或URL> [区间]` | `RoundN\_work\{raw\, 题面\, samples.py}` |
| 1 | **定档** | 看第 0 步打印的**分档建议**，再查《概念台账》的「已讲过」清单 | 每题详写 / 短写 |
| 2 | **写代码** | 在 `<数据根>\题解\牛客周赛\RoundN\<区间>\<字母>\` 里写 `<字母>.cpp`（对拍题再加 `<字母>_brute.cpp`） | cpp |
| 3 | **验证** | 写 `verify_<字母>.py`，只填 `gen` / `EDGES` / `LIMITS`，跑它（`python tools/verify.py`） | 末尾 5 行「可直接贴进 md 的实测记录」（≤6 行纯文字，数字逐字来自实跑） |
| 4 | **写题解** | 按《题解写法》的结构（节模板白名单也在那）；数学直接写 LaTeX（《数学 LaTeX》）；配图脚本用 `tools/vizgrid.py`（《配图》） | `RoundN\RoundN题解.md` |
| 5 | **自检** | `python tools/check_solution.py <md>` —— **交付前必跑** | **17 项**报告（第 1 项＝`$` 配对、第 2 项＝LaTeX 完整度、第 9 项＝节白名单、第 10 项＝目录表四列、第 11 项＝题内小节顺序、第 16 项＝缩进代码块里的公式、第 17 项＝KaTeX 全量渲染，都必须「全部通过」） |
| 6 | **复验 + 归档** | `python tools/md_full.py <md> <字母>`（四档全跑；只要样例就用 `verify.py --from-md`）；过后按《归档》归档、顺手更新《概念台账》，**归档时把本场非签到题行追加到 `<数据根>\题解\题目状态.md`（状态默认「未做」，日期留空；签到题不进此表）**，**「知识点」列用 `tools/fill_knowledge.py` 从全量索引刷新**（dry → apply，幂等）；报告 = `tools/status_report.py`、看队列 / 改状态用图形端 `tools/status_gui.py`；收工 `python tools/archive_check.py RoundNNN` 会对归档把关，**退出码 0 = 归档完成** | — |

第 0 步的 `RoundN` 是**自动认出来的**，不用手传 `--out`。
抓完题面想一次把目录与 md 空壳建好，跑 `python tools/new_round.py <URL 或 Round号>`：
建 `RoundN\<区间>\<字母>\` 每题目录 + `RoundN题解.md` 骨架（幂等、不覆盖已存在文件；
目录表的考点 / 难度是「待填」「CF ???」占位，自检会报出来逼你填完）。
目录名对不上也没关系：`verify.py` 的 `find_samples()` 会往上找 `_work`
（`RoundN\A-F\A\` → `RoundN\_work\samples.py`），`_work` 里按场次 / 按 cid 两种命名都认。

第 5、6 步是**两道不同的闸**，别合并：第 5 步查格式（`$` 配对 / LaTeX 完整度 / 灰底 / 表格 / 编译），
第 6 步查语义（**md 里那一份**代码跑样例与对拍对不对）。第 6 步堵的缝是
「工作目录里的版本 ≠ 贴进 md 的版本」。

### 第 6 步的两个已知坑

1. **`--from-md` 只跑「编译 + 官方样例」**：边界 / 对拍 / 极限三档它一律报「没填」（它拿不到
   `EDGES` / `LIMITS` / `gen`）。要连边界和极限一起验，**用 `md_full.py`**——
   它直接复用同字母的 `verify_<字母>.py` 里那套用例，把 `md=` 一起转交给 `verify.main()`，四档全跑。
2. **相对路径的基准是「python 进程的 cwd」，不是脚本所在目录**：`verify.py` 会把
   `solution="a.cpp"` 拼到 cwd 上，于是从比赛目录跑 `python Round124\A-F\A\verify_a.py`
   会去找 `牛客周赛\a.cpp` 而不是 `Round124\A-F\A\a.cpp`（报「No such file or directory」）。
   **做法**：`verify_<字母>.py` 里用 `HERE = os.path.dirname(os.path.abspath(__file__))`
   拼绝对路径传进去（`workdir=HERE`）。

## 落盘结构（唯一定义处）

现行结构：**一场一个自包含文件夹**。

```
<数据根>\
  题解\
    题目状态.md                      ← **状态跟踪总表**（一题一行；改状态走图形端 tools/status_gui.py 或直接改 md；报告 = tools/status_report.py）
    牛客周赛\                        ← **按比赛分一层**；Codeforces / AtCoder 平级再开
      Round124\                      ← 一场一个 `RoundNNN\`，自包含
        Round124题解.md              ← 交付物，放**场次根**（不塞子目录）
        A-F\                         ← 题号区间一层（A-F / A-G / B-G，跟着本场实际题号走）
          A\
            a.cpp                   正解（**就是贴进 md 的那一份**）
            a_brute.cpp             暴力（可选；跟正解**必须不同实现范式**，见《验证协议》）
            verify_a.py             填空文件，只写 gen / EDGES / LIMITS
            samples.py              官方样例常量表（可选；也可整场放 _work，verify.py 自己找）
            pair_visual.py          配图脚本（可选，见《配图》）
            run.cmd                 纯 ASCII + CRLF，双击可跑
          ...
        _work\                       ← 本场中间产物；随用随清（抓取产物不留）
          raw\<字母>.html              抓下来的原始页面
          题面\<字母>.txt              Unicode 化后的题面
          题面\_全部.txt               合并版
          samples.py                  官方样例常量表（整场，机械生成，别手敲）
          from_md\                    verify.py --from-md 抽出来的临时 cpp
    牛客周赛\_work\                  ← 比赛目录级暂存区：只给「还不知道场次号」的抓取用
      nk<cid>\                        定下场次后改名成 RoundN\_work
  算法\                              ← 算法库（见《归档》）
  索引\                              ← 全量索引（见《归档》）
```

五条规矩：

1. **交付的 md 放场次根 `RoundNNN\`**，名字就叫 **`RoundNNN题解.md`**（场次号自带、区间不写）；
   桌面副本是**可选功能**：`config.json` 里配了 `desktop_copy_dir` 才有这一步，
   副本名 = `<比赛名>RoundNNN题解.md`，且**副本不主动同步**——说要同步才同步；
2. **每题一个 `<字母>\` 子目录**（套在题号区间层下面），装它自己的 cpp 与脚本；
3. **`_work\` 是唯一允许杂乱的地方**，也是唯一可以随手删的地方。改 md 前的备份
   **不在这里**——备份统一进备份仓（`config.json` 的 `backup_root`，镜像子目录 + 时间戳），
   题解区不留任何 `.bak` / `.orig`；一次性 diff 输出丢 `_work\`；
4. `verify.py` 的 `--from-md` 临时文件写到 `RoundN\_work\from_md\`，**不落场次根**；
5. **持久信息一律进知识库，不留在题解区**。凡是「下次写题解会用上」的东西——流程改动、
   工具新行为、踩过的坑、留证、约定——写进知识库（`knowledge\`）或你的项目笔记；
   题解区只放**交付物 + 代码 + 脚本**。
   判断标准一句话：**这句话删了，下次会不会做错？会 → 进知识库。**

**抓取产物不长期留**：`_work\raw\`、`_work\题面\`、`_work\samples.py`、`__pycache__`
都是**一条命令就能重生成**的东西，随手清。代价是：**复跑 `--from-md` 之前得先重抓一次**
（`python tools/fetch_problem.py <cid>`，它自己会落回 `RoundN\_work\`）。
`verify.py` 找不到 `samples.py` 时不会崩，只会报「没找到，跳过」并如实显示「未验证」。

## 分档（唯一定义处）

`fetch_problem.py` 直接给建议：**AC 数 ≥ 全场最高 AC 的一半 → 短写**，其余 → 详写。

| 档 | 写什么 |
|---|---|
| **短写**（签到 / 入门） | 题意 → 手算 → 参考代码 → 易错点。**手算样例和易错点一个都不能省** |
| **详写**（普及以上 / 需要新套路） | 按《题解写法》的教程式长文 |

**两条覆盖规则（优先级高于 AC 数）**：

1. 用到**前面场次没出现过**的新算法 / 数据结构 → 无论 AC 多高都详写（见《从零讲》）；
2. 用到的算法**在《概念台账》清单里** → 算法讲解段只给指针，不重复从零讲。
   注意降的**只是算法讲解段**，该题其余内容一律照写。

分档是替读者省时间，不是降标准。

## 验证档位（唯一定义处）

| 档 | 跑什么 | 什么时候 |
|---|---|---|
| **基线**（全员） | 官方全样例 + 自构边界 | 每一题 |
| **加码**（靠后 1~2 题） | 加同语言随机对拍（几百 ~ 1500 组） | 逻辑绕的题：博弈 / 并查集 / 阈值转化 / 几何 |
| **极限** | 最大规模计时 | 每一题 |
| **未验证** | 如实写「未验证」，不留空、不照抄往次记录 | 没跑的档 |

边界用例固定清单：`n=1`、`k=0`、`t=0`、全零、全同、单点环、最大规模。

**对拍必须是「同语言 + 不同实现范式」**（递归 vs 迭代、位掩码 vs 集合、匹配 vs 枚举），
两边各自先对上手算过的期望值再上随机——**同源互拍等于没拍**（见《验证协议》）。

## 可调档

- 单题加码：「G 题必须对拍」——几何题可用精确有理数（Python `fractions.Fraction`）对拍，
  此法在真实使用中抓到过符号写反的错误。
- 整体降级：「只跑样例」。

## 易错提醒

- Special Judge 构造题若恰好复现样例，要**专门注明**；
- 几何 / 大数题主动提示溢出坑（如叉积爆 `long long`）；
- **禁 stdio 与 iostream 混用**：部分 MinGW / UCRT64 工具链上会静默读空、样例直接跑错（见《环境准备》）。

## 实测记录不许「生成」（机制化）

**不要凭记忆写验证结论**。真实使用中出过「文末写『N 组对拍全部一致』、现场复跑第一组就失败」
的事故（原样留证见《反面教材》）。执行类错误要靠机制堵，四个口子已由脚本堵死：

1. **样例别手敲** —— `samples.py` 由 `fetch_problem.py` 从题面原文机械生成，没有「凭记忆」这一步；
2. **组数别手写** —— `verify.py` 分开统计「实际跑了 N 组」与「设计 M 组」，
   提前中断会直接打出「★记录里写 N 组、不要写 M 组★」；
3. **验 md 里那一份** —— `--from-md` 直接抽 md 的代码块来编译；
4. **模糊词自动查** —— `check_solution.py` 第 6 项扫「约 / 大概 / 左右」，报出的是**带行号的原句**。

记录 **≤6 行、写成文字**（写清实跑过哪几档、各组数、极限耗时；**不用表格、不用 `- ` 列表**），
数字全部来自实跑输出，不写「约 / 大概」。
