# 牛客周赛 Round 163 C - 小月的对局

- **难度**：CF 1800
- **原题链接**：https://ac.nowcoder.com/acm/contest/140737/C
- **题解位置**：`<数据根>\题解\牛客周赛\Round163\Round163题解.md`（整场题解，含完整推导）
- **归档文件夹**：`二分图匹配\`
- **数据结构与算法**：二分图最大匹配（匈牙利）+ Hall 定理
- **具体知识点**：Bob 能赢 ⟺ 互质图上存在完美匹配；另有全排列枚举、记忆化搜索两种等价写法

## 题意（精简）

双方各有 n 张牌（正整数），每轮 Alice 先出一张 x，Bob 看到之后再出一张 y：
若 `gcd(x, y) > 1` 则 Alice 立刻获胜，否则这两张牌一起移出对局；牌全部打完 Alice 还没赢则 Bob 获胜。
双方都最优，问胜者。题面只写了"Bob 看到 Alice 本轮出的牌后再出"，没写双方是否知道彼此全部手牌——本解依赖完全信息这个前提。

**数据范围**：1 ≤ n ≤ 6；牌面 ≤ 30；时限 2 秒

## 关键点（为什么用这个算法）

1. 信号：Bob 想赢就必须每一轮都掏出一张与 Alice 当前牌互质的牌；他"看得到牌"，难点不是信息，而是牌够不够、配不配得上。
2. 朴素想法"每张牌都有搭档就行"不够：a = {6,10,14}、b = {2,3,7} 时三张牌各自都有能接的，但 6 和 14 抢同一个 3/7，凑不出三对互不重复的。
3. 正解：把 Bob 的"应对表"看成二分图完美匹配——左部 Alice 的 n 张牌，右部 Bob 的 n 张牌，gcd(a<sub>i</sub>, b<sub>j</sub>) == 1 才连边；存在完美匹配 ⟺ Bob 胜。
4. 反方向：不存在完美匹配时，由 Hall 定理存在 Alice 的子集 S 使 |N(S)| < |S|；Alice 先把 S 里的牌全部打出，Bob 只能从 N(S) 里选牌，牌不够用，必然某轮被迫打出 `gcd > 1` 的一对。

## 复杂度

- 时间：匈牙利算法 O(n · E) = O(n³)（n ≤ 6，实际是常数级），加读入 O(n)；等价写法：全排列枚举 O((n!)² · n)（n = 6 时约 3.1×10^6），记忆化博弈搜索 O(4^n · n²)
- 空间：O(n) 的匹配数组与访问标记（邻接矩阵意义上的 O(n²) 也很小）

## 踩过的坑

1. 边的方向搞反 → "能安全接住"是 `gcd == 1`，不是 `gcd > 1`，写反了输出整体倒过来。
2. `vis` 没有对每个左部点重新清空 → 同一轮里会漏掉可以"换人"的增广路，匹配数偏小。
3. 只看"每张牌有没有伴"就下结论 → a = {6,10,14}、b = {2,3,7} 逐张看都有搭档，但凑不出三对互不重复的（本地验证输出 Alice），必须真的跑匹配或写博弈搜索。
4. 写全排列枚举版时的三个连坐坑 → 判据是"存在全互质配对 → Bob"，不是"存在 `gcd > 1` 的一对 → Alice"（写反了 n = 1 的样例照样对，不容易当场发现）；`next_permutation` 前没 `sort` 会一个排列都不产出；内层跳出后 b 停在中间顺序，每轮外层都要重新 `sort(b)`。
