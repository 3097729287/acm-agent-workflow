## B. 小月的十六进制

### 题意

- 给一个十六进制字符串 $x$（长度 1 ~ $8 \times 10^5$，可能有前导零，大小写都有）和一个整数 $k$（0 ~ $10^5$）。
- 问：$x$ 表示的**整数**能不能被 $2^k$ 整除？是输出 `YES`，否则 `NO`。
- 特别注意说明里的第三组样例：`x = "0"`, $k = 100000 \to$ `YES`。因为 $0 = 0 \times 2^{100000}$。

### 思路

**朴素想法**：把十六进制转成十进制/二进制大整数，再去除。可是 $8 \times 10^5$ 个十六进制位 = $3.2 \times 10^6$ 个二进制位，就算用高精度也很笨重。

**关键观察**：一个整数能被 2 整除，就是二进制末尾是 0；能被 4 整除，末尾两个 0；一般地：

> 正整数 V 能被 $2^k$ 整除 $\iff V$ 的二进制表示末尾至少有 $k$ 个 0。

所以只需要数出"二进制末尾 0 的个数" $z$，判断 $z \ge k$ 即可。**根本不用知道这个数具体是多少。**

**怎么快速数 $z$**：十六进制 **1 位 = 4 个二进制位**。从字符串的**末尾**（最低位）往前扫：

- 遇到字符 `'0'`（这一位数值是 0）：它贡献 4 个末尾 0，继续往前看；
- 遇到第一个非 0 位，数值记为 $d$：它贡献 $d$ 自己二进制末尾 0 的个数（$d = 8 = 1000_2$ 贡献 3 个，$d = 10 = 1010_2$ 贡献 1 个），**然后立刻停止**——再往前的高位不可能再产生末尾 0 了。

$d$ 的末尾 0 个数可以用 GCC 内置函数 `__builtin_ctz(d)`（count trailing zeros）直接拿到。

**手算例子 1**：`x = "1A0"`, $k = 5$

| 扫描位置 | 字符 | 数值 | 累计 $z$ |
|---|---|---|---|
| 最后 1 位 | 0 | 0 | 4 |
| 倒数第 2 位 | A | $10 = 1010_2$ | 4 + 1 = 5，停止 |

$z = 5 \ge 5 \to$ `YES`。（原题说明：$416 = 13 \times 32$ ✓）

**手算例子 2**：`x = "Abc"`, $k = 4$：末位 $c = 12 = 1100_2 \to z = 2 < 4 \to$ `NO`。（$2748 \div 16$ 余 12 ✓）

**手算例子 3**：`x = "0"`, $k = 100000$：整个串都是 `'0'`，值是 0 → 直接 `YES`。

**为什么这样数是对的**：设 V > 0，把 V 写成 $V = 2^z \cdot m$（$m$ 是奇数），这个分解唯一，$z$ 就是二进制末尾 0 的个数，于是 $2^k$ | $V \iff k \le z$。再把十六进制串写成 $V = \sum h_i \cdot 2^{4i}$：末位 $h_0 = 0$ 时 $V = 16 \cdot V'$，末尾 0 的个数正好比 V' 多 4，与"读到 `'0'` 就 +4 再往前"一致；末位 $h_0 = d > 0$ 时 $V = d + 16 \cdot V'$，而 $16 \cdot V'$ 的末尾 0 个数至少 4 个、比 $d$ 的末尾 0 个数多（$d \le 15 < 16$），所以 V 的末尾 0 个数恰好等于 $d$ 的末尾 0 个数，累加 `ctz(d)` 之后必须立刻停。归纳即得：算法数出的 $z$ 就是 V 的二进制末尾 0 个数。唯一的例外是 V = 0（末尾有无穷多个 0），但 $0 = 0 \times 2^k$ 对任何 $k$ 都成立、题面也明确说明输出 `YES`，所以用 `allZero` 标记单独处理。

### 参考代码

```cpp
// B - 小月的十六进制
// 判断十六进制串 x 表示的数能否被 2^k 整除
// 做法：一个数能被 2^k 整除 <=> 它的二进制末尾至少有 k 个 0
// 十六进制每一位恰好是 4 个二进制位，所以可以从末位往前数 0
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string x;          // 十六进制字符串
    int k;             // 2 的指数
    cin >> x >> k;

    long long zeros = 0;   // 已经数出来的“二进制末尾 0”的个数
    bool allZero = true;   // x 表示的数是不是 0

    // 从字符串最后一位（最低的十六进制位）往前扫
    for (int i = (int)x.size() - 1; i >= 0; --i) {
        int d;                                   // 这一位对应的数值 0~15
        if (isdigit((unsigned char)x[i])) d = x[i] - '0';
        else                              d = tolower(x[i]) - 'a' + 10;

        if (d == 0) {
            zeros += 4;          // 这一位是 0，它贡献 4 个二进制 0，继续往前看
        } else {
            allZero = false;     // 遇到第一个非 0 位，数到这里就够了
            zeros += __builtin_ctz(d);   // d 自己的二进制末尾 0 的个数（d>0 才有定义）
            break;
        }
    }

    // 整个数是 0 时，0 = 0 * 2^k，任何 k 都整除
    if (allZero || zeros >= k) cout << "YES\n";
    else                       cout << "NO\n";
    return 0;
}
```

### 复杂度

- 时间：$O$(|$x$|)，最坏（全 0 串）要扫完整个字符串，$8 \times 10^5$ 次操作，1 秒绰绰有余。
- 空间：$O$(|$x$|) 存输入串，额外变量 $O(1)$。

### 易错点

1. **$x = 0$ 必须特判**。样例 3 就是专门挖的坑：$k = 100000$ 比位数能提供的 0 多得多，但 0 能被任何 $2^k$ 整除。
2. **大小写都要转**：题面允许 A~F 和 $a$~$f$，用 `tolower` 统一处理。
3. $z$ 最大 $4 \times 8 \times 10^5 = 3.2 \times 10^6$，`int` 不会溢出，但用 `long long` 更省心。
4. **不要真的去算这个大整数**（`long double` 存不下 $3.2 \times 10^6$ 位的信息），本题考的就是"只看末尾零"。
5. `isdigit` 的入参要转 `unsigned char`，否则遇到负值字符是未定义行为（比赛中很常见的隐藏 bug）。

## C. 小月的对局

### 题意

- 双方各有 $n$ 张牌（$1 \le n \le 6$），牌面是正整数（$\le 30$）。
- 每轮：Alice 先出一张 $x \to$ **Bob 看到之后**再出一张 $y \to$ 若 `gcd(x, y) > 1`，**Alice 立刻获胜**；否则这两张牌一起移出对局。
- 牌全部打完 Alice 还没赢 → Bob 获胜。双方都最优。问胜者。

> **【必须点明的隐含前提】** 题面只明写了「Bob 在看到 Alice 本轮打出的牌后……再出牌」，
> **并没有写"双方知道彼此的全部手牌"**。但本解（以及"匹配"这个结论）依赖的是**完全信息**：
> 双方都知道当前双方手里还剩哪些牌。若不这么假设，这题**没有唯一答案**——
> 例如 Bob 手牌固定为 {2,3,5}、Alice 首手都是出 4 时，{4,6,7} 是 Bob 胜、{2,4,8} 是 Alice 胜，
> 而 Bob 观察到的信息完全相同，他的"最优应对"根本无从定义。

### 思路

**先站在 Bob 的角度想**：Bob 要赢，就必须在**每一轮**都掏出一张和 Alice 当前牌**互质**的牌。注意 Bob 是"看到 Alice 的牌再出"，所以他的难点不是信息，而是**牌够不够、配不配得上**。

**核心转化**：如果 Bob 能事先定好一张"应对表"——给 Alice 的每张牌都指定一张**互质的、互不重复的** Bob 牌——那么不管 Alice 按什么顺序出牌，Bob 照表回应，就能一直苟到最后一张，Bob 胜。
这张"应对表"就是一张**二分图完美匹配**：

- 左部 = Alice 的 $n$ 张牌，右部 = Bob 的 $n$ 张牌；
- 若 $\gcd(a_i, b_j) == 1$ 就连一条边（表示"Bob 用 $b_j$ 能安全接住 $a_i$"）；
- 存在**完美匹配**（$n$ 条边两两不共用点）$\iff Bob$ 能赢。

**反过来**（不存在完美匹配时 Alice 怎么赢）：由 **Hall 定理**，此时存在 Alice 的某个子集 S，能安全接住 S 的 Bob 牌集合 N(S) 满足 |N(S)| < |S|。Alice 就把 S 里的牌**全部先打出去**：每一轮 Bob 只能从 N(S) 里选牌（N(S) 之外的牌与 S 里每张牌都 `gcd > 1`，出了就直接输），可 N(S) 的牌不够 |S| 轮用，必然有一轮无牌可出 → 只能出 `gcd > 1` 的牌 → Alice 胜。

所以答案就是一句话：**能求出 $n$ 对互质配对 → Bob，否则 → Alice**。

**手算例子（样例 3）**：$a = \{3, 8, 5, 2, 4\}$，$b = \{6, 9, 10, 7, 2\}$。

先列出"谁能接住谁"（只看互质的）：

| Alice 的牌 | 能安全接住的 Bob 牌 |
|---|---|
| 3 | 10, 7, 2 |
| 8 | 9, 7 |
| 5 | 6, 9, 7, 2 |
| 2 | 9, 7 |
| 4 | 9, 7 |

看子集 S = {8, 2, 4}：它们能用的 Bob 牌合起来只有 {9, 7} 两张，3 > 2 —— Hall 条件被破坏，完美匹配不存在 → **Alice 胜**。这正是样例说明里说的"打出 8、2、4 三张牌"。

再手算样例 1、2：$n = 1$ 时，只有一对牌，`gcd(2,4)=2>1` → Alice；`gcd(2,3)=1` → Bob。

#### 想省事的两条等价写法

上面的"完美匹配 $\iff Bob$ 胜"证起来要用 Hall 定理。$n \le 6$ 这个范围还给了两条更省事、都已交叉验证等价的路子：

| 写法 | 代码量 | 复杂度 | 要动脑的地方 | 天花板 |
|---|---|---|---|---|
| **A. 全排列枚举** | 约 20 行 | $O((n!)^2 \cdot n)$ | 只需想通"为什么固定排列就够" | $n \le 7$ |
| **B. 记忆化博弈搜索** | 约 40 行 | $O(4^n \cdot n^2)$ | 要设计状态、递归、记忆化 | $n \le 12$ |
| 匈牙利匹配（主解） | 约 45 行 | $O(n^3)$ | 要理解匹配 / Hall | 不限 |

写法 A 的着眼点是"Bob 后手但看得见牌"：他**开局就可以在心里固定一个自己的出牌排列** P，之后 Alice 出哪张，他就打 P 里跟那张配成对的那张（这是允许的，他不需要提前亮牌）。只要 P 里**每一对都互质**，Alice 不管按什么顺序出 Bob 都顶得住；若对 Alice 的每一种出牌顺序都凑不出这样的 P，Bob 就必然被迫打出一对 `gcd > 1` 的牌。于是博弈退化成一句判据：**存不存在一组每一对都互质的完整配对**。写法 B 更省脑：$n \le 6$ 时状态只有 $2^n \times 2^n$ 种，直接把博弈树搜一遍即可（win(ma, mb) = Alice 手牌为 ma、Bob 为 mb、轮到 Alice 时她是否必胜）。

两条路的完整教程在 `B-G\C\专题\牛客C-小月的对局-全排列枚举写法.md` 与 `牛客C-小月的对局-DFS博弈详解.md`；六路互拍脚本是同目录的 `对拍_含排列枚举.py`（结果见文末实测记录）。

> 判据方向别写反：是"**存在全互质配对 → Bob**"，不是"存在 `gcd>1` 的一对 → Alice"。
> 这两种说法互为反面，写反了输出会整体倒过来，而样例 1、2（$n = 1$）照样是对的，不容易当场发现。

**为什么这个判据是充要的**：若二分图存在完美匹配 M，Bob 采用策略"Alice 出 $a_i$，我就出 M 中与 $a_i$ 配对的 $b_j$"——因为 M 是匹配，$b_j$ 不会被用过两次；因为 M 中每条边都满足 `gcd = 1`，Bob 每轮都安全，$n$ 轮打完 Alice 都没赢，Bob 胜。反过来若不存在完美匹配，由 Hall 定理存在 $S \subseteq A$ 使 |N(S)| < |S|，Alice 就把 S 里的牌全部先打出去：Bob 若出 N(S) 以外的牌，那张牌与 S 中每张牌都不互质、Alice 立即获胜，所以他只能出 N(S) 里的牌；可 S 的 |S| 轮里他要拿 |S| 张**互不相同**的 N(S) 牌，而 |N(S)| < |S|，鸽巢原理保证某轮无牌可用，Bob 必输。两个方向合起来：完美匹配存在 $\iff Bob$ 胜，而匈牙利算法求出的最大匹配大小等于 $n$ 当且仅当完美匹配存在。

### 参考代码

```cpp
// C - 小月的对局
// 结论：Bob 能活下来（Bob 胜）<=> 二分图“安全配对”存在完美匹配
//       Alice 牌 i 与 Bob 牌 j 能安全配对 <=> gcd(a_i, b_j) == 1
// 若不存在完美匹配，Alice 先打出缺口子集里的牌即可逼死 Bob
#include <bits/stdc++.h>
using namespace std;

int n;
int a[10], b[10];
int matchB[10];      // matchB[j] = 与 Bob 的牌 j 配对的 Alice 牌编号，-1 表示还没配对
bool vis[10];        // 本轮 DFS 中 Bob 的牌 j 是否已被访问过

// 匈牙利算法：尝试给 Alice 的牌 u 找一张能安全配对的 Bob 牌
bool dfs(int u) {
    for (int v = 0; v < n; ++v) {
        if (__gcd(a[u], b[v]) != 1) continue;   // gcd > 1 就不安全，Bob 不敢出这张
        if (vis[v]) continue;                   // 本轮已经试过 Bob 的这张牌
        vis[v] = true;
        // Bob 的牌 v 还空着，或者能给它原来的主人换一张别的牌
        if (matchB[v] == -1 || dfs(matchB[v])) {
            matchB[v] = u;
            return true;
        }
    }
    return false;   // 实在找不到，说明这张 Alice 牌没法被安全应对
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    for (int i = 0; i < n; ++i) cin >> a[i];
    for (int i = 0; i < n; ++i) cin >> b[i];

    fill(matchB, matchB + n, -1);
    int matched = 0;
    for (int i = 0; i < n; ++i) {
        fill(vis, vis + n, false);   // 每个左部点开始找增广路前都要清空标记
        if (dfs(i)) ++matched;
    }

    // 所有 Alice 的牌都能被互质的 Bob 牌一对一挡住 -> Bob 胜，否则 Alice 胜
    cout << (matched == n ? "Bob" : "Alice") << '\n';
    return 0;
}
```

### 复杂度

- 时间：匈牙利算法 $O(n \cdot E) = O(n^3)$（$n \le 6$，实际是常数级），加上读入 $O(n)$。记忆化搜索是 $O(4^n \cdot n^2)$，本题同样安全。
- 空间：$O(n)$ 的匹配数组与访问标记（邻接矩阵意义上的 $O(n^2)$ 也很小）。

### 易错点

1. **边的方向不能搞反**：能安全接住 = `gcd == 1`，不是 `gcd > 1`。
2. **`vis` 要针对每个左部点重新清空**，否则同一轮里会漏掉可以"换人"的增广路。
3. **"每张牌都有人能接"不等于"能一一配对"**。反例（已本地验证，程序输出 Alice）：
   $a = \{6, 10, 14\}$，$b = \{2, 3, 7\}$。逐张看：6 只能接 7，10 能接 3、7，14 只能接 3 ——
   **每张牌都有搭档**，但 6 和 14 抢同一个 7/3，凑不出三对互不重复的 → 无完美匹配 → Alice 胜。
   所以必须真的跑匹配（或像 `牛客C-小月的对局\` 里那样写博弈搜索），不能只看"每张牌有没有伴"。
4. 用 `std::gcd`（`<numeric>`，C++17）或 `__gcd` 都行；`__gcd` 对负数行为不确定，本题都是正数，没问题。
5. 牌面相同、有重复都没关系，匈牙利算法按"位置"处理，不按"数值"。
6. 写记忆化搜索版本时，注意"Bob 无牌可出"这种情况不存在（双方牌数始终相同），但"Alice 无牌可出"必须返回 `false`。
7. **（写法 A 全排列枚举）三个高频坑**：
   - 判据方向：是"存在**全互质**配对 → Bob"，不是"存在 `gcd>1` 的一对 → Alice"。写反了整体倒过来，且 $n=1$ 的样例 1、2 仍然是对的，不容易当场发现。
   - `next_permutation` **前必须 `sort`**，序列非升序时它一个排列都不产出，循环直接空转。
   - 内层 `break` 跳出后 $b$ 停在中间顺序，**每轮外层都要重新 `sort(b)`**，否则会漏排列。

## D. 小月的地砖

### 题意

要构造一个 $n$ 行 $m$ 列的 01 网格（$n, m \le 2 \times 10^5$，且 $n \times m \le 2 \times 10^5$），满足三条：

1. 第 $i$ 行**恰好**有 $a_i$ 个 1；
2. 每行的 1 在**环**上连续（第 $m$ 列与第 1 列相邻），也就是说这些 1 允许"跨过边界"连成一段；$a_i = 0$ 或 $a_i = m$ 自然满足；
3. 任意两列中 1 的个数之差**不超过 1**。

输出任意一个合法解（Special Judge）。

### 思路

**先看条件 3 说了什么**：总共有 $S = a_1 + a_2 + \ldots+ a_n$ 个 1，平均到 $m$ 列是 $S/m$ 个。要求任意两列只差不超过 1，等价于：

> 每一列的 1 的个数必须是 $\lfloor S/m \rfloor$ 或 $\lceil S/m \rceil$。

所以"每列分到几个 1"是**被唯一确定的**，构造的难点在于同时满足"行内环上连续"。

**朴素想法**：一行一行地填，第 $i$ 行从上一行结束的列继续往后放 $a_i$ 个连续 1。这其实就是下面正解的手工版，但起点一旦算错就会出现某列多 1 个少 1 个，所以需要一个精确的模型。

**正解：一条长带子模型**：

1. 想象把所有 1 排成一条**一维长带子**，位置编号 0, 1, 2, …, S-1；
2. 第 $i$ 行"占用"带子上的一段：[$P_i, P_i + a_i$)，其中 $P_i = a_1 + a_2 + \ldots+ a_{i-1}$（前 $i-1$ 行用掉的个数）；
3. 把带子上第 $t$ 号位置**映射到列** $t \bmod m$。

三件事全都自动成立：

- **每行个数**正好 $a_i$（这一段长度就是 $a_i$）；
- **环上连续**：每行占的是带子上**连续**的一段，映射到列就是连续的一段（可能跨过 $m-1 \to 0$，但在环上它们本来就相邻）。若 $a_i = m$，正好覆盖所有列，全 1；若 $a_i = 0$，这段是空的；
- **列计数差 $\le 1$**：第 $j$ 列拿到的是带子上所有 $t \equiv j (\bmod m)$ 的位置，个数就是 0…S-1 中模 $m$ 余 $j$ 的数的个数，恰好是 $\lfloor S/m \rfloor$ 或 $\lceil S/m \rceil$。

**手算例子（样例 1）**：$n = 3, m = 4, a = \{3, 2, 1\}$，S = 6，带子编号 0..5：

| 行 | 占的带子编号 | 对应列 $t \bmod 4$ | 该行 | 说明 |
|---|---|---|---|---|
| 1 | 0, 1, 2 | 0, 1, 2 | 1110 | |
| 2 | 3, 4 | 3, 0 | 1001 | 1 在列 3 和列 0，环上相邻 ✓ |
| 3 | 5 | 1 | 0100 | |

四列分别是 2, 2, 1, 1，最大差 1 ✓。和样例输出完全一致（当然，任意合法解都可以）。

**再看样例 2**：$n = 2, m = 3, a = \{0, 3\}$，S = 3。第 1 行空段 → 000；第 2 行占 0,1,2 → 列 0,1,2 → 111。三列计数全相等 ✓。

**为什么这个构造合法**：逐条对着三条约束验一遍。约束 1：第 $i$ 行占的带子区间 [$P_i, P_i + a_i$) 长度恰为 $a_i$，且这些 $t$ 两两不同（区间不重叠，因为 $P_{i+1} = P_i + a_i$）；区间内两个不同的 $t$ 相差 $< m$，模 $m$ 后必然落在不同列，所以该行恰好有 $a_i$ 个 1。约束 2：$t$ 与 $t+1$ 映射到的列在环上相邻（含 $m-1 \to 0$），该行的列集合是连续区间的模 $m$ 像，仍是环上连续的一段，$a_i = 0$ 时为空、$a_i = m$ 时为全体列，按题面都算满足。约束 3：列 $j$ 的 1 的个数 = |{ t ∈ [0, S) : t ≡ j (mod m) }|，把 S 写成 $qm + r$，它就是 $q+1$（当 $j < r$）或 $q$（否则），总是 $\lfloor S/m \rfloor$ 或 $\lceil S/m \rceil$，所以最大最小差 $\le 1$。题面保证"在给定范围内总能构造出合法答案"，这个构造对所有合法输入都成立。

### 参考代码

```cpp
// D - 小月的地砖
// 构造：想象一条总长为 S = sum(a_i) 的一维带子，把第 i 行要填的 a_i 个 1
//       依次摆在带子上（第 i 行占 [P_i, P_i + a_i)，P_i 是前 i-1 行的 1 的个数之和）。
//       带子上第 t 个位置映射到列 t mod m。
// 这样：每行的 1 在环上连续；每一列被用到的次数只差不超过 1。
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    scanf("%d %d", &n, &m);
    vector<int> a(n);
    for (int i = 0; i < n; ++i) {
        scanf("%d", &a[i]);
    }

    vector<string> g(n, string(m, '0'));
    long long ptr = 0;              // 当前这一行在“总带子”上的起点
    for (int i = 0; i < n; ++i) {
        for (int t = 0; t < a[i]; ++t) {
            int col = (int)((ptr + t) % m);   // 带子上的位置 -> 列号
            g[i][col] = '1';
        }
        ptr += a[i];                // 下一行的起点往后挪 a_i
    }

    for (int i = 0; i < n; ++i) puts(g[i].c_str());
    return 0;
}
```

### 复杂度

- 时间：$O(n + S) = O(nm)$（每个 1 摆放一次），$nm \le 2 \times 10^5$。
- 空间：$O(nm)$ 存输出网格（$n$ 个 `string`）。

### 易错点

1. **"环上连续"允许越过边界**：1001 在 $m = 4$ 时是合法的（列 3 与列 0 相邻），不要以为非要写成 0011。
2. $a_i = 0 / a_i = m$ 都要能正确处理，上面的写法天然支持。
3. **Special Judge**：牛客的"自测运行"可能因为只比对一个标准答案而报错，这是正常的，自己按三条约束检查即可。
4. S 用 `int` 也行（$S \le nm \le 2 \times 10^5$），但用 `long long` 更保险；`ptr + t` 也不会溢出。
5. 输出量 $nm \le 2 \times 10^5$ 字符，用 `puts`/`'\n'` 都行，别用 `endl` 逐行刷新。

## E. 小月的门

### 题意

- 有一条**有向**闸门线段 P1(u1,v1) → P2(u2,v2)，以该方向为准，**左侧区域是库内**，右侧是库外。
- 有 $n$ 条物品移动线段，第 $i$ 个物品从 $(a_i, b_i)$ 直线走到 $(c_i, d_i)$（可以是同一个点）。
- **只有交点严格位于两条线段的内部**才算"穿过"：交点是任何一条线段的端点 → 不算；两线段有重合部分（含完全重合）→ 不算。
- 物品从库外穿到库内 → 库内数量 +1；从库内穿到库外 $\to -1$。求经过所有移动后库内的**变化量**。

### 从零讲：叉积

> 这一节是专门为"第一次见叉积"写的。这道题里你熟悉的部分（读入、循环、输出）占九成，
> 真正的新东西只有一个：**叉积**。它也是唯一需要动脑的地方，所以这里从头讲一遍，
> 讲完再往下看「思路」，你会发现那几行公式其实很朴素。
> 下面的图都来自 `B-G\E\cross_visual.py` 的实跑输出，双击 `B-G\E\run.cmd`（或在 `B-G\E\` 下敲 `python cross_visual.py`）就能自己跑一遍。

#### 它要回答的问题

这道题要求判断"物品线段有没有真正从闸门穿过去"。判断的关键是一句话：

> **物品的两个端点，分别在闸门这条直线的两侧。**

听起来很直观 —— 画个图就看得出来。但程序不会看图，它需要**一个能算出正负号的数字**，
用这个数字的符号来回答"一个点在一条直线的哪一边"。

叉积就是造这个数字的工具。它不是什么新运算，就是**两次乘法、一次减法**。

#### 叉积是什么：一个"有向面积"

先看它长什么样：

```
cross(O, A, B) = (A.x - O.x) * (B.y - O.y) - (A.y - O.y) * (B.x - O.x)
```

它要三个点：一个**出发点** O，另外两个点 A、B。算出来**是一个数**，不是点、不是向量。

这个数的几何含义是：

> 把 O→A 和 O→B 当成平行四边形的两条边，**这个平行四边形的面积**，
> 再配上**一个正负号**。

面积本身总是正的，所以叫"**有向**面积"—— 多出来的那个符号记录了一件事：
从 O→A 转到 O→B，是**逆时针**还是**顺时针**。

- 逆时针（左手从 OA 扫到 OB）→ 面积为正 → `cross > 0`
- 顺时针 → 面积为负 → `cross < 0`
- 三点一条线（平行四边形被压扁）→ 面积是 0 → `cross = 0`

**这一步是整节的钥匙**：叉积的正负号，等于"B 在 O→A 的左边还是右边"。

#### 怎么算：代三个点进去

公式看着复杂，其实就是"**交叉相乘再相减**"：

```
cross = (A.x - O.x) × (B.y - O.y)  -  (A.y - O.y) × (B.x - O.x)
          ╰────── 前一半 ──────╯      ╰────── 后一半 ──────╯
```

拿三个具体点代进去算一遍。取 $O = (0, 0)$、$A = (4, 0)$、$B = (1, 3)$：

| 要算的量 | 代入 | 结果 |
|---|---|---|
| $A.x - O.x$ | $4 - 0$ | 4 |
| $B.y - O.y$ | $3 - 0$ | 3 |
| $A.y - O.y$ | $0 - 0$ | 0 |
| $B.x - O.x$ | $1 - 0$ | 1 |

```
cross = 4 × 3  -  0 × 1
      = 12     -  0      = 12
```

算出 **12 > 0**，所以 **B 在 O→A 的左侧**。

**验算一下"面积"这个说法**：O→A 长 4，B 离直线 OA 的高度是 3，
平行四边形面积 = 底 $\times$ 高 = $4 \times 3 = 12$ —— 和叉积的绝对值一模一样。
这就是"叉积 = 有向面积"的字面意思。

画出来看（下面是脚本的真实输出）：

```

          ·   B
             /
          ·  /
            /
          ·/
           /
      ·   O━━━━━━━━━━━━━━━A   >

          ·
```

屏幕上的 ━ 就是 O→A 这条边，/ 是 O→B，B 在 O→A 的上方 —— 也就是左侧，
所以叉积是正的。

#### 符号才是重点：转一圈看规律

把 O、A 固定住（$O = (0, 0)$、$A = (4, 0)$），让 B 待在周围八个位置，
每个位置算一次叉积：

```

      ----------------------------------------------------------
      正右边        (4, 0)                0      0   在直线上（共线）
      右上方        (3, 3)               12      +   左侧
      正上方        (0, 4)               16      +   左侧
      左上方        (-3, 3)              12      +   左侧
      正左边        (-4, 0)               0      0   在直线上（共线）
      左下方        (-3, -3)            -12      -   右侧
      正下方        (0, -4)             -16      -   右侧
      右下方        (3, -3)             -12      -   右侧
```

规律非常干净：

- $x$ 轴**上方**的点 → 叉积一律为**正**（在 O→A 左侧）
- $x$ 轴**下方**的点 → 叉积一律为**负**（在 O→A 右侧）
- 正好落在 $x$ 轴上的点 → 叉积是 **0**

这不是巧合：`cross` 的符号本来就是在回答"B 在直线 OA 的哪一边"，
而直线 OA 在这里就是 $x$ 轴，把平面切成了上下两半。

不信的话，把这块矩形里**每个整点**都算一遍看看（脚本的真实输出）：

```

      + + + + + + + + +
      + + + + + + + + +
      + + + + + + + + +
      + + + + + + + + +
      ········O━━━━━━━A━>
      - - - - - - - - -
      - - - - - - - - -
      - - - - - - - - -
      - - - - - - - - -
```

上半平面一整片 +，下半平面一整片 -，中间那一条 ━ 就是 O→A ——
几十个格点算下来，一个例外都没有。这就是"符号即左右"的字面含义。

#### 在这道题里怎么用

回到题目。闸门是**有向**的 P1 → P2，题面规定**左侧是库内**。
于是"某个点在库内还是库外"就变成一个叉积的符号问题：

```
cross(P1, P2, 那个点) > 0   ->  点在 P1→P2 的左侧  ->  库内
cross(P1, P2, 那个点) < 0   ->  点在右侧           ->  库外
cross(P1, P2, 那个点) = 0   ->  点正好落在闸门直线上
```

物品从 A 走到 C，我们分别算这两个端点：

- `d1 = cross(P1, P2, A)` —— 起点在闸门直线的哪一侧
- `d2 = cross(P1, P2, C)` —— 终点在闸门直线的哪一侧

**`d1` 和 `d2` 一正一负**，就说明物品线段的两个端点分居闸门直线两边 ——
它必然跨过了这条直线（从一边连续走到另一边，中间一定穿过）。

用样例 1 的第一条物品 $A = (1, -1) \to C = (1, 1)$ 走一遍（脚本的真实输出）：

```

  ① 物品的两个端点，在闸门直线的哪一侧？
    d1 = cross((0,0), (4,0), (1,-1))
         = (4-0)*(-1-0) - (0-0)*(1-0) = -4
       d1 = -4 < 0  ->  起点 A 在闸门直线的【右侧 = 库外】

    d2 = cross((0,0), (4,0), (1,1))
         = (4-0)*(1-0) - (0-0)*(1-0) = 4
       d2 = 4 > 0  ->  终点 C 在闸门直线的【左侧 = 库内】

       d1 和 d2 一负一正，【严格异号】 -> 物品线段跨过了闸门所在的那条直线
```

`d1 = -4 < 0`，起点在库外；`d2 = 4 > 0`，终点在库内。
一负一正，所以这条线段跨过了闸门所在的直线。方向也清楚了：**从库外走进库内，库内 +1**。

#### 为什么还要算另外两个叉积

到这里你可能觉得已经够了：跨过直线 = 穿过闸门？

**不够。** 跨过的是"闸门所在的那条**直线**"，不是"闸门这条**线段**"。
直线是无限长的，线段只有 P1 到 P2 那一小截。看这个例子：

> 物品 $(5, -1) \to (5, 1)$，交点在 $(5, 0)$。
> 它确实跨过了 $x$ 轴（`d1 = -4`、`d2 = 4`，异号），
> 但闸门只从 $x = 0$ 画到 $x = 4$，交点 $x = 5$ 跑在线段**外面**了 —— 不算穿过。

画出来是这样（脚本的真实输出）：

```

          ·

          ·   C               ┆
              ┃               ┆
      ·   P1━━━┃━━━━━━━━━━━P2   ┆   >
              ┃               ┆
          ·   A               ┆

          ·
```

左边实线那条才是真穿过，右边虚线那条就是上面说的反例 —— 它的交点跑到闸门外面去了。

挡住这种情况的，就是**反着再算一组**：

- `d3 = cross(A, C, P1)` —— 闸门起点在物品直线的哪一侧
- `d4 = cross(A, C, P2)` —— 闸门终点在物品直线的哪一侧

`d3`、`d4` 也**严格异号**，才说明闸门这条线段同样跨过了物品所在的直线。
两组条件同时成立，交点才被**夹在两条线段内部** —— 这才是"真穿过"。

上面那个反例的两组值（脚本的真实输出，注意第 3 行）：

```

      #    物品线段                   d1     d2     d3     d4  贡献
      --------------------------------------------------------------
      1    (1, -1)→(1, 1)         -4      4      2     -6  +1
      2    (3, 1)→(3, -1)          4     -4     -6      2  -1
      3    (5, -1)→(5, 1)         -4      4     10      2  +0
      4    (2, 0)→(2, 1)           0      4      2     -2  +0
      5    (2, -1)→(2, 2)         -4      8      6     -6  +1

      合计 = +1
      样例答案 = 1
      一致 ✔
```

第 3 行 `d1 = -4`、`d2 = 4` 异号（跨过了直线），但 `d3 = 10`、`d4 = 2`
**同号** —— 闸门整条都待在物品直线的同一边，交点自然跑到线段外面去了，
于是贡献是 0，正确地被排除了。

第 4 行也值得看一眼：`d1 = 0`，起点正好压在闸门直线上。
题目规定"交点是端点不算穿过"，0 不满足"严格异号"，所以也被排除 ——
**凡是端点/共线的情况，0 这个符号会自己把它们挡掉，不用额外写特判。**

#### 两个常见疑问

**"为什么不用点积？"**
点积 $A \cdot B$ = |A||B|$cos \theta$ 回答的是"两个方向有多接近"（垂直时为 0），
它算出来的是夹角信息，**分不出左右**。要判"在直线的哪一边"，只有叉积能办到。

**"为什么代码里要用 `long long`？"**
题目坐标最大到 $10^6$，两个坐标差相乘能到 $10^{12}$ 量级，`int`（约 $2 \times 10^9$）装不下。
而且易错点里提到：**千万别写 `d1 * d2 < 0`**，
两个 $10^{12}$ 量级的数相乘会到 $10^{25}$，`long long` 也会溢出 ——
要写成 `(d1 > 0 && d2 < 0) || (d1 < 0 && d2 > 0)` 这种**比较符号**的形式。

### 思路

分两步：**判断有没有"真正穿过"**，**判断穿的方向**。

**第一步：严格相交的判定。** 两条线段 AB 与 CD 严格相交（交点严格在两条线段内部）$\iff$

- C、D 严格分居直线 AB 的两侧，**且**
- A、B 严格分居直线 CD 的两侧。

"在哪一侧"用**叉积**的符号判断：

```
cross(O, A, B) = (A.x-O.x)*(B.y-O.y) - (A.y-O.y)*(B.x-O.x)
```

它的正负表示 B 在向量 OA 的左侧还是右侧，为 0 表示三点共线。

于是设：
- `d1 = cross(P1, P2, 起点)`，`d2 = cross(P1, P2, 终点)`；
- `d3 = cross(起点, 终点, P1)`，`d4 = cross(起点, 终点, P2)`。

`d1` 与 `d2` **严格异号**，且 `d3` 与 `d4` **严格异号** → 真穿过。
只要有一个为 0（端点落在对方直线上）或者同号，就不算穿过 —— 这正好对应题面"端点相交、共线重合都不算"。

**第二步：方向。** 真穿过时，起点一定**不在**闸门直线上（否则 `d1 = 0`，已经被排除了），所以 `d1 > 0` 或 `d1 < 0` 必居其一：

- `d1 > 0`：起点在 P1→P2 的**左侧 = 库内** → 这次是"出库" → 答案 **$-1$**；
- `d1 < 0`：起点在**库外** → "入库" → 答案 **+1**。

**手算例子（样例 1）**：闸门 $(0, 0) \to (4, 0)$，左侧就是 $y > 0$（库内）。

| # | 物品线段 | 是否真穿过 | 起点位置 | 贡献 |
|---|---|---|---|---|
| 1 | $(1, -1) \to (1, 1)$ | 交于 $(1, 0)$，在两条线段内部 ✓ | 库外 | +1 |
| 2 | $(3, 1) \to (3, -1)$ | 交于 $(3, 0)$，内部 ✓ | 库内 | $-1$ |
| 3 | $(5, -1) \to (5, 1)$ | 交点 $(5, 0)$ 超出闸门线段（$x \le 4$）| — | 0 |
| 4 | $(2, 0) \to (2, 1)$ | 起点在闸门直线上，交点是物品线段的端点 | — | 0 |
| 5 | $(2, -1) \to (2, 2)$ | 交于 $(2, 0)$，内部 ✓ | 库外 | +1 |

合计 $+1-1+0+0+1 = 1$ ✓（与样例输出一致，也验证了"左侧 = 库内"的方向约定没写反）。

**样例 2** 手算：闸门 $(0, 0) \to (2, 0)$。
- $(0, -1) \to (0, 1)$：交点是 $(0, 0)$，正是闸门的**端点** → 不算。
- $(-1, 0) \to (3, 0)$：与闸门**共线重合** → 不算。
合计 0 ✓。

**为什么"两组严格异号"就等于内部相交**：把直线 AB 上的点写成 $A + t(B-A)$，则 `cross(A,B,X)` 关于 X 是线性的，且 `cross(A,B,A) = cross(A,B,B) = 0`，即 $cross(A, B, A + t(B-A)) = t \cdot cross(A, B, B-A)$。C、D 严格异侧时，线段 CD 与直线 AB 的交点参数 $t$ 落于 $(0, 1)$（把 $t$ 用 C、D 的符号线性插值即得），说明**交点在线段 AB 内部**；对称地，P1、P2 严格异侧保证交点也在线段 CD 内部，而两条直线的交点唯一，所以是同一个点，即内部相交。反过来，若交点 Q 严格在 AB 内部，则直线 CD 在 Q 处把平面分成两个开半平面，A、B 分居两侧，即 `cross(C,D,A)` 与 `cross(C,D,B)` 严格异号，另一条同理。这条引理同时解释了"为什么等号（= 0）必须排除"：`cross = 0` 意味着端点在对方直线上，交点必是该端点或出现共线重合，按题面都不算穿过。方向判定则是因为叉积的符号表示点在有向直线的左/右半平面，而真穿过时起点不在闸门直线上（否则与严格异侧矛盾），所以 `d1` 的符号唯一确定起点在库内还是库外，也就唯一确定这次是"入库 +1"还是"出库 $-1$"；每条移动记录独立贡献，总和即为库内变化量。

### 参考代码

```cpp
// E - 小月的门
// 两条线段“真正相交”（交点严格落在两条线段内部）才叫穿过。
// 用叉积判断：闸门线段 P1P2 与物品线段 AC
//   d1 = cross(P1,P2,A)，d2 = cross(P1,P2,C)  -> A、C 在闸门直线异侧
//   d3 = cross(A,C,P1)，d4 = cross(A,C,P2)    -> P1、P2 在物品直线异侧
// 两个条件同时成立才是“内部相交”（等号表示端点在对方直线上，不算穿过）。
// 方向：d1 > 0 说明起点在闸门直线左侧（库内）-> 出库，答案 -1；否则 +1。
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;

// 求 (O->A) 与 (O->B) 的叉积：>0 表示 B 在向量 OA 的左侧
ll cross(ll ox, ll oy, ll ax, ll ay, ll bx, ll by) {
    return (ax - ox) * (by - oy) - (ay - oy) * (bx - ox);
}

int main() {
    int n;
    scanf("%d", &n);
    ll u1, v1, u2, v2;
    scanf("%lld %lld %lld %lld", &u1, &v1, &u2, &v2);

    ll ans = 0;
    for (int i = 0; i < n; ++i) {
        ll a, b, c, d;
        scanf("%lld %lld %lld %lld", &a, &b, &c, &d);

        ll d1 = cross(u1, v1, u2, v2, a, b);   // 起点相对闸门直线的位置
        ll d2 = cross(u1, v1, u2, v2, c, d);   // 终点相对闸门直线的位置
        ll d3 = cross(a, b, c, d, u1, v1);     // 闸门起点相对物品直线的位置
        ll d4 = cross(a, b, c, d, u2, v2);     // 闸门终点相对物品直线的位置

        // 严格异侧（不写成 d1*d2<0 是为了避免两个大数相乘溢出）
        bool sideAC = (d1 > 0 && d2 < 0) || (d1 < 0 && d2 > 0);
        bool sideP  = (d3 > 0 && d4 < 0) || (d3 < 0 && d4 > 0);
        if (!sideAC || !sideP) continue;       // 没穿过（含端点相交、共线重合等）

        if (d1 > 0) --ans;   // 起点在库内 -> 从库内穿到库外，库内 -1
        else        ++ans;   // 起点在库外 -> 穿进库内，库内 +1
    }
    printf("%lld\n", ans);
    return 0;
}
```

### 复杂度

- 时间：$O(n)$（每条记录 4 次叉积）。
- 空间：$O(1)$（不存数据，边读边算）。

### 易错点

1. **不要写 `d1 * d2 < 0`**：坐标到 $10^6$，叉积可达约 $8 \times 10^{12}$，两个相乘约 $6.4 \times 10^{25}$，**`long long` 直接溢出**，必须用"符号比较"写成 `(d1 > 0 && d2 < 0) || (d1 < 0 && d2 > 0)`。
2. **端点相交不算**：所以所有比较都要**严格**（< 0 / > 0，不能是 $\le$）。
3. **共线重合不算**：共线时 `d1 = d2 = 0`，会被严格异侧条件自动排除，不用特判。
4. **左右方向别写反**：本题坐标系是常规数学系（$y$ 轴向上），`cross(P1,P2,X) > 0` 才是左侧（库内）。写反了样例 1 会输出 $-1$ 而不是 1。
5. **起点 = 终点的退化线段**：此时 `d1 == d2`，严格异侧不成立 → 自动不算穿过，不需要特判。
6. 叉积用 `long long`；坐标读入也用 `long long`（`int` 也能存，但中间乘积必须 `long long`）。

### 题意

- 有 $n$ 种**互不相同**的非空小写字符串 $s_i$，第 $i$ 种有 $c_i$ 个（$0 \le c_i \le 10^9$）。
- $q$ 次操作，每次给一个字符串 $t$：
  - 在所有满足"$s_i$ 是 $t$ 的前缀 **且** 剩余数量 $c_i > 0$"的 $s_i$ 中，挑**最长**的那个，输出它的编号 $i$，并让 $c_i$ 减 1；
  - 不存在就输出 0（数量不减）。
- 保证所有 $s_i$ 与 $t_i$ 的长度之和 $\le 5 \times 10^5$；$n, q \le 2 \times 10^5$；内存 256 MB。

**先把"前缀"这个词说死**（题面里也专门解释了）：$s$ 的前 $k$ 个字符连起来，就是 $s$ 的第 $k$ 个前缀。
比如 `s = "abc"`，它的前缀有 3 个：`"a"`、`"ab"`、`"abc"`（空串不算，题目要非空）。
注意是**从头开始连续取**，`"bc"` 不是 `"abc"` 的前缀。

所以每次操作的三个动作，拆开就是：

| 步骤 | 要做的事 |
|---|---|
| ① 找 | 在所有 $s_i$ 里，挑出"是 $t$ 的前缀"的那些 |
| ② 筛 | 其中 $c_i > 0$ 的才要 |
| ③ 取最长 | 在这些里面挑最长的，输出编号 $i$，$c_i$ 减 1 |

第 ③ 步的"最长"两个字是本题的题眼。如果只要"随便一个前缀"，从头扫一遍遇到就返回也行；
要最长，就得**把所有候选都看一遍**或者**换个数据结构**。

### 从零讲：Trie（字典树）

#### 先看一个不用电脑也能懂的例子

假设要记三个串：$a$、ab、abc。

笨办法是抄三行：

```
a
ab
abc
```

聪明办法是"从头一样的那部分只写一次"：

```
a
 └ b
    └ c
```

变成这样一棵"往下长的树"：从最上面出发，每往下走一步就多一个字符；
走到哪里，读出来的就是哪个串。$a$、ab、abc 分别是走 1 步、2 步、3 步的结果。

**这就是 Trie（字典树 / 前缀树）**。它把"一堆字符串"按**公共开头**合并起来存。
只要两个串开头有一段一样，它们在树上就**共用同一段路**，后面的才分岔。

#### 换成"岔路口"的说法

把它想成一个迷宫：

- 最上面那个口子叫**根**，是所有人的起点，**根本身不代表任何字符**；
- 从根走一步，就是一个字符；再走一步，又是一个字符；
- 每走到一个地方，**从根到这里的整条路读出来，就是"当前这个字符串"**；
- 某个串走完了，就在停下的那个地方**立一块牌子**，牌子上写着"编号 $i$ 的串到这儿为止"。

现在看这道题：$t$ 的所有前缀是什么？

> $t$ 的第 1 个前缀 = 走 1 步的位置，第 2 个前缀 = 走 2 步的位置，……
>
> **$t$ 的所有前缀 = 沿着 $t$ 从根往下走，路上依次经过的每一个位置。**

这句话是整道题的钥匙。原来要"枚举 $t$ 的所有前缀、再挨个去和 $n$ 个 $s_i$ 比"，
现在变成**沿着 $t$ 走一遍路，看看路上哪些位置立着牌子**。走一趟只要 |$t$| 步。

**图 1**（`B-G/F/trie_figs.py` 的实跑输出，一条命令 `python trie_figs.py 1`）：把样例的三个串一个一个插进去，看树是怎么"长"出来的。
带 ★ 的是这一步**新加**的结点，没★ 的是**复用**的老结点。

```

======================================================================

  ── 第 1 步：插入 「a」（2 个） ──
     新建结点 v=1

  {根 v=0}
  └─ a ──→ ★ v=1 「a」id=1 剩2

  ★ = 这一步新建的结点；没有★的是复用的老结点。

  ── 第 2 步：插入 「ab」（1 个） ──
     v=1 已有（复用），再从 v=1 新建结点 v=2

  {根 v=0}
  └─ a ──→   v=1 「a」id=1 剩2
      └─ b ──→ ★ v=2 「ab」id=2 剩1

  ★ = 这一步新建的结点；没有★的是复用的老结点。

  ── 第 3 步：插入 「abc」（0 个） ──
     v=1、v=2 已有（复用），再从 v=2 新建结点 v=3
```

2. **牌子挂在不同的深度上**——深度 1 挂 `"a"`、深度 2 挂 `"ab"`、深度 3 挂 `"abc"`。
   所以"走得更深"就等于"前缀更长"。

#### 把树存进数组（本节最关键，请一定看完图 2 和图 3）

树是给人看的概念，程序里得用数组存。**很多人卡住就卡在这里**：
代码里只看得到 `ch[v][x] = u`、`id[v] = i`、`cnt[i]--` 这些数组操作，
脑子里浮现不出树在怎么变。下面就是把这两边钉死。

先看要存什么。一棵树只有三种信息：

| 信息 | 用什么存 | 一句话解释 |
|---|---|---|
| 从某个位置出发、走某个字符、能到哪 | `ch[v][x]` | 一个格子 = 一条边 |
| 哪些位置立着牌子、牌子写的是几号 | `id[v]` | 一个格子 = 一个位置上的牌子 |
| 每块牌子对应的串还剩几个 | `cnt[i]` | 一个格子 = 一种串的库存 |

##### `ch[v][x]`：结点 $v$ 的字符 $x$ 儿子是谁

```cpp
int ch[MAXN][26];    // ch[v][x]：编号为 v 的位置，沿字符 x 走一步，到哪个位置
                     // x 是 0..25，分别对应 'a'..'z'；值是 0 用来看作"没有这条路"
```

- 第一个下标 $v$ 是**你现在站在哪**（结点编号）；
- 第二个下标 $x$ 是**你想走哪个字符**；
- 存的值是**走完到哪儿**（下一个结点编号）。

所以 `ch[2]['c'] = 3` 这句话，翻译成人话就是：

> 站在 2 号位置，走一步 `'c'`，就来到了 3 号位置。

**图 2**（`python trie_figs.py 2` 的实跑输出）：上半是 ch 表，中间是它唯一决定的那棵树，下半再把格子和边一条条对上。

> 左边表里的**每一个非零格子**，就是右边树上**一条实实在在的边**。

反过来也成立：树上每多一条边，数组里就多一个非零格子。
**树变了，数组就变；数组动了，树就动。它们是同一个东西的两种画法。**

##### `id[v]`：牌子挂在哪个位置

```cpp
int id[MAXN];        // id[v] = 在 v 号位置结束的那种串的编号；0 表示这个位置没挂牌子
```

注意**下标是结点编号 $v$，不是字符串编号**。
`id[2] = 3` 的意思是："3 号串走完的时候停在 2 号位置，所以 2 号位置上挂着 3 号牌。"

所以插入 $s_i$ 的最后一步永远是这一行：

```cpp
id[v] = i;           // v 是走完整个 s_i 之后停下的那个结点
```

##### `cnt[i]`：每块牌子还剩几个

```cpp
int cnt[MAXN];       // cnt[i] = 第 i 种字符串还剩几个
```

这一张表的**下标又换回字符串编号了**，和 `id` 不是一回事——这是本题最容易混的地方。

- `id[v]`：给你一个**位置**，问"这儿挂的是几号牌"；
- `cnt[i]`：给你一个**编号**，问"这种串还剩几个"。

要查"$v$ 号位置上的牌子还剩几个"，得先 `id[v]` 拿到编号，再 `cnt[id[v]]`。
代码里那行 `if (id[v] && cnt[id[v]] > 0)` 就是这两个查表串起来的。

**图 3**（`python trie_figs.py 3` 的实跑输出）：把 $v=2$ 上那块牌子放大，看它是怎么由 `id` 和 `cnt` 拼出来的。

##### 一句话对照表（记不住就回来看这张）

| 代码 | 树上发生的事 |
|---|---|
| `if (!ch[v][x]) ch[v][x] = ++tot;` | 树上还没有"从 $v$ 走 $x$"这条路 → 新长出一个结点，把这条边接上 |
| `v = ch[v][x];` | 沿着这条边走过去（"我现在站在 $v$ 了"） |
| `id[v] = i;` | 在 $v$ 这个位置立一块牌子，写着 $i$ |
| `cnt[i] = c;` | 给 $i$ 号牌子的库存记上 $c$ |
| `if (id[v] && cnt[id[v]] > 0)` | 这个位置立着牌子，且那块牌子还有货 |
| `best = id[v];` | 记住这块牌子的编号（越走越深，直接覆盖就是"最长"） |
| `--cnt[best];` | 那本库存册上 `best` 那一格减 1 |

### 手算

样例 1：

```
3 5
a 2
ab 1
abc 0
abc
abc
ax
a
b
```

也就是说：$s_1$ = "$a$"（2 个），$s_2$ = "ab"（1 个），$s_3$ = "abc"（0 个）。5 次操作，我们一次一次走。

| 第几次 | $t$ | $t$ 的前缀都有谁 | 哪个是 $s_i$ 且还有货 | 最长的是 | 输出 | 用掉之后 |
|---|---|---|---|---|---|---|
| 1 | abc | $a, ab, abc$ | $a$(还有 2)、ab(还有 1)；abc 有 0 个 | ab | **2** | $c_2$ 变 0 |
| 2 | abc | $a, ab, abc$ | 只剩 $a(2)$ 有货 | $a$ | **1** | $c_1$ 变 1 |
| 3 | ax | $a, ax$ | $a(1)$ 有货；ax 根本不在名单里 | $a$ | **1** | $c_1$ 变 0 |
| 4 | $a$ | $a$ | $a$ 有 0 个了，没货 | 无 | **0** | 不减 |
| 5 | $b$ | $b$ | $b$ 不在名单里 | 无 | **0** | 不减 |

输出 2 1 1 0 0，和样例一致。

**关键在于第 3 次**：`t = "ax"`，它的前缀是 `"a"` 和 `"ax"`。
`"ax"` 不是任何一个 $s_i$，但它"排在 $a$ 后面"——$a$ 依然是合法答案。
所以"走到某个字符走不下去"时，**前面已经找到的答案要留下来**，不能整个作废。

**手动做这题慢在哪**：每次都要把 $n$ 个 $s_i$ 都拿出来比对。$t$ 的前缀有 |$t$| 个，
每个都去和 $n$ 个串比，单次 O(n × |$t$|)。$n = q = 2 \times 10^5$ 时稳稳超时。

### 思路

#### 插入过程：逐字看数组怎么动

下面是 `trie_visual.py` 的**真实输出**（`python trie_visual.py` 跑出来的）。
为了让图不至于太长，这里只截最关键的几步。

**一开始**：只有一个光杆树根，编号 0。

```
  {根 v=0}

  （空树：ch[0] 整行都是 0）

  id[v]  : id[0]=0
```

**插入 $s_1$ = "$a$"（2 个）**：

```
  插入 「a」（编号 1，库存 2）：
    第 1 个字符 'a'：ch[0]['a'] 是 0 --> 新建结点 v=1，停在 v=1
    走完了 --> 在停下的结点 v=1 上挂编号：id[1] = 1

  {根 v=0}
  └─ a ──→   v=1 「a」id=1 剩2

  ch[0]         1
  ch[1]         0

  id[v]  : id[0]=0  id[1]=1
  cnt[i] : cnt[1]=2
```

对照「把树存进数组」那一节：`ch[0]['a']` 从 0 变成 1，树上就多了一条从根出发、标着 $a$、指向 1 号结点的边。
`id[1] = 1`，1 号结点上就多了一块写着 1 的牌子。

**插入 $s_2$ = "ab"（1 个）**：

```
  插入 「ab」（编号 2，库存 1）：
    第 1 个字符 'a'：ch[0]['a'] 已经是 1 --> 复用老结点，停在 v=1
    第 2 个字符 'b'：ch[1]['b'] 是 0 --> 新建结点 v=2，停在 v=2
    走完了 --> 在停下的结点 v=2 上挂编号：id[2] = 2

  {根 v=0}
  └─ a ──→   v=1 「a」id=1 剩2
      └─ b ──→   v=2 「ab」id=2 剩1

              'a'   'b'
  ch[0]         1     0
  ch[1]         0     2
  ch[2]         0     0

  id[v]  : id[0]=0  id[1]=1  id[2]=2
  cnt[i] : cnt[1]=2  cnt[2]=1
```

**插入 $s_3$ = "abc"（0 个）之后，树就齐了**：

```
  {根 v=0}
  └─ a ──→   v=1 「a」id=1 剩2
      └─ b ──→   v=2 「ab」id=2 剩1
          └─ c ──→   v=3 「abc」id=3 剩0

              'a'   'b'   'c'
  ch[0]         1     0     0
  ch[1]         0     2     0
  ch[2]         0     0     3
  ch[3]         0     0     0

  id[v]  : id[0]=0  id[1]=1  id[2]=2  id[3]=3
  cnt[i] : cnt[1]=2  cnt[2]=1  cnt[3]=0
```

**注意这三件事**（以后读代码就靠它们）：

1. `ch` 有三行非零（`ch[0]['a']=1`、`ch[1]['b']=2`、`ch[2]['c']=3`），树上正好三条边；
2. 编号**从 1 开始发**，0 永远是根。看最后一行 `ch[3]` 全是 0 —— 3 号结点是条死路（"abc" 走到头了）；
3. `ch[v]['a']` 那一列里，只有 `ch[0]` 是 1，别的位置都是 0 —— 而且**别的位置也确实不该有**，
   因为只有根才有 `'a'` 这个儿子。

**为什么 `ch` 开 26 列而不是"用多少开多少"**：因为这题限定小写字母，26 是个很小的常数。
`ch[v][x]` 一次寻址就是 $O(1)$，写起来最简单。想省内存才用 `map` 或链表挂儿子，本题不需要。

#### 查询过程：沿 $t$ 往下走

查询的写法就三句话：

1. 从根出发，$v = 0$，答案 `best = 0`；
2. 一个字符一个字符往下走。每走到一个结点，就问它一句：
   **"这儿挂着牌子吗？挂着的话，那块牌子的货还剩吗？"** 都满足，就把 `best` 改成这个编号；
3. 某个字符走不通了，**直接跳出**——因为更长的前缀都要经过这个不存在的结点，更不可能存在。

第 2 步里**不需要比较长度**：从根往下走是越走越深的，所以**后遇到的牌子一定挂在更深处、
对应的串一定更长**。直接用新的覆盖旧的，剩下的自然就是最长的。

### 参考代码

```cpp
// 牛客周赛 Round 163 F - 小月的前缀
// 做法：把所有 s_i 插进一棵 Trie；查询时沿 t 往下走，边走边记"最深且还有货"的那种串。
#include <bits/stdc++.h>
using namespace std;

// 结点总数 = 所有 s_i 的长度之和 + 1（根）<= 5*10^5 + 1，所以开 500005 富余
const int MAXN = 500005;

int ch[MAXN][26];   // ch[v][x] = 结点 v 沿字符 x（0..25 对应 'a'..'z'）走到的儿子；0 表示没有这条路
int id[MAXN];       // id[v] = 在结点 v 结束的那种字符串的编号；0 表示没有串在这里结束
int cnt[MAXN];      // cnt[i] = 第 i 种字符串还剩几个（注意下标是"字符串编号"，不是结点编号）

int main() {
    ios::sync_with_stdio(false);   // 关掉 cin 与 scanf 的同步，读入快很多
    cin.tie(nullptr);              // 解绑 cout，避免每次 cin 都冲一次输出缓冲

    int n, q;
    cin >> n >> q;

    int tot = 0;                   // 已经开出多少个结点；根固定是 0 号，从 1 开始分配新结点
    string s;
    for (int i = 1; i <= n; ++i) {         // 字符串编号从 1 开始，0 号留给"没有"
        int c;
        cin >> s >> c;
        cnt[i] = c;                        // 先记下这种串的库存

        int v = 0;                         // v 是"我现在站在哪个结点"，从根出发
        for (char cc : s) {                // 一个字符一个字符往下走
            int x = cc - 'a';              // 把字符翻译成 0..25 的列号
            if (ch[v][x] == 0) {           // 这条边还不存在 → 新开一个结点
                ch[v][x] = ++tot;          // 新结点编号 = tot + 1；同时把这条边接上
            }
            v = ch[v][x];                  // 走到儿子去
        }
        id[v] = i;                         // 整串走完，停在 v：把编号牌挂在 v 上
    }

    string t;
    for (int qi = 0; qi < q; ++qi) {
        cin >> t;

        int v = 0;                         // 从根出发
        int best = 0;                      // 目前找到的最长合法前缀的编号；0 = 还没找到
        for (char cc : t) {
            int x = cc - 'a';
            if (ch[v][x] == 0) break;      // 这条路不存在 → 再走只会更长的前缀更不可能存在，直接停
            v = ch[v][x];                  // 走到下一个前缀对应的结点
            if (id[v] && cnt[id[v]] > 0) { // 这里挂着牌子，并且还有货
                best = id[v];              // 越走越深，所以后来者一定更长，直接覆盖即可
            }
        }

        cout << best << '\n';              // 输出答案
        if (best) --cnt[best];             // 用掉一个（best = 0 时什么都不减）
    }
    return 0;
}
```

**几个容易看不懂的地方，单独拎出来说**：

- `ch[v][x] = ++tot;` 这一行干了三件事：把 `tot` 加 1、把新编号写进 `ch[v][x]`、让 `v = ch[v][x]` 时能走到新结点。
  写成两句就是 `++tot; ch[v][x] = tot;`，一模一样。
- `for (char cc : s)` 是范围 for，等价于按顺序遍历 $s$ 里的每个字符；
  写成 `for (int k = 0; k < (int)s.size(); ++k)` 用 `s[k]` 也一样。
- `cnt[id[v]] > 0` 是**两层查表**：先用 $v$ 查 `id`（这儿挂的是几号牌），再用那个编号查 `cnt`（还剩几个）。
  这两个数组的下标不一样，是本题最容易写错的地方。
- `if (best) --cnt[best];` 里的 `if (best)` 不能省：`best = 0` 表示"没找到"，此时**什么都不该减**。

### 复杂度

- **时间**：插入一个串是 |$s_i$| 步，查询一次是 |$t_i$| 步，每步都是 $O(1)$（因为字母表固定 26）。
  总量就是题目给的 $\sum$|$s_i$| + $\sum$|$t_i$| $\le 5 \times 10^5$，跑得飞起。
- **空间**：`ch` 是 $500005 \times 26 \times 4$ 字节 ≈ 52 MB，`id` 和 `cnt` 各约 2 MB。
  一共约 56 MB，题目给了 256 MB，安全。
- **结点数上界**：最坏情况是"所有串都完全不共享前缀"，此时每个字符都新开一个结点，
  所以 **结点数 $\le$ 总长度 + 1（根）$\le 500001$**。这就是 `MAXN = 500005` 的来源。

**顺带算一个题外话**：题面写 $n \le 2 \times 10^5$，但因为"$s_i$ 互不相同" + "总长 $\le 5 \times 10^5$"这两条卡着，
$n$ 其实根本到不了 20 万。1 位的串最多 26 个、2 位的最多 676 个、3 位的最多 17576 个，
把这些吃干净用掉 54106 个字符、拿到 18278 个串；剩下的预算只够开 4 位串，每个 4 个字符，
还能再塞 $(5 \times 10^5 - 54106) / 4 \approx 111473$ 个。加起来 $n$ 最多也就 **12.9 万左右**。
（这不是解题必需的，只是提醒你别一看到 $2 \times 10^5$ 就按"20 万个串长度 1"去想。）

### 易错点

1. **新结点编号从 0 开始发** —— 错。
   0 号是根，同时还兼任"没有这个儿子"的空指针哨兵（`ch` 里存 0 就表示没边）。
   新结点必须 `++tot`，从 1 开始，否则新结点会和根、和"没有边"混淆。
   *做法*：永远写 `ch[v][x] = ++tot;`，不要写 `ch[v][x] = tot++;`。

2. **找到第一个合法前缀就 `break`** —— 错。
   题目要的是**最长**，不是**最先找到**。路径是从浅到深走的，
   所以正确做法是"每遇到一个合法牌子就覆盖 `best`"，让最后一次覆盖胜出。
   *自检*：样例 1 第 1 次操作，如果你在 $a$ 那里就停下，会输出 1，答案是 2。

3. **把 `cnt` 和 `id` 的下标搞混** —— 错，而且是本题最经典的错。
   `id[v]` 的下标是**结点编号**，`cnt[i]` 的下标是**字符串编号**。
   写成 `cnt[v]` 就完全歪了（$v$ 是位置，$i$ 是编号，两者毫无关系）。
   *记住*：查询时永远是 `cnt[id[v]]`，两层查表。

4. **数组按 $n$ 开**（比如 `ch[200005][26]`）—— 错。
   结点数只和**所有字符串的总长度**有关，和 $n$ 无关。
   一个长度 $5 \times 10^5$ 的串就能开出 $5 \times 10^5$ 个结点，按 $n$ 开必越界。

5. **$c_i$ 用 `int` 存** —— 这个是对的。
   $10^9 < 2^{31} - 1 \approx 2.1 \times 10^9$，`int` 装得下。
   但如果你把题目改成 $c_i \le 10^{10}$，就必须换 `long long` —— 心里要清楚这条边界在哪。

6. **读入用 `cin` 但不关同步** —— 会慢。
   $n, q$ 各到 $2 \times 10^5$、总长 $5 \times 10^5$，量不算大，但要养成习惯：
   `ios::sync_with_stdio(false); cin.tie(nullptr);` 放在 `main` 开头。
   （另外**别混用 `scanf` 和 `cin`**：部分 MinGW / UCRT64 工具链的 g++ 有实测过的怪癖，混用时后面那个会静默读到空——不报错、不崩，但读进来是空的；牛客评测机不复现这个问题，可本地调不出结果时会白白怀疑算法，所以本节代码统一只用 `cin` / `cout`。）

7. **插入结束时忘了 `id[v] = i`，或者挂错结点** —— 错。
   牌子挂在**整串走完停下的那个结点**上，不是中间某个结点。
   `"abc"` 只有走完 $c$ 之后停在的 $v=3$ 才有牌，$v=1$（只有 $a$）上挂的是别人（`"a"`）的牌。

8. **查询完忘了减库存，或者无脑减** —— 错。
   必须是 `if (best) --cnt[best];`：找到才减，没找到（`best = 0`）时**一个都不能减**。
   另外减的是 `cnt[best]`（编号 `best` 那种串），不是 `cnt[v]`。

9. **把 `ch[v][x]` 写成 `ch[x][v]`** —— 编译能过、样例大概率也能过，然后错得莫名其妙。
   记住第一个下标是"站在哪"，第二个是"走哪个字符"。看图 2 就不会写反。

## G. 小月的环

### 题意

- 有 $n$ 个房间，传送门用排列 $p$ 表示：从房间 $i$ 能到房间 $p_i$。
- **同一组** = 能通过传送门互相到达的房间。这正是"置换的**环**"：把 $i \to p_i \to p_{pi} \to \ldots$ 走一圈，经过的房间就是一组。
- 对整数 $i$，说它**「穿过」**一组房间 $\{a_1, \ldots, a_m\}$，当且仅当 $\min(a_1..a_m) \le i < \max(a_1..a_m)$（**左闭右开**！单点组永远不会被穿过）。
- $w_i$ = 整数 $i$ 穿过的组数（$i$ 取 $0..n$）。
- 区间 $[l, r]$ **「包含」**一组，当且仅当 $l \le \min$ 且 $\max \le r$。
- $s(l, r)$ = 区间 $[l, r]$ 包含的组数。
- 求满足 $w_{l-1} + w_r = k$ 且 $s(l, r) \ge t$ 的区间 $[l, r]$（$1 \le l \le r \le n$）的**个数**。

题面保证 $0 \le k, t \le n$。

### 思路

**第 1 步：把一个"组"压缩成两个数。**
后面的所有条件只用到每组的 `min` 和 `max`，所以每个环只要算出这两个值：沿 $p$ 走完整个环，边记录最小值最大值。于是"一组" = "一个闭区间 [mn, mx]"。

**第 2 步：算 $w$（前缀和/差分）。**
$w_i = \#${组 $: mn \le i < mx$} —— 就是"有多少个区间覆盖了点 $i$"，经典差分：
对每组做 `diff[mn] += 1; diff[mx] -= 1;`，然后前缀和，得到 `w[0..n]`。
注意 $w_0 = 0$（$mn \ge 1$，没人能穿过 0），$w_n = 0$（$i = n$ 时 `i < mx` 不可能）。

**第 3 步：换字母，把两个条件写成只与两个下标有关。**
令 $L = l-1$（$0 \le L \le n-1$），$R = r$（$1 \le R \le n$，且 L < R）：

- 条件一：$w_L + w_R = k$；
- 条件二：#{组 : mn > L 且 mx ≤ R} ≥ t。
  （因为 $l \le mn$ 就是 $mn \ge L+1$，也就是 `mn > L`；$mx \le r$ 就是 $mx \le R$。）

**第 4 步（全题最关键的转化）：固定 R，合法的 L 是一段前缀。**
先只看条件二。固定 R 之后，"已完成"的组就是那些 $mx \le R$ 的组。在这些组里数 `mn > L` 的个数，记作 $f(L)$。
L 变大（左端点右移）时，满足 `mn > L` 的组只会变少，所以

> $f(L)$ 关于 L 单调不增 $\Rightarrow$ 满足 $f(L) \ge t$ 的 L 是 0, 1, …, P 这样一段**前缀**。

P 怎么算？把已完成组的 `mn` 从大到小排：$m_1 \ge m_2 \ge \ldots\ge m_c$。要凑够 $t$ 个组，就需要 $L < m_t$（第 $t$ 大的那个 `mn`），即

> $L \le m_t - 1$，再和 $L \le R-1$ 取最紧的：$P = \min(R-1, m_t - 1)$。

如果已完成的组数 $c < t$，说明 $f(L)$ 永远凑不够 $t$，这个 R 直接跳过。
特判 $t = 0$：此时 $s(l, r) \ge 0$ 恒成立，只剩 $P = R-1$。

**第 5 步：统计。**
固定 R 时，条件一需要 $w_L$ 恰好等于 $k - w_R$。于是：
把每个取值 $v$ 对应的所有 L 收集成有序数组 `pos[v]`（L 从小到大扫一遍天然有序），答案加上"$pos[k - w_R]$ 中 $\le P$ 的个数"，一次 `upper_bound` 即可。

**第 6 步：让 R 扫起来，动态维护"第 $t$ 大的 `mn`"。**
R 从 1 到 $n$ 递增，每当 R 增大，就把所有 `mx = R` 的组加进结构里（按 `mx` 分桶即可）。
需要支持"查询当前集合中第 $t$ 大的数"→ 用**树状数组**统计 `mn` 的分布（值域 $1..n$），第 $t$ 大 = 第 $c - t + 1$ 小，在树状数组上二分 $O(\log n)$。

**手算例子（样例 1）**：$n = 5$，$p = 2 1 4 5 3$，$k = 1$，$t = 1$。
环：1→2→1 得组 {1,2}（`mn=1, mx=2`）；3→4→5→3 得组 {3,4,5}（`mn=3, mx=5`）。

$w$：$w_0=0$；$w_1 = 1$（组 {1,2} 覆盖 $i=1$）；$w_2 = 0$；$w_3 = 1$；$w_4 = 1$；$w_5 = 0$。
即 `w = [0,1,0,1,1,0]`。

逐个 R 走一遍：

| R | 已完成的组（mn） | 第 $t=1$ 大的 mn | $P = \min(R-1, m_1-1)$ | 需要 $w_L = 1 - w_R$ | 数到的 L | 新增 |
|---|---|---|---|---|---|---|
| 1 | 无 | — | 凑不齐 1 组 → 跳过 | | | 0 |
| 2 | {1} | 1 | $\min(1, 0) = 0$ | $1 - 0 = 1$ | L=0 时 $w=0$ ✗ | 0 |
| 3 | {1} | 1 | $\min(2, 0) = 0$ | $1 - 1 = 0$ | L=0 时 $w=0$ ✓ | 1（[1,3]）|
| 4 | {1} | 1 | $\min(3, 0) = 0$ | $1 - 1 = 0$ | L=0 ✓ | 1（[1,4]）|
| 5 | {1}, {3} | 3 | $\min(4, 2) = 2$ | $1 - 0 = 1$ | L=1 时 $w=1$ ✓（L=2 时 $w=0$ ✗）| 1（[2,5]）|

合计 **3** ✓，与样例说明给出的 [1,3], [1,4], [2,5] 完全一致。

**样例 2** 的直觉：$p = 1 2 3 4 \to$ 四个单点组，`mn = mx`，所以所有 $w_i = 0$，$k = 0$ 自动满足；$t = 2$ 要求区间里至少装下 2 个单点组，即长度 $\ge 2$，$C(4, 2) = 6$ ✓。

**为什么这样统计不重不漏**：置换的每个环内部任意两点互相可达（沿 $p$ 一直走），不同环之间不可达（$p$ 是双射，出的边不跨环），所以"极大互相可达组"就是环，第 1 步的构造是对的；`diff[mn] += 1, diff[mx] -= 1` 的前缀和等于 #{组 $: mn \le i < mx$}（区间加 1、点查询的标准差分），故 $w_i$ 正确。固定 R 时 $f(L) = \#${组 $: mx \le R, mn > L$}：若 $L_1 \le L_2$ 则 $\{mn > L_2\} \subseteq \{mn > L_1\}$，所以 $f$ 单调不增，$\{L : f(L) \ge t\}$ 必然是 [0, P] 这样一段前缀（也可能为空）；把已完成组的 `mn` 降序排成 $m_1 \ge m_2 \ge \ldots\ge m_c$，$f(L) \ge t$ 就等价于第 $t$ 大的 $m_t > L$，即 $L \le m_t - 1$，再和 $L \le R-1$ 取最紧的得到 P（$c < t$ 时无解，$t = 0$ 时条件恒真、$P = R-1$）。每个区间 $[l, r]$ 与 $(L, R) = (l-1, r)$ 一一对应，R 从 1 到 $n$ 枚举覆盖了全部区间，固定 R 时算法恰好统计了 [0,P] 中所有 $w_L = k - w_R$ 的 L，正是满足两个条件的全部 L。

### 参考代码

```cpp
// G - 小月的环
// 每个置换环（组）只关心它的最小值 mn 和最大值 mx：
//   w_i  = 满足 mn <= i < mx 的组数        （i 在 [mn, mx-1] 里都“穿过”这一组）
//   s(l,r) = 满足 l <= mn 且 mx <= r 的组数
// 令 L = l-1，条件变成：w_L + w_R = k 且 #{组 : mn > L, mx <= R} >= t
// 固定 R 时，把 mx <= R 的组按 mn 从大到小排，第 t 大的 mn 记作 m_t，
// 则 #{mn > L} >= t  <=>  L <= m_t - 1，也就是 L 的合法上界。
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, k, t;
    scanf("%d %d %d", &n, &k, &t);
    vector<int> p(n + 1);
    for (int i = 1; i <= n; ++i) scanf("%d", &p[i]);

    vector<int> diff(n + 2, 0);              // 差分数组，用来求 w
    vector<vector<int>> byMax(n + 1);        // byMax[R] = 所有 mx == R 的组的 mn
    vector<char> vis(n + 1, 0);

    for (int i = 1; i <= n; ++i) {
        if (vis[i]) continue;
        int cur = i, mn = i, mx = i;         // 顺着传送门走完整个环
        while (!vis[cur]) {
            vis[cur] = 1;
            mn = min(mn, cur);
            mx = max(mx, cur);
            cur = p[cur];
        }
        diff[mn] += 1;                       // 这组让 w[mn..mx-1] 各 +1
        diff[mx] -= 1;
        byMax[mx].push_back(mn);             // 当 R 增长到 mx 时，这组开始计入 s
    }

    vector<int> w(n + 1, 0);
    int run = 0;
    for (int i = 0; i <= n; ++i) {           // w[0] = 0（mn >= 1，没有组能穿过 0）
        run += diff[i];
        w[i] = run;
    }

    // pos[v] = 所有满足 w[L] == v 的 L，数组天然有序，方便二分
    vector<vector<int>> pos(n + 1);
    for (int L = 0; L <= n; ++L) pos[w[L]].push_back(L);

    // 树状数组：统计“已完成”的组的 mn 分布，支持查询第 k 小
    vector<int> bit(n + 1, 0);
    auto add = [&](int i) { for (; i <= n; i += i & -i) ++bit[i]; };
    auto kth = [&](int kk) {                 // 返回第 kk 小的 mn（kk 从 1 开始）
        int mask = 1;
        while ((mask << 1) <= n) mask <<= 1;
        int idx = 0;
        for (int d = mask; d; d >>= 1) {
            int nxt = idx + d;
            if (nxt <= n && bit[nxt] < kk) { idx = nxt; kk -= bit[nxt]; }
        }
        return idx + 1;
    };

    long long ans = 0;
    int finished = 0;                        // 目前 mx <= R 的组数
    for (int R = 1; R <= n; ++R) {
        for (int mn : byMax[R]) { add(mn); ++finished; }

        int P;                               // L 的上界：L <= R-1 且 L <= m_t - 1
        if (t == 0) {
            P = R - 1;                       // s >= 0 恒成立，只剩 L <= R-1
        } else if (finished >= t) {
            int mt = kth(finished - t + 1);  // 第 t 大的 mn = 第 (finished-t+1) 小的 mn
            P = min(R - 1, mt - 1);
        } else {
            P = -1;                          // 连 t 组都凑不齐
        }
        if (P < 0) continue;

        int need = k - w[R];                 // 需要 w[L] 等于它
        if (need < 0 || need > n) continue;
        const vector<int>& v = pos[need];
        ans += upper_bound(v.begin(), v.end(), P) - v.begin();   // 数出 L <= P 的个数
    }

    printf("%lld\n", ans);
    return 0;
}
```

### 复杂度

- 时间：找环 $O(n)$；差分求 $w O(n)$；每个 R 一次树状数组查询 $O(\log n)$、一次二分 $O(\log n)$，共 $O(n \log n)$。
- 空间：$O(n)$（$w$、分桶、`pos`、树状数组）。

### 易错点

1. **读题第一坑**：$i$ "穿过"一组的条件是 $\min \le i < \max$（**左闭右开**），而区间"包含"一组的条件是 $l \le \min$ 且 $\max \le r$（**闭区间**）。两个不等号方向不一致，很容易抄错，一错就全错。
2. **$w$ 的下标范围是 $0..n$**，别只算 $1..n$；$w_0 = 0$ 是合法取值（很多区间以 $l = 1$ 开头，用到的正是 $w_0$）。
3. **`mn > L` 不是 $mn \ge L$**：因为 $l = L + 1$，$l \le mn$ 即 $mn \ge L+1$ 即 `mn > L`。差一位，样例都过不了，但很可能过掉小的手造数据。
4. **$t = 0$ 要特判**，否则会去查"第 0 大"导致 `kth(0)` 行为异常。
5. **答案要 `long long`**：区间总数可达 $n(n+1)/2 \approx 2 \times 10^{10}$。实测 $n = 2 \times 10^5$、全为单点组、$k=0, t=100000$ 的用例答案为 5000150001。
6. **单点组（自环）的特殊性**：它永远不被任何 $i$ 穿过（对 $w$ 无贡献，因为 `mn = mx` 时 $mn \le i < mx$ 无解），但它**算 $s$**（只要区间包含它）。这一点想清楚，样例 2 就通了。
7. 树状数组的值域开 $n$（$mn \le n$），二分时的最高位掩码从不超过 $n$ 的最大 2 的幂开始。
