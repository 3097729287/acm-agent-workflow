## 1. 一句话说清这个写法

把 Bob 的"临场应对"**换成一个开局就固定的排列**，问题就退化成：

> **Alice 赢 ⟺ 不存在任何一组"全互质"的完整配对。**

代码只要做一件事：枚举 a 的排列、再枚举 b 的排列，看有没有哪一组配对里
**每一对都互质**（`gcd == 1`）。

- 找到这样一组 → Bob 能躲 → 输出 Bob
- 720 种 a 的排列都找不到 → 输出 Alice

```cpp
sort(a.begin(), a.end());
do {
    sort(b.begin(), b.end());
    do {
        bool has_block = false;
        for (int i = 0; i < n; i++)
            if (gcd(a[i], b[i]) > 1) { has_block = true; break; }
        if (!has_block) { cout << "Bob"; return 0; }   // 这组全互质
    } while (next_permutation(b.begin(), b.end()));
} while (next_permutation(a.begin(), a.end()));
cout << "Alice";
```

## 2. 它凭什么是对的（本题最关键的一步推理）

先明确游戏规则里容易读漏的两点：

1. **Alice 先出，Bob 看到她出的牌之后再出**；
2. **每张牌只会被打出一次**，一共打 n 轮。

### 2.1 Bob 的"照单对接"策略

假设存在一个 b 的排列 P = (p<sub>1</sub>, …, p<sub>n</sub>)，使得把 a 按某个顺序摆成 (x<sub>1</sub>, …, x<sub>n</sub>) 后，
gcd(x<sub>i</sub>, p<sub>i</sub>) == 1 对每个 i 都成立。

那么 Bob 可以这样打：**开局就在心里固定 P**（不必真的亮出来），
Alice 每出一张牌，Bob 就打出 P 里与它配成一对的那张。

- 因为 Alice 的牌不会重复用，Bob 配对的那张牌在那一刻一定还在手里；
- 配对是 `gcd == 1`，所以这一轮不会让 Alice 获胜。

于是 **n 轮全部打完，Alice 一张都没赢 → Bob 获胜**。

> 这就是"排列"的物理含义：**Bob 的排列 = 他给 Alice 的每张牌预先指定好的对手。**

### 2.2 反过来：找不到全互质配对，Alice 就赢

如果对 Alice 的**每一种**出牌顺序，都不存在全互质的完整配对，
那 Bob 无论怎么应对，都必然在某一轮被迫打出与 Alice 那张 `gcd > 1` 的组合 ——
（n 轮打完时，双方各自打出的牌恰好构成一个完整的配对关系；只要这个配对里有一对 `gcd > 1`，
Alice 在那一轮就已经赢了）。

所以：

```
Alice 赢  ⟺  对 a 的每个排列，都不存在「每对都互质」的完整配对
Bob   赢  ⟺  存在一个 a 的排列，它有一种「每对都互质」的完整配对
```

这就是代码里双重排列枚举的全部理由。

### 2.3 一个容易想歪的地方

> "Bob 能看到牌、能临场改主意，凭什么用一个固定排列就够了？"

因为**这一招是充分条件**：固定排列只是一种特殊的策略，它能让 Bob 赢，说明 Bob 至少有一招能赢。
而我们只需要判断"Bob 有没有一招能赢"。
至于 Bob 用不用这招、会不会玩得更花，不影响结论。

> 另一个容易想歪的地方：**"打出来的顺序"和"排列"不是一回事。**
> 排列 (x<sub>1</sub>, …, x<sub>n</sub>) 只是"把哪几张牌配成对"，具体谁先打无所谓。
> 代码里对 a 排一遍、对 b 排一遍，就是把"所有可能的配对方式"全部过一遍。

## 3. 手算两个例子，把判据摸熟

### 例 A：a = {2, 3}，b = {2, 3} → **Bob 赢**

先列出所有配对（只看 `gcd`）：

| a ＼ b | 2 | 3 |
|---|---|---|
| **2** | 2 | 1 |
| **3** | 1 | 3 |

找"每对都互质"的配对：
- 配对 (2, 3) 和 (3, 2)：两个 `gcd` 都是 1 ✅

存在这样的配对，所以 Bob 赢。实打一遍：
Alice 出 2 → Bob 用配对的 3 顶住（`gcd(2,3)=1`）；Alice 出 3 → Bob 出 2（`gcd(3,2)=1`）。Alice 一次都没赢。

### 例 B：a = {2, 4}，b = {3, 6} → **Alice 赢**

| a ＼ b | 3 | 6 |
|---|---|---|
| **2** | 1 | 2 |
| **4** | 1 | 2 |

- 4 只能配 3（`gcd(4,6)=2` 不行），那么 2 只剩 6 配（`gcd(2,6)=2` 不行）❌
- 2 配 3（可以），4 配 6（不行）❌

**两种配对方式都做不到"全互质"**，所以 Alice 赢。实打一遍：
Alice 出 2 → Bob 不用 3 就当场输（`gcd(2,6)=2`），所以 Bob 只能出 3；剩 4 和 6，`gcd(4,6)=2` → Alice 赢。

### 例 C：a = {6, 12}，b = {5, 7} → **Bob 赢**

`gcd(6,5)=1, gcd(12,7)=1`，配对 (6,5),(12,7) 全互质 → Bob 赢。
（注意：这个例子里 **每对 gcd 都不大**，但结论是 **Bob** 赢 —— 判据是"存在全互质配对"，不是"存在 gcd>1 的对"。）

### 官方样例 3 验一遍

a = {3,8,5,2,4}，b = {6,9,10,7,2}，答案 Alice。配对表（1 表示互质）：

| a ＼ b | 6 | 9 | 10 | 7 | 2 |
|---|---|---|---|---|---|
| 3 | | | 1 | 1 | 1 |
| 8 | | 1 | | 1 | |
| 5 | 1 | 1 | | 1 | 1 |
| 2 | | 1 | | 1 | |
| 4 | | 1 | | 1 | |

试着找全互质配对：3-10、8-9、5-6、2-7、4-? —— 4 只剩 9、7，都被占了 ❌；
换 8-7、4-9、2-? —— 2 也只剩 9、7 ❌。
**怎么排都凑不齐**，所以 Alice 赢，和样例一致。

## 4. 代码逐行

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    if (!(cin >> n)) return 0;
    vector<int> a(n), b(n);
    for (auto &c : a) cin >> c;          // 读 Alice 的牌
    for (auto &c : b) cin >> c;          // 读 Bob 的牌

    sort(a.begin(), a.end());            // next_permutation 要求序列升序，必须先排一次
    do {
        sort(b.begin(), b.end());        // 每一轮外层都要把 b 复位成升序，才能重新枚举
        do {
            bool has_block = false;      // 这一组配对里，是否存在 gcd>1 的一对
            for (int i = 0; i < n; i++) {
                if (gcd(a[i], b[i]) > 1) { has_block = true; break; }
            }
            if (!has_block) {            // 一组配对"全互质" -> Bob 照单对接就能赢
                cout << "Bob" << endl;
                return 0;                // 找到一个就够，直接结束
            }
        } while (next_permutation(b.begin(), b.end()));
    } while (next_permutation(a.begin(), a.end()));

    cout << "Alice" << endl;             // 所有配对都有 gcd>1 的一对 -> Alice 必胜
    return 0;
}
```

几个写法细节：

- **`do { } while (next_permutation(...))` 而不是 `while`**：`next_permutation` 只负责"下一个排列"，
  第一个排列（排序后的原序）必须自己跑一遍，所以用 `do-while`。
- 每次进入外层循环都 `sort(b)`：因为内层 `next_permutation` 会把 b 转一圈回到升序，
  但中途 `break` 出来时可能停在中间，重新 `sort` 最稳妥。
- return 0 直接结束程序：只要找到一组全互质配对，Bob 就赢了，不需要继续枚举。

## 5. 复杂度：为什么数据范围允许这么写

题目范围：n ≤ 6，1 ≤ a<sub>i</sub>, b<sub>i</sub> ≤ 30。

| 量 | 大小 |
|---|---|
| a 的排列数 | 6! = 720 |
| b 的排列数 | 720 |
| 每组配对的检查 | n = 6 次 `gcd` |
| 合计 | 720 × 720 × 6 ≈ 3.1e6 次 `gcd`，再乘上 `next_permutation` 自身的开销 |

实测（n=6、需要把所有排列跑满的最坏输入 a={2,4,6,8,10,12}、b={3,9,27,5,15,21}）：

```
约 5 ms / 组
（500 组批量测、7 次取中位数；这个例子里只有 b=5 能配 a=6/12，凑不出全互质匹配，
 所以外层 720 个排列要全部跑满，每个都还要扫完内层的 720 个排列）
```

和 2 秒的限制比，余量 300 倍以上。**这就是"利用数据量范围小"的含义**：
n! 在 n ≤ 6 时最大只有 720，平方之后也才五十万，直接枚举完全够用。
如果 n 到了 10 以上，这个写法立刻爆炸（10! = 3628800，平方就上 1e13），
那时候就必须换成博弈搜索或匹配。

**想自己复现这个数字**：把上面那组最坏输入拼成 500 组（第一行写 500，之后循环 500 次
6 / a 行 / b 行）存成 `worst.txt`，然后跑批处理版：

```bash
# 批处理版源码原在比赛工作区（清理后未入库），同版本的单组源码见本目录 C_排列枚举.cpp
g++ -O2 -std=c++17 -o C_perm_batch.exe C_perm_batch.cpp
```

```powershell
# PowerShell 里计时（500 组）
$sw = [Diagnostics.Stopwatch]::StartNew()
cmd /c "C_perm_batch.exe < worst.txt > out.txt"
$sw.Stop()
"{0:N2} ms/组" -f ($sw.Elapsed.TotalMilliseconds / 500)
```

> 顺便一个反例对比：同样 n = 6，但一边全是质数、答案落到 Bob 的输入只要 **0.04 ms/组** ——
> 因为外层第一个排列就找到了全互质配对，直接 `return` 了。
> **这道题"最坏"指的是"答案为 Alice"的那些输入**（720 个排列得全部跑满）。

## 6. 两种写法的取舍

| | 全排列枚举（本篇） | 状压 DFS（另一篇） |
|---|---|---|
| 代码长度 | 约 20 行 | 约 40 行 |
| 需要想的事 | **只需想清等价性**，实现几乎照抄 | 要设计状态、写 `dfs` 递归、写记忆化 |
| 时间复杂度 | O((n!)² · n) | O(2^n · 2^n · n)（约 4096 状态） |
| 上限 | 只能撑到 n ≤ 7 左右 | n ≤ 12 左右都没问题 |
| 赛场风险 | 低（不太会写错），但**必须先想通"为什么排列就够了"** | 中等（递归边界、记忆化键值容易写错） |

> 说"这才是赛场正解"，从**性价比**角度站得住：20 行、几乎零实现风险、
> 数据范围又刚好放得下，赛场时间紧张时这才是能救命的写法。
> 但严格讲它是"**利用数据范围的暴力**"，而不是通用解法——
> 换一场 n ≤ 15 的同款题就得换成 DFS 或匹配。

## 7. 易错点清单

1. **等价性方向写反**。判据是"**存在全互质配对 → Bob 赢**"。
   我这次验证时反复把"存在全互质配对"和"存在 gcd>1 的一对"弄混，
   结果 Alice/Bob 整体反了 —— 手算例 A、例 C 可以立刻校准。
2. **`next_permutation` 前忘记排序**。序列不是升序时，它一个排列都不会产出，循环直接空转。
3. **b 没有复位**。内层 `break` 跳出后 b 停在中间顺序，外层下一轮必须先 `sort(b)`。
4. **判断写成 `gcd(a[i], b[i]) == 1` 就 break**。反了 ——
   我们要找的是"**所有** i 都互质"，所以应该"一旦发现 `gcd > 1` 就 has_block = true"。
5. **误以为"Alice 先手就能随便挑排列"**。排列是"配对方式"，不是"出牌顺序"；
   出牌顺序的灵活性体现在 Alice 每一轮都可以根据 Bob 已经打出的牌再决定，
   而这一点恰好被"存在全互质配对"完整刻画了（第 2 节）。
6. **把 n=1 当特殊情况写**。不用特判：`gcd(a[0], b[0]) > 1` → Alice，否则 Bob，双重循环天然覆盖。

## 8. 一句话总结

**Bob 可以"照单对接"，所以博弈退化成"存不存在全互质的完整配对"；
而 n ≤ 6 意味着 6! × 6! = 518400 种配对可以暴力枚举完 —— 20 行代码收工。**
