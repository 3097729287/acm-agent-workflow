# 讲解配图：用「可跑的终端字符画」

> 类型：行为规则明细 ｜ 触发：讲数据结构、算法过程、几何关系等任何抽象内容

## 规则

**讲数据结构 / 算法过程时必须配图；图的默认形态是「一个能跑的终端字符画脚本」，不是 PNG。**

- **PNG 一律不出**：不生成 PNG，也不在 md 里放图片链接。
- **不额外存「跑屏 txt」**：要看效果就双击同目录的 `run.cmd`；
  脚本输出只嵌进 md 的那一段，不在数据区另存一份文本。

## 为什么

- 纯文字 + 纯数组下标无法让人联想到结构的变化，必须把结构画出来。
- 可跑脚本比静态图多三件事：能改参数重看、能一次看到全过程、出问题能自己重跑。
- 脚本落盘后**可复现**，PNG 不可复现（下次想看别的参数就得重画）。

## 两种脚本，别混

| 形态 | 用途 | 输出特点 |
|---|---|---|
| **过程回放**（`xxx_visual.py`） | 用样例从头到尾跑一遍：结构怎么变、数组怎么跟着变 | 长，适合"看全过程" |
| **讲解插图**（`xxx_figs.py`） | 一图一要点，嵌进 md 里讲一个点 | 短，一段一图 |

一题两样都写不冲突，各司其职。共同套路：
**分部分（`part1/part2/part3`）→ 每部分先打印讲解文字，再打印字符画 → 最后对官方样例答案。**

落盘位置：跟该题绑在一起，放 `<数据根>\题解\<比赛名>\RoundNNN\<区间>\<字母>\`
（如 `...\B-G\E\`），每个脚本旁配一个 `run.cmd`。

## 画字符画的 5 个硬要求（踩出来的）

1. **终端字符是高瘦的（约 1 宽 × 2 高）**：网格取 `ys = xs / 2` 画出来才是方的。
   常用两档：`xs=4, ys=2`（稀疏图）、`xs=2, ys=1`（密集网格）。
2. **画线要逐格步进**（每步只动一格行或一列）。按比例采样会把两个字符堆进同一格，
   屏幕上看起来像 `//`。
3. **空行是真会出现的**：网格里没有点的行，`rstrip()` 之后就是空行。往 md 里嵌时
   **不能"遇到空行就结束"**，要按网格行数 `(ymax-ymin)*ys+1` 整段取，再统一 rstrip。
4. 用 **Unicode 制表符**（`━ ┃ ┆ · ─ └ ├`）比纯 ASCII 好看得多。**这不是 ASCII 画，
   是「终端字符画」** —— ASCII 只有 128 个字符，画不出这些。文件一律 UTF-8。
5. 每个脚本旁放一个 `run.cmd`（**纯 ASCII + CRLF**），双击就能看，不依赖查看器渲染。
   命令统一写 `python`，别写 `py`（不是每个环境都有这个启动器）。

## 引擎与工具寻址

字符画引擎在 `tools/vizgrid.py`（`Grid` / `render_tree` / `render_array` / `table` …），
它把「高瘦比例、逐格步进、空行整段取」这几条固化进了代码，调 API 就自动遵守。

自己的脚本要用它（以及 `toolutil`）时，在开头加一段**工具寻址头** ——
优先读 `AGENT_CP_TOOLS` 环境变量，否则从脚本位置向上找含 `tools/toolutil.py` 的目录：

```python
import os, sys
_p = os.environ.get("AGENT_CP_TOOLS")
if not _p:                       # 向上找到含 tools/toolutil.py 的目录
    _p = os.path.dirname(os.path.abspath(__file__))
    while not os.path.isfile(os.path.join(_p, "tools", "toolutil.py")):
        _q = os.path.dirname(_p)
        if _q == _p:
            raise SystemExit("没找到仓库 tools/：请设置 AGENT_CP_TOOLS 环境变量")
        _p = _q
    _p = os.path.join(_p, "tools")
sys.path.insert(0, _p)
from vizgrid import Grid, banner, render_tree, table, hr
```

### vizgrid 的坑

1. **`banner()` / `hr()` / `part()` 是「打印并返回 None」**，`table()` 是「打印并返回字符串」。
   想攒行列表一次打印时**不能直接用**它们 —— 混用要么 `TypeError: expected str, got NoneType`，
   要么同一张表被打印两遍。要么只用 `render_tree()` / `render_array()`（这两个真返回行列表），
   要么自己写十来行的 `_table_lines()`（记得用 `pad()` / `dwidth()` 算宽度，含中文的列
   用 `str.ljust()` 会错位）。
2. **输出到终端的东西不要带 markdown 强调符**：图是嵌在代码围栏里进 md 的，
   `**新建**` 在围栏内**不会变粗**，只会原样显示成 `**新建**`。要强调就用「」或 ★。
3. **`run.cmd` 测的时候一律传绝对路径**：Git Bash 里用相对名会假报
   `'xxx.cmd' is not recognized`，双击与绝对路径都正常。`pause >nul` 结尾的脚本
   在管道里跑要记得 `< /dev/null`，否则可能一直挂着。
4. **`Grid.text(indent=...)` 自带缩进，外面别再拼一遍**：字符画要跟手写的下标行 / 值行对齐时，
   在 `rows[0]` 外又拼了一遍缩进，整段右移、线段和上面的数字**错开一格半**，
   一眼看上去像"图没画对"。判法：数一下线段第一个字符的列号，
   是不是等于 `indent + (x-xmin)*xs`。

## 嵌进 md 的做法

- 题解里直接嵌**脚本的真实输出**（跑一遍，把片段抓进来），并写明「下面是脚本的真实输出」。
- **不许手写 / 凭记忆画**：片段必须逐字来自实跑（校验脚本重新跑一遍，再要求片段逐字出现在
  md 里）。空行差异只允许「行尾空格」一种归一化，且两侧同做。
- 相关脚本放**该题自己的子目录**，和 `run.cmd` 放一起。
- **成段嵌图的脚本要"攒好再一次 print"，别边算边 print**：这样每张图是一个完整字符串，
  校正（跑脚本 → 抠 md 里的 fenced block → 逐字比）才好做。实测过的做法：给每张图各写一个
  `figN()` 返回**行列表**，`main()` 统一 `print("\n".join(...))`，再写一段核对脚本按
  `**图 N**（` 定位、取后面那个 fenced block、和实跑输出逐字比。

## 配套的 md 写法

数据结构的正文里，数组下标（`ch[v][x]`、`id[v]`、`cnt[i]`）**不要当主角**，
要把它们当作树上某个具体结点 / 牌子的"地址"来指。对照表（数组量 ↔ 树上的东西）
比一段文字说明有效得多。
