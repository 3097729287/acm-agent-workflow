# 题解写法（教程式题解的格式与风格）

> 类型：格式规范 ｜ 题解 / 教程 / 讲解的默认写法

## 风格基准（照它抄"结构"，不抄"内容"）

动笔前先在本库已有题解里挑一份基准：

- **优先挑最短、最典型的那份**——它的七节骨架摆得最干净，不会被长文的花样带偏；
- 需要展开的题，参考带「插入式小课」的长文（如"树状数组从零讲起""离散化三件套"）；
- 单题专题长文可参考带「学习路线图」「术语小抄」的那类——**这些节只允许出现在长文规格里**，整场题解一个都不写。

## 两种文档，两套模板

长文规格曾被误当成整场题解的模板用，一批题解因此长出多种结构；**模板必须分家**。

| 文档 | 什么时候写 | 用哪个模板 |
|---|---|---|
| **整场题解**（主交付物） | 收到一场比赛的 URL（触发口径见《工作流》） | 下面的「节白名单」 |
| 单题教程 / 知识点讲解 | 单独问一道题、一个算法 | 本节末尾的「长文规格」 |

### 整场题解：节白名单（唯一定义处）

**只允许下面这些节名，顺序固定、名字固定、一题一套。** 白名单之外一律不写：

```
# <比赛名> Round NNN 题解           ← 无后缀（不写「（A-F）」）

> 比赛主页：<URL>
> 题面来源：比赛题目页直接抓取，只摘关键条件、不复述完整题面；样例与极限都实跑核对，文末有实测记录。
> 语言标准：C++17 ｜ 标识符英文、注释中文 ｜ 每题一个目录 <区间>\<字母>\
                                        ← 固定这 3 行引用块；不写「本场骨架」「怎么读」段

## 目录                       ← 一律写
| 题号 | 题名 | 考点 | 难度 |     ← 固定四列，就这四列（多余列一律删）
|---|---|---|---|
| A | <题名> | … | … |

## A. <题名>                  ← 题级一律二级、格式就是「字母. 空格 题名」
### 题意                       ← 必写
### 从零讲：<主题>            ← 可选，只在这个概念是**首次出现**时写（见《从零讲》《概念台账》）
### 手算                       ← 可选
### 思路                       ← 必写
### 参考代码                   ← 必写
### 复杂度                     ← 可选
### 易错点                     ← 必写

## B. <题名>
...

## 实测记录                    ← 整场只写一次，≤6 行纯文字，不用表格、不用 `- ` 列表
```

**七条硬规矩**：

1. **题内一律 `###`，一律不写编号**。`### 1. 题意` / `### 2. 思路` 这种编号**不要**——
   中间插一节就得重排后面全部编号，是主要的不一致来源。
2. **题级一律 `##`，格式严格是 `<字母>. <题名>`**。别写成 `## A. 题名 —— 一句话概括`
   这种带副标题的。
3. **下列节名一律不许出现**（自作主张加的，没要过）：
   `正确性证明`（**融进「思路」**，像"为什么这样做不会重复计数"那样自然带过）、
   `练习建议`、`自己动手`、`一句话总结`、`术语小抄`、`学习路线图`、`套路迁移表`、
   `写完自查清单`、`附录 A / B / C`、`这场比赛在考什么`（要写就并进开头引言）。
4. **实测记录整场只写一次**、放文末、$\le 6$ 行纯文字、**不用表格**（行数超限 / 表格 / 列表
   由 `tools/check_solution.py` 第 6 项当场报）。
5. **题内小节的顺序固定**：
   题意 → 从零讲 → 手算 → 思路 → 参考代码 → 复杂度 → 易错点。
   四项**必写**：题意 / 思路 / 参考代码 / 易错点；从零讲 / 手算 / 复杂度 按需。
6. **一道题最多一个 `### 从零讲：<主题>`**，里面再要分小概念就用 `####`。
7. **目录表就四列**：`题号 | 题名 | 考点 | 难度`，难度列一律写 **`CF <数字>`**——
   **必须带 `CF ` 前缀**（如 `CF 800`），它标明这是 CF rating 口径，不是某个 OJ 自己的难度分，
   跨平台时才有可比性。多出来的列（一句话核心 / 一句话结论 / 复杂度 / 通过$\cdot$提交数 / 档位详略）**一律删**。

**文字块一律用裸围栏**（三个反引号，不加 `text` 这类语言标注）；实测记录也别用 `- ` 列表。

**这两个口径已脚本化**：`tools/check_solution.py` 的**第 10 项**（目录表列头 + 每行四格）、
**第 11 项**（题内小节顺序 + 四项必写 + 不许重复），以后漂了会当场报错。

**数学一律写 LaTeX**（行内 `$...$`、下标 `$a_i$`、复杂度 `$O(n \log n)$`）——细则、转换器与校验见《数学 LaTeX》；
脚本闸 = `check_solution.py` 第 1 / 1b / 2 项。

**代码块**：每题贴**一份**参考代码，就是该题目录里那份 `<字母>.cpp`（逐行中文注释）。
别贴两份（除非这题真有两种正解要对比，那也只在「思路」里说，代码只留一份）。

**难度**：题解正文里要提难度也一律写 **`CF <数字>`**（`CF 900` / `CF 1500` / `CF 1800`），
**同样带 `CF ` 前缀**，不写"普及-"这类档位名（档位名不直观，各平台口径也不一）。

### 单题教程：长文规格（例外情形）

只在单独问一道题 / 一个知识点时用，**整场题解不用这套**：

```
0. 先回答"这是什么算法 / 本质是什么"（对方贴了自己的代码时，先给结论：
   对不对、和别的解法是不是同一个算法、差异表）
1. 题目在讲什么（逐句拆条件；点出题面里的"信号"，如 n≤6 在喊状态压缩）
2. 先手算（官方样例 + 自造最小例子，纸上走一遍，建立直觉）
3. 核心概念从零讲（配 ASCII 图 / 表格 / 真实程序输出）
4. 从朴素做法推到正解（写清"朴素为什么不行"，最好给反例数字）
5. 状态/公式定义 + 转移（贴出定义式）
6. 关键数据结构或前置知识从零讲（树状数组、Trie、位运算小抄…）
7. 逐行精读代码（对方贴了代码就精读**他的**；否则给逐行中文注释的完整代码）
8. 与其它解法/套路的关系（对比表：思想、前置知识、复杂度、适用场景）
9. 复杂度（给**具体数字**，不只给大 O，如"924 个状态 × 36"）
10. 易错点清单（逐条编号；先肯定对的部分，再说为什么错）
11. 写完自查清单（checkbox 列表）
12. 练习建议 + 随机数据生成器模板 + 套路迁移表
13. 一句话总结
附：术语小抄 / 实测记录（文字一行）
```

## 硬要求

- **第二人称、口语化**，允许"说句实话""这个坑很阴"这类语气；不要写成论文。
- 抽象概念**必须**配"能手算的小例子"或"真实跑出来的输出"，不许只有文字定义。
- **表格 > 长段落，图 > 纯文字描述**；讲数据结构 / 算法过程时**图是必须的**，且默认形态是
  **「可跑的终端字符画脚本」**（不是 PNG）——细则、风格基准、五个踩坑见《配图》。
- **第一次出现的新概念要单独开一节从零讲**（是什么 / 有什么用 / 在这题里怎么用 / 为什么），
  插在「题意」和「思路」之间、后续小节顺延——细则见《从零讲》。
- **已经讲过的概念只给指针**，一句话带过（「XX 在《某份题解》的哪一节讲过」），别再展开；
  查表和登记都走《概念台账》。**降的只是算法讲解段**——该题的题意、手算、逐行代码、
  易错点、复杂度一律照写，不因为算法讲过就缩水。
- 代码逐行中文注释、标识符英文（这条不变）。
- 正确性/复杂度**不能丢，但要融进讲解**（像"为什么这样做不会重复计数"这样的小节），
  不要单开一个干巴巴的「正确性证明」标题。
- 对方贴了自己的代码时：**先编译跑样例 + 对拍**，再逐行读；错的地方逐条说"为什么错"并先肯定对的部分。
- **实测记录整场题解只在文末写一次**（**文字 $\le 6$ 行**、不用表格）：实跑过哪几档、
  各组数、极限耗时；数字照样必须来自实跑输出（不许"约/大概"），没跑的那档就写"未验证"。
- 篇幅**按题分配**（简单题简单写、难题详细写）：签到 / 入门题写到
  「题意 → 手算 → 参考代码 → 易错点」就够，不硬凑长文；需要新套路或数据结构的题才展开。
  **分档规则与两条覆盖规则见《工作流》**（唯一定义处）。
  （量级参考：单题教程 16~35KB 是常见量级，怕的是跳跃和省略，不怕长。）

## 可调档

- 对方明确说"简短 / 只要代码 / 速查版"时，缩到 `题意 → 参考代码` 两节即可。
- 单题教程默认用上面的长文规格。

## 落盘

**落盘结构见《工作流》的「落盘结构」一节**（唯一定义处：交付 md 放**场次根** `<数据根>\题解\<比赛名>\RoundNNN\`，
每题一个 `<区间><字母>\` 子目录，中间产物进 `_work\`）。本节不再重复，免得两处走样。

几条跟"写"有关的：

- 单题 / 单知识点教程放 `<数据根>\算法\<算法名>\`（或题解区该题的子目录）：教程 md + 正解 cpp +（暴力 / 对拍 / 可视化脚本）。**副本目录（`config.json` 的 `desktop_copy_dir`，默认关）只收整场题解，教程不复制过去。**
- 配套脚本是好东西（范例里就有"可视化版.py"）：能打印中间过程 / 状态表 / 博弈树的脚本，能写就写。
- **讲数据结构 / 过程时配图脚本是默认项，不是可选项**，并放一个 `run.cmd` 让它双击就能看
  （纯 ASCII + CRLF；`run.cmd` 里一律写 `python`）——见《配图》。
- 绘图别从零写：`tools/vizgrid.py` 已把 5 条硬要求固化成 API
  （`Grid` / `render_tree` / `render_array` / `table` / `banner` / `hr`）。
  自己题目的脚本按**工具寻址头**导入它：设 `AGENT_CP_TOOLS` 指向仓库 `tools/`，
  或从脚本位置向上查找含 `tools/toolutil.py` 的仓库根；`vizgrid.py` 头部就是这段样板，直接抄。
- 交付前跑 `tools/check_solution.py`（见《工作流》第六步）。
