# 算法实现踩坑集

> 类型：方法 ｜ 收集「思路对了、代码也写出来了，但某个量算错」的实现级错误。
> 每条格式：**症状 → 为什么 → 下次怎么避免**。与《验证协议》的分工：
> 那边管"怎么验"，这边管"验出来的错长什么样、怎么根治"。

## 分布压缩 DP：总和要乘段长，别把"每格的值"当"段的和"

**症状**（一道网格路径计数题，F）。把 DP 分布压缩成"两段常数"（左段每格 `A`、
右段每格 `B`，`v = x` 处为 0）后，更新总和的式子写成：

    S = A + B                        // 错

正确是：

    S = (x - 1) * A + (n - x) * B    // 每格的值 × 该段格数

**为什么**：`A`、`B` 是**每格的值**，不是"段的和"。变量名若恰好叫 `lo` / `hi`，
语感上顺着"总和 = 左边之和 + 右边之和"就直接相加了。

**为什么样例没拦住**：样例 `n = 3`、障碍在第 2 行，正好 `x - 1 = n - x = 1`，
两个式子数值**恰好相同**。是随机对拍到第 11 组才炸出来：`n = 4, m = 5`、
禁格 `(4,2)`，正确答案 144，错解 48（差了整 3 倍）。

**下次怎么避免（祈使句）**：

1. 写下形如 `S = 左 + 右` 的转移式时，**先自问一句"这是每格的值，还是整段的和"**；
2. 分段常数结构里的变量**别名带上 `per`**（`per_lo` / `per_hi`），让"每格"这件事写在名字里；
3. 挑验证样例时**特意选段长不等的**（`x - 1 ≠ n - x`），别让巧合替你通过。

## dfs 用递归写：2×10^5 的链上直接爆栈

**症状**（一道树上路径题，F；实测）。树上 dfs 写成递归（`void dfs(int u, int p)`），
小样例、随机小树、甚至随机大树都正常；换一条 `n = 2×10^5` 的**链**（`u = v - 1` 连边）
去跑，进程以退出码 `-1073741571`（即 `0xC00000FD`，`STATUS_STACK_OVERFLOW`）退出，
**stdout 一行输出都没有** —— 表现像"程序没启动"或"输入没读到"，一点都不像"算法写错了"。
改成显式栈的迭代 dfs，同一份数据 0.11 s 正常跑完、输出 99913 行。

**为什么**：链状树上递归深度 = `n` = 2×10^5，每层栈帧几十字节，累计远超默认栈
（Windows 主线程 1～2 MB）。更麻烦的是**爆不爆栈取决于编译器与系统给的栈大小**，
本地不炸不等于评测机不炸，反之亦然 —— 所以"我本地递归跑过了"证明不了任何东西。

**为什么随机对拍没拦住**：随机生成的树深度只有 `O(log n)`，递归深度根本涨不上去；
只有**刻意构造的链**才碰得到。这和第一条（分布压缩 DP）是同一类病：
**验证数据的形状没覆盖到出错的形状**。

**下次怎么避免（祈使句）**：

1. 树的 `n` 上限 ≥ 10^5 时，dfs **一律写显式栈的迭代版**：`while (!st.empty())` +
   `it[u]` 记录枚举到第几个邻居，离开时 `tout[u] = timer_`；
2. 对拍数据里**必须含一条链和一朵菊花**，别只随机生成树；
3. 见到"非零退出码 + 零输出"，**先怀疑栈溢出 / 数组越界，再怀疑算法**；
   退出码 `-1073741571` 就是栈溢出的签名；
4. 递归版别删，留成 `F_rec.cpp` 这样的独立文件当反例，下次一条命令就能复现。

## 空区间的下标是 −1：`dp[l][l-1] = 0` 会把堆写坏，退出码 0xC0000374

**症状**（一道区间 DP 题，F；实测）。区间 DP 按长度递推，长度 0 表示"空区间"，
很自然写成：

    for (int len = 0; len <= n; len += 2) {
        int r = l + len - 1;
        if (len == 0) { dp[l][r] = 0; continue; }   // 错！len=0 时 r = l-1
        ...
    }

`r = l - 1` 在 `int` 里是 −1，但 `vector::operator[]` 收的是 `size_type`（无符号），
−1 变成 18446744073709551615，**越界写**。程序在样例上就崩，退出码 `3221226356`
（`0xC0000374`，`STATUS_HEAP_CORRUPTION`），stdout 一行都没有。

**为什么难查**：崩的地方和写错的地方不在一处 —— gdb 回溯停在
`ucrtbase!_free_base` → `main`，看着像"析构时堆坏了"；而真正的越界写在第一层循环里。
`-fsanitize=address` 在 MSYS2 UCRT64 上可能装不出来（`cannot find -lasan`），
最后靠**插桩探针**（每一步 `fprintf(stderr, "l=%d r=%d", ...)`）才看到 `l=0 r=-1` 那一行。

**为什么不能靠"跑通一次"下结论**：堆损坏是"有时行有时不行" —— 同一份代码第一次跑
还打印了完整汇总（堆没被踩到要害），换个更小的 n 立刻暴露。

**下次怎么避免（祈使句）**：

1. 写区间 DP 时，**空区间永远不写数组**：只在用到它的地方用三元式顶上
   （`(j-1 >= l+1) ? dp[l+1][j-1] : 0`）；`len == 0` 分支直接 `continue`。
2. 循环里出现 `- 1`、`+ 1` 的下标，**先手推一遍最小规模的取值**（n = 2、l = 0、len = 0）；
3. 见到 `0xC0000374` / `0xC0000005` + 零输出，**先按"越界写"找**，别怀疑算法；
4. ASan 装不上就用**打印探针**：写一个只读最小输入的探针程序，把每步下标打出来，
   跑一次就能定位到 `l=0 r=-1`。

## 多重循环 DP 差一个数量级：别把"枚举切口"写成"每个切口各做一遍完整 DP"

**症状**（同一道区间 DP 题）。圆上区间 DP 的第一版写成：枚举 n 个切口，
**每个切口都做一遍完整的 O(n³) 区间 DP**，取最小。功能全对（样例、边界、300 组对拍全过），
但极限用例 `n = 500` 全同字母 **33.881 s**，限时 1 秒 —— 必然 TLE。

**为什么**：`n` 个切口 × `O(n³)` = `O(n⁴)`；全同字母时每个位置的字符都相等，
内层转移一个都 `continue` 不掉，跑满。

**怎么改**：把 `s` 复制成 `2n`，**只做一遍**区间 DP，然后取 n 个长度 n 的窗口的最小值。
同样的算法骨架，`O(n³)`，实测 **0.115 s**（同样的用例）。差 300 倍。

**下次怎么避免（祈使句）**：

1. 遇到"圆上 / 环上"的 DP，**先想"复制成两倍 + 取 n 个窗口"**，别把切口当外层循环；
2. 写完先算一遍最坏复杂度再提交，**别等 `tools/verify.py` 的极限档告诉你**；
3. 极限用例里**必须有一个"全同 / 全相等"的输入**（本题是全同字母）——
   随机数据测不出这种最坏情况。

## 统计量做 O(1) 修正时，修正项要逐位置判断，不能想当然写成"减 2"

**症状**（一道打牌计数题，D）。答案要在每个合法起点 `a` 上累加 `C(|T|,2) + |T4|`，
其中 `T = {x : cap[x] ≥ 2}`、`T4 = {x : cap[x] ≥ 4}`，
`cap` 是"扣掉两个三张之后每种点数还能用几张"。为了 O(1) 算出 `|T|`、`|T4|`，
先全场统计 `g2`（够 2 张的点数种数）、`g4`（够 4 张的点数种数），然后写：

    |T|  = g2 - 2 + [cnt[a]≥5] + [cnt[a+1]≥5]        // 对
    |T4| = g4 - 2 + [cnt[a]≥7] + [cnt[a+1]≥7]        // 错

**为什么错**：`a`、`a+1` 一定被算进了 `g2`（合法起点要求 `cnt ≥ 3`），
所以 `|T|` 里减 2 成立；但 `a`、`a+1` **不一定**被算进 `g4` ——
样例 1 里 `cnt[2] = 3 < 4`，`a+1` 根本不在 `g4` 里，再减一次就少算了。
正确写法是按位置逐个判：
`|T4| = g4 - [cnt[a]≥4] - [cnt[a+1]≥4] + [cnt[a]≥7] + [cnt[a+1]≥7]`。

**为什么样例能拦住**：样例 1（七个 1、三个 2）的正确答案是 1，用错的修正式会算出 0，
**手算样例时当场就露馅** —— 这说明"每个样例都手算一遍期望值"比"多跑几组随机"
更早抓到这类错。

**下次怎么避免（祈使句）**：

1. 写 `全集统计量 ± 修正项` 这种 O(1) 式子时，**逐个位置写出它是否真的在集合里**
   （`[cnt[x]≥k]`），不要用"反正是 a 和 a+1 两个，就减 2"这种打包写法；
2. 修正项里的每个布尔条件都要能在纸上指出"什么时候为真 / 为假"，
   并用**一个让它为假的样例**验证；
3. 先用**手算过的样例**跑公式，再上随机对拍 —— 两者抓的错误类型不一样。
