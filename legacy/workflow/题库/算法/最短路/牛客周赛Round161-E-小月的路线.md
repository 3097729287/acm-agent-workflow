# 牛客周赛 Round 161 E - 小月的路线

- **难度**：CF 1300
- **原题链接**：https://ac.nowcoder.com/acm/contest/140235/E
- **题解位置**：`题解\牛客周赛\Round161\Round161题解.md`（整场题解，含完整推导）
- **归档文件夹**：`算法\最短路\`（2026-10-01 新建，本场第一份记录）
- **数据结构与算法**：最短路（优先队列）+ 字典序双关键字松弛
- **具体知识点**：边权非负 ⟹ 每次取最小的那个已是最优；二元组 (距离, 风险) 的字典序松弛；`long long` 防路径和溢出

## 题意（精简）

n 个点 m 条有向边（允许重边），每条边有距离 d 和风险 r。从 1 到 n，先取距离最小的路径，再在其中取风险最小的。输出最优路径的总距离与总风险；走不到输出 `-1 -1`；n = 1 时输出 `0 0`。

**数据范围**：1 ≤ n ≤ 2 × 10⁵；0 ≤ m ≤ 3 × 10⁵；0 ≤ d, r ≤ 10⁹。

## 关键点（为什么用这个算法）

1. 双权但**有优先级**（不是求和、不是比值），所以边上的权是一个二元组 (d, r)，按字典序取最小 —— d 和 r 都非负，Dijkstra 的「取最小者定死」论证照样成立。
2. 松弛条件多一条：距离更小 → 更新；距离相等但风险更小 → 也更新。优先队列只按距离排序就够，风险更小的那次更新会再入队一次。
3. 不用 Floyd（O(n³)）也不用 Bellman-Ford（O(nm)），这个规模必超时；也不用 SPFA（最坏会退化）。
4. 备选写法「先跑距离最短路、再在最短路子图上跑风险最短路」也可行，但要建子图跑两遍，字典序一遍更省。

## 复杂度

- 时间：O((n + m) log n)，m = 3 × 10⁵ 时约 3 × 10⁵ × 18 次堆操作。
- 空间：O(n + m) 邻接表 + 两个 long long 数组。

## 踩过的坑

1. **`int` 装不下距离**：10⁹ × 2 × 10⁵ 条边 = 2 × 10¹⁴，必须 `long long`（风险同理）。这是本题最常见的 WA 原因。
2. 过时堆元素的判断写成 `du != dist[u]` 就够；但别把它当成「风险没变就不处理」的开关 —— 风险变小、距离没变的那次更新入队时 `du == dist[u]`，必须让它照常往后面传。
3. n = 1 要输出 `0 0`（题目明确要求），走不到要输出 `-1 -1`（不是一个 -1、也不是 0 0）。
4. 重边不用特殊处理：两条边各自松弛，风险小的自然留下。
