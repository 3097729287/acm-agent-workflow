# 牛客周赛 Round 162 E - 小月的区间

- **难度**：CF 1800
- **原题链接**：https://ac.nowcoder.com/acm/contest/140489/E
- **题解位置**：`题解\牛客周赛\Round162\Round162题解.md`（整场题解，含完整推导）
- **归档文件夹**：`算法\稀疏表\`
- **数据结构与算法**：稀疏表（ST 表 / RMQ 倍增）+ 二分答案
- **具体知识点**：st[k][i] = 从 i 开始长 2<sup>k</sup> 段的最值；查 [l, r] 用两块长 2<sup>k</sup> 的区间拼（允许重叠）

## 题意（精简）

给一个长度 n 的排列。称非空子数组 [l, r] 是"新鲜"的，当且仅当同时满足：子数组最大值大于它左边的所有元素，且子数组最小值小于它右边的所有元素。数一数有几个。n ≤ 2 × 10<sup>5</sup>。

**数据范围**：n ≤ 2 × 10<sup>5</sup>；a 是 1 ~ n 的排列。

## 关键点（为什么用这个算法）

1. 两个条件写成：max(a[l..r]) > preMax[l]（preMax[l] = max(a[1..l−1])）且 min(a[l..r]) < sufMin[r]（sufMin[r] = min(a[r+1..n])）。左边 / 右边没有元素时条件自动成立，用哨兵 preMax[1] = 0、sufMin[n] = n + 1 带过去。
2. **单调性**：固定 l，max(a[l..r]) 随 r 只增大、阈值是死的；min(a[l..r]) 随 r 只减小而 sufMin[r] 随 r 只增大。所以两个条件都形如"r ≥ 某个阈值"，可以各二分一次找阈值，然后 r 的可行区间就是从 max(r<sub>1</sub>, r<sub>2</sub>) 到 n。
3. 二分要反复问区间最值，必须 O(1) 查询，否则二分省下的全还回去 —— 稀疏表就是干这个的：预处理 O(n log n)，查询 O(1)。
4. 条件一可能压根无解（比如 [3,2,1] 里 l = 2，preMax = 3 而后缀最大只有 2），二分前必须先判 `qMax(l, n) > preMax[l]`，否则二分返回假答案。
5. 稀疏表为什么够用而不上线段树：查询次数约 n × 2 × 18 ≈ 7 × 10<sup>6</sup>，稀疏表每次只做两次数组访问 + 一次 max，常数远小于爬树。

## 复杂度

- 时间：O(n log n)。预处理 18 层 × 2 × 10<sup>5</sup> = 3.6 × 10<sup>6</sup> 次取最值；主循环 n 次、每次约 36 次 O(1) 查询 ≈ 7.2 × 10<sup>6</sup> 次。实跑极限：递增排列 0.139 s、递减排列 0.135 s
- 空间：O(n log n)，max/min 两张表 ≈ 27 MB

## 踩过的坑

1. **空集要按"条件成立"处理**：l = 1 时左边没元素、r = n 时右边没元素，题面的全称量化在空集上是真的。哨兵取 0 和 n + 1（排列元素都在 1..n，一定成）。
2. **答案要开 long long**：最多 n(n + 1) / 2 ≈ 2 × 10<sup>10</sup> 个子数组，int 装不下。
3. **稀疏表第二块的起点是 r − 2<sup>k</sup> + 1**，写成 r − 2<sup>k</sup> 会漏掉一个位置（这种错误在随机对拍里不一定被抓到，因为漏的常常不是极值所在）。
4. 条件一先判可行性再二分；不判的话 [3,2,1] 这种递减数据会立刻出错。
5. `__builtin_clz` 的参数不能是 0（n ≥ 1 时安全）。
