## 0. 先回答几个关键问题

### 0.1 这是什么算法？

**状态压缩 + 记忆化搜索（DFS）的博弈树搜索**，也就是竞赛圈常说的"**状压 + 记忆化爆搜**"。

拆成三个词：

| 词 | 在你的代码里对应什么 |
|---|---|
| **状态压缩** | mask1、mask2 用二进制位表示"哪几张牌还在手里" |
| **记忆化搜索** | `dp[mask1][mask2]` 存下算过的局面，`dfs` 进来先查表 |
| **博弈搜索** | `dfs` 里"Alice 枚举招式 + Bob 枚举应对"的双层循环 |

### 0.2 本质是什么？

本质是：**在一个"有限、完美信息、零和"的两人游戏里，把必胜/必败的定义直接翻译成递归。**

形式化地说：

```
win(ma, mb) = 存在一张 Alice 的牌 a_i 使得：
                  对 Bob 的每一张牌 b_j 都有：
                      gcd(a_i, b_j) > 1        （Bob 出这张当场输）
                      或者 win(ma - a_i, mb - b_j) == true   （Bob 出了也白出）
```

翻译成人话：

> **Alice 只要找到"一招"，让 Bob 无论怎么应都逃不掉，这个局面就是 Alice 必胜的。**

这在博弈论里有正式名字：**P 态 / N 态（必败态 / 必胜态）递推**，也叫 **minimax（极小极大）**、
从终局往回推也叫 **retrograde analysis（反推分析）**。你的 `dfs` 就是在算"这个局面是 P 态还是 N 态"。

**为什么能记忆化？** 因为每走一轮，Alice 和 Bob 各少一张牌，牌只会越来越少 ——
**状态之间不可能绕回来**（专业说法：状态图是一个 DAG，无环）。无环 + 状态有限 = 可以把答案存下来反复用。

**一句话**：这不是"搜索技巧"，而是"把博弈规则原封不动翻译成一句递归定义"，DFS 只是执行这个定义的工具。

### 0.3 跟你之前的解答一样吗？

| `gcd > 1` 的 Bob 牌 | `continue` 跳过 | `continue` 跳过 | 一样 |

**（b）和 `C.cpp`（匈牙利求最大匹配）—— 完全不同的两条路。**

| | **DFS 博弈搜索（你的）** | **匈牙利匹配（另一份）** |
|---|---|---|
| 核心思想 | 不猜结论，把"最优对抗"一局一局模拟到底 | 先**证明**一条结论：Bob 能赢 ⟺ "互质图"上存在完美匹配，再求最大匹配 |
| 需要的前置知识 | 递归、位运算 | **Hall 定理**、二分图匹配 |
| 复杂度 | O(C(2n,n) · n²)，n=6 时约 924 × 36 ≈ 3.3 万次操作 | O(n³) |
| n 变大时 | n=10 → 184756 状态；n=12 → 270 万状态，开始吃力 | n 到几百都轻松 |
| 什么时候更香 | 状态小、规则绕、一时看不出结论 | 状态大、能一眼看出"配对"结构 |

**两条路我都跑过，结论在 600 组随机数据上完全一致**（`对拍.py` 的输出见第 12 节）。
所以你的写法**没有任何问题**，它是这道题最"稳"的解法：不需要任何定理，照着题面就能写出来。

### 0.4 「双方均采取最优策略」是什么意思？等于明牌吗？

**先给结论：明牌说得对，但它和"最优策略"是两件不同的事。**

| | 说的是什么 | 本题满足吗 |
|---|---|---|
| **明牌** | **信息**：双方能不能看见对方的牌 | ⚠️ **隐含假设**（题面未明写，见 0.5 节） |
| **最优策略** | **行为准则**：双方都不会失误 | ✅ 满足（这是题目给的前提） |

#### （1）"明牌"说的是信息

本题的信息结构是**全公开**的：

- **Bob 能看见 Alice 本轮打出了哪张**（这一条**题面明写了**："Bob 在看到 Alice 本轮打出的牌后…"）；
- 没有任何随机性（不洗牌、不掷骰子）；
- **双方手里还剩哪几张牌，互相都可见** —— ⚠️ 这一条**题面没有明写**（题面只是把两行牌给了"读题人"），
  但它是**必需的隐含前提**：不这么假设，这题就没有唯一答案了。详见 0.5 节的反例。

所以这是**完全信息、确定性的有限博弈**。你可以理解成"两个人把牌摊在桌上打"。

#### （2）"最优策略"是一个数学定义，不是"打得聪明"

- **策略** = 一份完整的作战手册：**在任何可能遇到的局面，我出哪张牌**。
  （注意：是"任何局面"都要写清楚，不是"这一轮我想出哪张"）
- **最优** = 在**对手也不会失误**的前提下，我能保证拿到的最好结果。

本题只有两种结局（Alice 赢 / Bob 赢）、零和、状态有限，所以"最优"**不需要任何概率和取舍**，
它就等价于两个词：**必胜 / 必败**。

而且有一个重要结论（博弈论里叫 **Zermelo 定理**）：

> 这种"有限、无随机、无平局、完全信息"的游戏，**一定**有一方存在必胜策略。
> 不存在"看运气"或者"双方都最优就僵住"的情况。

这就是为什么题目敢直接问"请判断最终的胜者"——**答案是被局面唯一决定的**。

#### （3）那为什么题目非要写这一句？

因为**不写的话，这个问题就没有意义了**。举个真实的小例子（配套文件 `s6.txt`）：

```
Alice {2, 3}   vs   Bob {4, 9}
```

Alice 出 2 时，Bob 如果**随手出 4**：`gcd(2,4)=2>1` → **Alice 立刻赢**。
但 Bob 不傻，他会出 9：`gcd(2,9)=1` 安全，最后变成 Alice {3} vs Bob {4}，`gcd(3,4)=1`，牌打完了 → **Bob 赢**。

所以：

- 说"Alice 赢"也能找到依据（**只要 Bob 犯错**）；
- 说"Bob 赢"也能找到依据（**只要 Alice 犯错**）；
- 加上"双方均采取最优策略" = **排除"靠对手失误赢"这条路**。
  Alice 必须赢在"Bob 已经拼尽全力"的前提上。

一句话：**题目问的是"这个局面的数学真相"，不是"两个普通人乱打谁会赢"。**

（顺带一提：双方都知道对方在按最优打，这叫"理性是共同知识"。
所以不用去想"我猜他以为我会出什么"这种无限套娃。）

#### （4）「明牌」≠「同时出牌」——这里是第二个容易混的点

"明牌"只描述了**信息**，没有描述**顺序**。本题的顺序是明确的：

```
   Alice 先亮牌  →  Bob 看到之后再决定  →  比 gcd
```

这是"明牌 + **先后手**"，不是"明牌 + 同时出"。区别很实在：

- **本题**：Bob 在**一轮之内**有信息优势 —— 他能针对 Alice 刚打出的这一张，临时挑一张最合适的。
  这正是代码里 **Bob 的内层循环可以直接盯着 `a[i]` 去挑 `b[j]`** 的原因。
- **如果改成同时出牌**：Bob 失去了这个针对性，他要在"不知道 Alice 出什么"的情况下做决定，
  "最优"的定义本身都要重新讨论（对手不知道你的选择时，通常得引入随机化 / 混合策略）——
  那就是**另一道题**了。

#### （5）落到代码上：「明牌 + 最优」= 一对量词

这两个前提翻译成逻辑，就是一对量词，而它们和代码是**一一对应**的：

| 中文 | 逻辑 | 代码 |
|---|---|---|
| Alice 只要**存在**一招 | ∃（存在） | 外层 `for (p)` + `if (f) return 1;` |
| Bob 的**每一种**应对都挡不住 | ∀（任意） | 内层 `for (pp)`，要全部"逃不掉"才算数 |
| Bob 找到**一条**活路，这招就废了 | ¬∃ | `f = false; break;` |

**为什么 Alice 不用去"猜"Bob 会出哪张？**
因为明牌 + Bob 后手 ⇒ Alice 必须假设 Bob 会打出**最克她的那张**（这就是 ∀）。
所以 Alice 要做的就是：找一张"**怎么克都克不住**"的牌。找到了，她就赢。

> **本节一句话**：明牌 = 大家看得见牌；最优 = 大家都不失误。
> 两个都满足 → 答案唯一，并且可以用"存在 / 任意"这对量词直接算出来。

### 0.5 「Bob 好像是提前知道了我的牌」——不，是"对每种情况都有预案"

很多人第一次看到"Bob 有一本作战手册"时会有这个疑问：

> "Bob 怎么知道我下一张会出 4？这不是作弊吗？真实的牌类游戏哪能看见对方的手牌？"

把两件事分开，疑问就消失了：

| | 意思 | 本题需要吗 |
|---|---|---|
| **预知未来** | 提前知道 Alice **这一轮会出哪张** | ❌ **不需要** |
| **覆盖所有情况** | 对 Alice **可能出的每一张**都准备好了应对 | ✅ 这才是 Bob 做的 |

**Bob 的手册是"事先写死"的**，写它的时候只需要双方的手牌（这是题面公开给所有人的信息），
**完全不需要知道 Alice 会按什么顺序出牌**：

```
   如果 Alice 出 4  ->  我出 3
   如果 Alice 出 6  ->  我出 5
   如果 Alice 出 7  ->  我出 2
```

这张表就是**策略**的标准定义：**一个从"我看到的情况"到"我采取的行动"的函数**。
它不预测未来，它覆盖未来 —— 而"完美匹配"保证了这些"如果……就……"之间**不会互相打架**
（三张 Bob 牌各用一次，永远不会出现"两个分支都想要 3"的情况）。

> 精确一点说，Bob 用得上手册，靠的是两样东西：
> ①**双方手牌对彼此都是公开的**；②**每一轮看得见 Alice 出了哪张** —— 这一条**题面明写了**：
> 「Bob 在看到 Alice 本轮打出的牌后，从自己剩余的牌中选择一张打出」。
>
> ⚠️ **但第 ① 条题面并没有明写。** 它是**隐含假设**，而且是**必需的** —— 理由见下面这个反例。

#### 为什么 ① 必须假设？两个"世界"的反例

Bob 的手牌都是 {2,3,5}，Alice 的第一步都是出 4：

| | 世界 A | 世界 B |
|---|---|---|
| Alice 的手牌 | {4,6,7} | {2,4,8} |
| Bob 观察到的东西 | Alice 出了 4；自己手里是 {2,3,5} | **完全相同** |
| 结果 | **Bob 胜**（必须出 3） | **Alice 胜**（出 3 出 5 都救不了） |

Bob 在两个世界里**看到的信息一模一样**，"正确的那一手"和"最终胜负"却都不同 ——
也就是说：**如果不假设"双方知道彼此的全部手牌"，Bob 的"最优策略"根本无从定义**，
题目也就不可能有一个由输入唯一决定的答案。

所以"完全信息"不是我们额外加上去的设定，而是**要让这道题有解就必须接受的隐含前提**：
题面要求输出唯一的 Alice / Bob，只有在这个前提下才成立。
（更根本的原因是：**不完全信息博弈可能"不确定"** —— 双方都没有必胜策略、要靠混合策略和均衡，
那时答案就不是"Alice/Bob"两个词能表达的了。）

> 实战提示：遇到"双方最优，判断胜者"这类题，先问一句"**谁看得见什么**"。
> 题面没写清楚时，按"完全信息"这个通行约定理解，并在题解里**把这个假设点明**。

> 这正是"必胜策略"的含义：**不是"我能猜到你"，而是"你无论怎么走，都在我的准备之内"。**

**那"真实的牌类游戏看不见对方手牌"呢？** 那是另一类游戏：

| | 完全信息（本题） | 不完全信息（斗地主、桥牌那种） |
|---|---|---|
| 双方手牌 | 全部公开 | 互相看不见 |
| 数学工具 | 博弈树、P/N 态（本文这套） | 概率、期望、贝叶斯博弈 |
| 答案形态 | **谁必胜**（一个确定的词） | 通常是"**胜率多少**"（一个数） |

所以"把牌藏起来"之后，**并不是"没有谁必胜"，而是"必胜"这个概念本身失效了** ——
必须先补上一堆新规则（谁看得见什么？Alice 手牌的**先验分布**是什么？），题目才完整，
而答案也会从"Alice / Bob"变成"胜率 x%"。

本题之所以能问"谁必胜"，正是因为它是**完全信息**的：输入把两行牌都给你了。
这是出题人的设计，不是漏洞。

> **本节一句话**：明牌 ≠ 预知；**策略 = 预案，不是预言。**

## 1. 题目在讲什么

- Alice 和 Bob 各有 n 张牌（1 ≤ n ≤ 6），牌面是正整数（≤ 30）。
- 一轮的流程（**顺序很重要**）：

```
   ① Alice 从自己手里挑一张打出来，记作 x
   ② Bob 看到 x 之后，从自己手里挑一张打出来，记作 y
   ③ 如果 gcd(x, y) > 1  ->  Alice 立刻获胜，游戏结束
      否则                ->  这两张牌一起扔掉，进入下一轮
   ④ 牌全部扔完 Alice 还没赢  ->  Bob 获胜
```

**读题要抓住的三点**：

1. n ≤ 6 —— 这个数字小得反常，是出题人在喊"**状态压缩**"（2^6 = 64）。
2. **Bob 是后手**：他看得见 Alice 出了什么再决定。所以"Bob 能不能应对"是这一轮的核心问题。
3. Alice 要的是"**某一轮** gcd > 1"，Bob 要的是"**每一轮** gcd 都 = 1"。

## 2. 先手算，建立直觉

### 2.1 样例 1、2（n = 1）

只有一张牌，没得选：

- Alice {2}，Bob {4}：`gcd(2,4) = 2 > 1` → **Alice 胜**
- Alice {2}，Bob {3}：`gcd(2,3) = 1` → 两张牌扔掉，牌打完了 Alice 没赢 → **Bob 胜**

### 2.2 一个 n = 2 的完整推演

**局面：Alice {2, 4}，Bob {6, 3}。**

Alice 先试**出 2**：

- Bob 出 6：`gcd(2,6) = 2 > 1` → Alice 当场赢 ✗（Bob 不会这么干）
- Bob 出 3：`gcd(2,3) = 1` 安全 → 进入新局：Alice {4} vs Bob {6}
  - 只能各出一张：`gcd(4,6) = 2 > 1` → Alice 还是赢！
- 所以 Bob **两种应对都逃不掉** → Alice 出 2 就赢了。

再换个局面：**Alice {2, 3}，Bob {4, 9}。**

Alice 试**出 2**：

- Bob 出 4：`gcd(2,4)=2>1` → Alice 赢 ✗
- Bob 出 9：`gcd(2,9)=1` 安全 → 新局 Alice {3} vs Bob {4}：`gcd(3,4)=1` 安全 → 牌打完 → **Bob 胜** ✓
- 所以 Bob 会选 9，**Alice 出 2 不成立**。

Alice 试**出 3**：

- Bob 出 4：`gcd(3,4)=1` 安全 → 新局 Alice {2} vs Bob {9}：`gcd(2,9)=1` → **Bob 胜** ✓
- 所以 Alice 出 3 也不成立。

两种出法都被 Bob 化解 → **Bob 胜**。

> **你已经摸到这道题的本质了**：Alice 赢的条件是"**存在**一招，让 Bob 的**所有**应对都失败"。
> 这就是下一节的博弈树。

## 3. 博弈树：把游戏画成一棵树

### 3.1 树是怎么长出来的

把"一个局面"看成树的**结点**，把"一步走法"看成**边**：

```
                    根：Alice{2,4} vs Bob{6,3}
                    /                        \
          Alice 出 2                        Alice 出 4
          /        \                       /        \
   Bob 出 6       Bob 出 3          Bob 出 6        Bob 出 3
   (当场输)      /       \          (当场输)      /       \
            Alice出4   ...                  Alice出2   ...
```

- **Alice 的结点**：她要在所有儿子里挑一个"对我有利"的 → 用 **存在（∃ / OR）**
- **Bob 的结点**：他要在所有儿子里挑一个"对我有利"的 → 对 Alice 来说就是 **任意（∀ / AND）**

这两个字（存在 / 任意）交替出现，就是"**极小极大**"这个名字的由来。

### 3.2 真实打印出来的树

用配套的 `打印博弈树.py` 跑 Alice {2,4} vs Bob {6,3}，真实输出：

```
根局面： [这个局面 Alice 必胜]
    Alice 出 2：
        Bob 出 6 -> gcd(2,6)=2>1，Alice 立刻获胜 ✗
        Bob 出 3 -> gcd=1 安全，但之后 Alice 仍必胜 ✗
    => Bob 无路可逃，Alice 出 2 就能赢
    Alice 出 4：
        Bob 出 6 -> gcd(4,6)=2>1，Alice 立刻获胜 ✗
        Bob 出 3 -> gcd=1 安全，但之后 Alice 仍必胜 ✗
    => Bob 无路可逃，Alice 出 4 就能赢
```

再跑 Alice {2,3} vs Bob {4,9}，真实输出：

```
根局面： [这个局面 Alice 必败]
    Alice 出 2：
        Bob 出 4 -> gcd(2,4)=2>1，Alice 立刻获胜 ✗
        Bob 出 9 -> gcd=1 安全，之后 Alice 必败 ✓ Bob 会选这个
            继续： [这个局面 Alice 必败]
                Alice 出 3：
                    Bob 出 4 -> gcd=1 安全，之后 Alice 必败 ✓ Bob 会选这个
                        继续： -> Alice 没牌了，Bob 胜
    Alice 出 3：
        Bob 出 4 -> gcd=1 安全，之后 Alice 必败 ✓ Bob 会选这个
            继续： [这个局面 Alice 必败]
                Alice 出 2：
                    Bob 出 9 -> gcd=1 安全，之后 Alice 必败 ✓ Bob 会选这个
                        继续： -> Alice 没牌了，Bob 胜
```

注意打印时 Bob 一旦找到"能逃的牌"就停了（`break`）—— 这和代码里的 `break` 是一回事：
**Bob 只要有一条活路，这个局面就不是 Alice 必胜。**

### 3.3 "必胜 / 必败"的精确定义

设 win(ma, mb) 表示"轮到 Alice 出牌，Alice 手里的牌是集合 ma、Bob 是 mb，Alice 是否必胜"。那么：

```
win(空, 空) = false                       ← 牌打完了，Alice 没赢，Bob 胜

win(ma, mb) = true
    ⟺ 存在 a_i ∈ ma，使得
          对每个 b_j ∈ mb：
              gcd(a_i, b_j) > 1  （Bob 出这张就直接送死，跳过不管）
              或者 win(ma \ a_i, mb \ b_j) = true
```

**注意两个量词的方向**，这是全题最容易写反的地方：

- Alice 的循环是 **`break` 出去就赢**（找到一招就行）→ 存在
- Bob 的循环是 **找到一个能逃的就否掉 Alice 的这一招** → 任意

写成代码就是：

```
外层 for(Alice 的牌 p)  {          // 存在
    假设这招能赢;
    内层 for(Bob 的牌 pp) {        // 任意
        if (Bob 出这张会当场输) continue;       // 这个应对不算"逃掉"
        if (后续局面 Alice 还能赢) continue;     // 这个应对也不算"逃掉"
        // 找到一个真的能逃的应对：
        这招不能赢; break;
    }
    if (这招真的能赢) return 必胜;
}
return 必败;
```

### 3.4 递归终止（base case）在哪

只有一处：**Alice 没牌了**（`ma == 0`）→ 返回 `false`。

写代码时你可能会想："那 Bob 没牌呢？"—— 不会发生。因为每轮**双方各扔一张**，
所以任何时刻双方手里的牌数永远相等。`ma == 0` 时 mb 必然也是 0。

## 4. DFS：怎么让程序走完整棵树

### 4.1 DFS 是什么（30 秒版本）

DFS（深度优先搜索）= **一条路走到黑，走不通再退回来换一条**。
写成代码通常就是**递归函数**：函数自己调用自己，每次都"往下走一步"。

对本题来说，"往下走一步" = Alice 出一张 + Bob 出一张，然后问"**剩下的局面怎么样？**"
—— 这正是递归的形状。

### 4.2 递归函数的三个零件

任何递归都只需要想清楚三件事：

| 零件 | 本题答案 |
|---|---|
| **① 参数/状态是什么** | Alice 剩哪些牌、Bob 剩哪些牌 |
| **② 什么时候停（base case）** | Alice 没牌了 → `false` |
| **③ 怎么缩小规模** | 双方各去掉一张牌，递归进去 |

**不用去想"递归是怎么一层层展开的"**，只要保证：③ 每次真的变小了（本题每次少两张牌），
并且 ② 最终一定会到达（牌有限），递归就一定会停。

### 4.3 把定义直译成代码

第 3.3 节那段定义，几乎是逐字翻译成 C++ 的：

```cpp
// 定义：win(ma, mb) = Alice 是否必胜
bool win(int ma, int mb) {
    if (ma == 0) return false;              // ② base case

    for (int i = 0; i < n; ++i) {           // 存在一张 Alice 的牌
        if (!(ma >> i & 1)) continue;
        bool allBlocked = true;
        for (int j = 0; j < n; ++j) {       // 对 Bob 的每一张牌
            if (!(mb >> j & 1)) continue;
            if (__gcd(a[i], b[j]) > 1) continue;                    // Bob 送死，不算逃掉
            if (win(ma ^ (1 << i), mb ^ (1 << j))) continue;        // ③ 递归，缩小规模
            allBlocked = false; break;                              // Bob 找到活路
        }
        if (allBlocked) return true;        // 存在一招，Bob 挡不住
    }
    return false;                            // 所有招都被挡
}
```

**你的代码就是这个骨架**，一个字都没跑偏。

## 5. 状态怎么存：二进制位

### 5.1 用第 i 位表示"第 i 张牌还在不在"

n ≤ 6，所以用一个整数的低 6 位就够了。以 n = 4、手里是第 1、3、4 张牌（这里先按 1 开始数）为例：

```
位:      3   2   1   0
二进制:  1   0   1   1
含义:   有  没有 有  有
```

mask = 0b1011 = 11。

### 5.2 四个必须会的位运算

| 想做的事 | 写法 | 说明 |
|---|---|---|
| 判断第 i 位是不是 1 | `mask >> i & 1` | 右移 i 位再取最低位 |
| 把第 i 位清零（扔掉这张牌） | `mask ^ (1 << i)` | 已知它是 1，用异或等价于减掉 |
| 把第 i 位置 1 | `mask \| (1 << i)` | 本题用不到 |
| 全部牌都在 | `(1 << n) - 1` | n=6 时是 63 |

> 小细节：`mask ^ (1 << i)` 和 `mask - (1 << i)` 在"第 i 位确定是 1"时结果一样。
> 代码里习惯写 ^，因为它明确表达"翻转这一位"，读起来更安全。

### 5.3 状态总数其实没有 2^n × 2^n 那么多

dp 开了 [1<<7][1<<7] = 128 × 128，但**真正会走到的状态**要少得多：
因为双方牌数永远相等，被访问的状态必然是 |ma| = |mb| = k 的形式，总数是

```
Σ(k=0..n) C(n,k) × C(n,k) = C(2n, n)
```

n = 6 时 C(12,6) = 924 个状态。每个状态枚举 n × n = 36 种走法，
总共约 924 × 36 ≈ 3.3 万次操作 —— 随便跑。

## 6. 记忆化：为什么必须有

### 6.1 同一个局面会被反复算到

看这棵树的形状：

```
     Alice 出 1，Bob 出 2   ┐
                           ├─ 到达的局面都是 {2,3,4...} vs {3,4,5...}
     Alice 出 2，Bob 出 1   ┘   ← 完全一样！
```

**不同的出牌顺序，会走到同一个局面。** 不加记忆化，这些重复局面会被重新算一遍又一遍。

### 6.2 实测数字（你可以自己跑）

配套的 `C_纯DFS_无记忆化.cpp` 会把递归次数打到屏幕上。实测 n = 6：

| 用例 | 纯 DFS 递归次数 | 记忆化版最多访问的状态数 |
|---|---|---|
| 全是互质关系（分支最多） | 1957 次 | 924 |
| 随机 [6,10,14,15,21,22] vs [2,3,5,7,11,13] | 1957 次 | 924 |
| 全同 [2,2,2,2,2,2] vs [2,2,2,2,2,2] | 1 次（第一招就赢） | 924 |
| 爬山搜索找到的最坏用例 | 约 5863 次 | 924 |

**说句实话**：本题 n ≤ 6，**不加记忆化也能过**（最坏也就几千次）。
但这不代表记忆化可有可无：

- 一旦 n 变成 10、12，纯 DFS 的状态就会膨胀到 (n!)² 级别（n=6 的理论上界就是 518400），
  而记忆化版本**始终只有 C(2n,n) 个状态**；
- 更重要的是，**记忆化是这个模型的"必需零件"**：写博弈 DP 的标准动作就是"状态 + 记忆化数组"，
  养成习惯以后遇到大的数据范围才不会翻车。

> 你要不要加？**要加，而且你已经加了**。你的 `dp[1<<7][1<<7]` + memset(dp,-1,...) 就是标准写法。

### 7.2 一行一行

### 7.3 三个可以改的地方（都不是错）

**① #define int long long 是双刃剑。**
它会让**所有** `int` 变成 64 位，包括循环变量 —— 常数变大、`main` 还必须写成 signed main()。
本题数字最大才 30，根本不需要。建议只在确实会溢出时用。

**② `#define rep(x,y,z) for(int x=y;x<=z;x++)` 是经典的宏陷阱。**
宏是纯文本替换，没有 do { } while(0) 包起来，遇到这种写法会翻车：

```cpp
if (cond) rep(i,1,n) f(i);   // 展开后 if 只管到 for 里的第一条语句
else ...
```

本题你没用到 rep，所以没事。但**养成习惯**：要么写成
`#define rep(x,y,z) for(int x=y;x<=z;x++)` 并永远配大括号，要么干脆别用宏。

**③ 递归 lambda 的另一种写法**（省掉 `std::function` 的开销）：

```cpp
    auto dfs = [&](auto &&self, int mask1, int mask2) -> bool {
        ...
        bool kk = self(self, mask1 ^ (1 << p), mask2 ^ (1 << pp));   // 自己调自己
        ...
    };
    int ff = dfs(dfs, (1 << n) - 1, (1 << n) - 1);
```

本题两种写法都 AC，你现在的写法**没有任何问题**，知道有这回事就行。

### 7.4 你的 base case 和我的写法，到底有没有区别

```cpp
你的：   if (mask1 == 0 && mask2 == 0) return false;
我的：   if (ma == 0) return false;
```

**在本题里完全等价**，因为：

1. 双方每轮各扔一张，所以**任何可达状态**都满足 `popcount(mask1) == popcount(mask2)`；
2. 于是 `mask1 == 0` ⟺ `mask2 == 0`，你的条件和我的是同一个条件；
3. 就算真出现"`mask1 == 0` 但 `mask2 != 0`"（不可达），你的代码会跳过 base case 进循环，
   外层 for(p) 找不到任何位，直接掉到最后一行 `return dp[..]=0`（false）—— 结果**仍然是 false**，一样。

**所以两种写法都不会错。** 我建议写成 `if (mask1 == 0) return false;`，理由只有一个：
**读代码的人不用再去想"mask2 会不会是别的值"**。可读性，不是正确性。

## 8. 和另一份解答（匈牙利匹配）是什么关系

### 8.1 两条路的直觉对比

**你的路（正向模拟）**：
> "我不知道谁会赢，那我就**把每一种可能都试一遍**。"

**另一条路（先证明再计算）**：
> "Bob 想活到最后，等价于他要给 Alice 的每张牌都预先配一张**互质的**牌，而且不能重复用。
> 这就是**二分图完美匹配**。求出来满配就是 Bob 胜，否则 Alice 胜。"

（为什么"不全配"就一定是 Alice 赢？用 **Hall 定理**：存在一个 Alice 的牌子集 S，
它能用的 Bob 牌不够多，Alice 把这 S 张牌先全打出去，Bob 必然有一轮无牌可应。）

我在 `对拍.py` 里做了**四路交叉验证**：你的版本 / 我的 DFS 版 / 纯 DFS 无记忆化 / 匈牙利匹配 /

## 9. 复杂度

## 10. 易错点清单

**① 两个循环的"存在/任意"写反。**
Alice 是"找到一招就赢"（return true），Bob 是"找到一招就逃"（`break` 后把 f 置 false）。
写反了样例都过不去，但如果只对拍小数据可能看不出来，务必拿样例 3 验证。

**② `gcd > 1` 的分支到底是 `continue` 还是"算 Bob 逃掉了"。**
`gcd > 1` = **Bob 出这张牌，Alice 当场获胜** → 对 Bob 来说这是**坏棋**，绝不能算作"逃掉"。
所以是 `continue`（跳过这个 j，去看 Bob 的其他牌），**不是** `break` 也不是 f = false。

**③ 忘了 memset(dp, -1, ...)。**
dp 初值是 0，而 0 表示"Alice 必败" —— 不初始化就会把所有没算过的局面当成必败，
样例 1（答案是 Alice）立刻挂掉。**这是本题最隐蔽的坑**。

**④ -1 只能用能存负数的类型。**
`bool dp[..]` 或 unsigned 类型都没法存 -1。用 `int` / `long long`。你的写法没问题。

**⑤ 状态里的两张掩码必须"同步删牌"。**
写 `dfs(mask1^(1<<p), mask2)` 这种漏删一个是致命的 —— 会出现"Bob 的牌凭空多出来"的局面。
**每轮双方各扔一张，这是题目规则**。你的代码 `mask1^(1<<p), mask2^(1<<pp)` 正确。

**⑥ 递归终止条件不要写成"某方没牌就赢"。**
Alice 没牌 = **Alice 输**（牌打完她没赢过），别顺手写成 return true。

**⑦ 输出大小写。**
题目要 Alice / Bob，首字母大写。写 alice 会 WA。

**⑧ `(1 << n) - 1` 别写成 `1 << n`。**
`1 << n` 是第 n 位是 1（比如 n=6 时是 64），但牌只有第 0..n-1 位，会**越界访问 `dp[64][64]`**（数组只有 128 大，不会崩，但语义完全错了）。

### 12.3 这套"状压博弈搜索"能迁移到哪

**通用骨架**（背下来）：

```
solve(状态) {
    if (状态是终局) return 终局结果;
    if (算过) return 表里的值;
    枚举"我"的每一种走法 {
        假设这招能赢;
        枚举"对手"的每一种应对 {
            if (这招被对手化解) { 这招不算数; break; }
        }
        if (这招算数) return 表里的值 = 赢;
    }
    return 表里的值 = 输;
}
```

## 附：术语小抄

| 术语 | 一句话解释 |
|---|---|
| **状态压缩** | 把"一个集合"塞进一个整数的二进制位里 |
| **记忆化搜索** | 递归 + 把算过的答案存表，下次直接查 |
| **博弈树** | 把所有可能的走法一层层展开成的树 |
| **minimax（极小极大）** | 双方轮流选"对自己最好的"：我取 max，对手取 min |
| **P 态 / N 态** | Previous player wins（必败态）/ Next player wins（必胜态） |
| **DAG** | 有向无环图。状态之间不会绕回来，所以能 DP |
| **完美信息** | 双方都能看到全部局面（本题 Bob 能看到 Alice 出的牌） |
| **零和** | 一个人赢就等于另一个人输，没有"双赢" |
| **Hall 定理** | 二分图存在完美匹配的充要条件（另一份解法用的） |
